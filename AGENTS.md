# Living Lyrics — инструкции для любого агента

Этот файл — единые правила для любого ИИ-агента и любой среды (Claude Code, Codex, Cursor, Gemini CLI, человек с терминалом). `CLAUDE.md` и `GEMINI.md` только подключают его.

**Начните с `docs/STATUS.md`** (состояние и решения) и `docs/BACKLOG.md` (задачи — каждая самодостаточна, её можно отдать агенту любого провайдера; полные задания — `docs/tasks/`). Что идёт прямо сейчас — `ops/board.json`. В конце каждой задачи обновите их и закоммитьте всё (код, данные, документацию): следующий агент продолжит без объяснений. Всё нужное для работы хранится в репозитории — не в памяти агента и не в сервисе какой-либо компании.

Сайт-сцена для песен: оригинал крупно, слова заливаются по мере пения (только при доказанном тайминге), русский перевод, пояснения, гравюры инструментов в проигрышах. Дизайн свой — качества Apple, но не копия. Сейчас в основном песни Sami Yusuf (персидский, арабский, турецкий, азербайджанский, английский, латынь, немецкий, испанский); проект — о музыке вообще, не только об этой теме.

## Если вы — отдельный чат или агент проекта

Владелец говорит только с оркестратором — **LL · Main** (адрес для сообщений между сессиями — `LL · Main`): решения, задачи, приёмка по отчётам, доска, `docs/STATUS.md`. Рабочие чаты:

- **LL · Site** — сайт и песни: ставит задачи Grok и Gemini, проверяет, вливает в `main`;
- **LL · Tech** — моды, настройка, устройства, ротация чатов, оркестрация исполнителей;
- **LL · Ops** — учёт работы и расхода токенов исполнителей и чатов, правила экономии;
- **LL · Business** — продукт и бизнес.

Рабочий чат или агент **всегда отчитывается LL · Main** после каждого законченного шага или изменения в репозитории: что сделано (файлы, коммиты), что дальше, что нужно от LL · Main. Сообщения между чатами и задания исполнителям — коротко и по-английски; владельцу и в документах для него — по-русски. Вопросы владельцу рабочие чаты передают через LL · Main, сами владельцу не пишут. Решение владельца — только то, что он прямо выбрал или подтвердил («да» на конкретный вопрос); свои выводы из его слов присылайте как рекомендации. Простые вопросы и выборы «да / нет» LL · Main задаёт формой с вариантами-кнопками (в Claude Code — AskUserQuestion), а не текстом. Когда нужен владелец (решение, действие, которое может сделать только он, лимит около 100 %, долгая задача закончилась или упала), LL · Main кроме сообщения в чате шлёт push-уведомление на телефон (в Claude Code — PushNotification). Агент в другой среде, где push нет, пишет об этом LL · Main первой строкой отчёта. Недельный лимит Claude от 95 % мод Dashboard присылает на телефон сам. Создавая новый чат или агента, давайте ему это правило в первом же задании.

**Ротация чатов.** Когда контекст чата переходит 30 % (мод Dashboard напоминает сам), чат доводит шаг до точки сдачи, пишет сдачу дел `ops/handoff/<дата>-<чат>.md`, запускает замену с тем же именем (`python ops/agents/rotate_chat.py …`, фоновый процесс под демоном Claude), переименовывает себя в «… · архив <дата>» и архивирует. Фоновые процессы не держат на чате, который уйдёт в архив. Подробно — `docs/process/chat-rotation.md`.

**Один чат — одна запись.** Рабочий чат живёт только фоновым процессом под демоном Claude. Запись в приложении Claude с именем рабочего чата — его копия, её архивируют. После выключения или перезагрузки Станции действуйте по `docs/process/after-restart.md` (в Claude Code — навык `/recover`). Новый чат взамен уснувшего не открывают. Фоновый чат правит файлы только в своей рабочей копии: `EnterWorktree` с `name` (папка `.claude/worktrees/<имя>`) или `git worktree add .claude/worktrees/<имя>`; `EnterWorktree` с `path` вне проекта просит разрешения и ночью вешает чат (`docs/process/chat-rotation.md`).

**Порядок.** В конце шага — `python ops/agents/hygiene.py` (только отчёт): своё уберите сами, остальное — строкой в отчёт LL · Main. Безопасное (влитые ветки и папки исполнителей) удаляют сами: на GitHub — `.github/workflows/cleanup.yml` после каждого обновления `main`, на Станции — мод раз в час.

**Бюджет исполнителей** (обязательно с 2026-10-22, подробно и с цифрами — `docs/process/executor-budget.md`):
1. Задача кругами — со списком проверок; не больше 3 кругов на бриф, четвёртый — после приёмки LL · Main. Принятое направление сначала вливается за флагом, следующие круги идут поверх.
2. Сессия исполнителя — не больше 30 млн токенов или 2 часов: коммит, запись «где остановились», новая сессия.
3. Два прохода без прибавки в измеряемом числе — стоп и отчёт.
4. Темп недели: к дню *d* — не больше *d*/7 + 10 %; при ≥ 70 % раньше чем за сутки до сброса — только то, что вливается сегодня, без ночных цепочек.
5. Бриф называет файлы для чтения, большие файлы читаются по диапазону.

**Кто на какой модели** (обязательно с 2026-10-22, решение владельца; полная таблица и шаблоны брифов — `docs/process/executors-guide.md`, раздел 4):
- Менеджеры (Main, Site, Tech, Ops, Business) — Opus 5.5; Main — усилие xhigh, остальные — high. Задаётся в карточке `.claude/agents/ll-*.md` (`model:`, `effort:`).
- Код (основной) — Grok `grok-4.7`, high, через `GROK_BINARY=ops/agents/grok_exec.mjs`; 30 млн / 2 ч на сессию, 3 круга на бриф.
- Мелкая правка кода — agy `claude-sonnet-5-5-medium`, 900 с; трудная, или Grok исчерпан — agy `claude-opus-5-5-high`, 1800 с. Усилие — в имени модели (`-low`/`-medium`/`-high`, у Opus ещё `-max`); флаг `--effort` agy не принимает (в `agy_run.py` — `-`). С 2026-10-23 Claude 4.6 в agy выключены, 5.5 — замена один к одному (LL · Main); имена и пробы — `docs/process/executors-guide.md`.
- Видео и кадры — agy `gemini-3.8-flash-high` (да/нет — `flash-low`); суждение о дизайне и переводе — agy `claude-opus-5-5-high`. Flash не судит и не пишет код. GPT-OSS не брать.
- Субагенты Claude: поиск — haiku, low; исследование и проверка кода — sonnet, medium.
- agy — решение владельца 2026-10-22: правила Google о сторонних обёртках он принимает на себя. Каждый запуск: cwd и `--add-dir` = worktree задачи, `--dangerously-skip-permissions`, `--output-format json --json-schema`, запись в учёт.
- **Приёмка — отдельный проверяющий `ll-judge`** (sonnet, low, ≤ 10 мин, только чтение): вердикт по списку «Готово, когда» с доказательствами. Исполнитель сам себя не принимает.

## Если вас попросили добавить песню

Вам дают ссылку на официальное видео или файл записи (или то и другое). Звук и видео берутся из одного официального ролика: одна попытка `yt-dlp` на машине, где это разрешено владельцем (команду даёт `song-status`); если сайт просит войти или отказывает — не обходить, а попросить файл у владельца. Маршрут — `docs/methodology/README.md`. После каждого шага `npm run song-status -- <slug>`: таблица стадий и одна следующая команда. Навык `/add-song` указывает на тот же маршрут. Код под новую песню не пишется: язык — ISO 639 (`src/data/iso639.ts`), письмо — `SCRIPT_CODES` в `src/data/schema.ts`.

Главные правила:
- ничего не выдумывать: буквы — из `canon.md`, непроверенное — флагом и в `review`;
- оригинал — ровно то, что поётся, каждый повтор — отдельная строка;
- время слов измеряет выравнивание, не глаз; пока на ветке нет `.github/workflows/pipeline.yml`, `song-status` помечает тайм-коды как отложенные и не просит пустое задание;
- перевод успевает читаться (≤ 17 зн/с по времени пения строки, считает `song-status`); пояснение — по делу; нигде нет капса;
- перед коммитом запись шифруется (`npm run audio:encrypt`), в git попадает `content/audio-enc/`;
- модули связаны контрактами (`src/data/schema.ts`, `src/instruments/animation.ts`): меняя одну часть, не ломайте другие и обновляйте контракт и его документ.

## Что нужно агенту и где тяжёлые шаги

Агенту достаточно git и редактирования файлов. Тяжёлые шаги (Demucs, Whisper, выравнивание) выполняются там, где есть вычисления и открытая сеть — выбирайте то, что доступно в вашей среде:

1. **GitHub Actions** (нужен `git push` и файл `.github/workflows/pipeline.yml` на ветке): задание `jobs/<slug>.json` → результат приходит коммитом. Если файла конвейера нет, `song-status` пишет «отложено». Подробно — `docs/methodology/README.md` и `docs/methodology/05-alignment.md`.
2. **Vercel Sandbox** (если у агента есть инструменты Vercel — MCP или CLI): `scripts/pipeline/sandbox/*.sh`.
3. **Локально** (если у агента есть компьютер с Python и ffmpeg): `scripts/pipeline/*.py`.

Если сеть среды не открывает сайты с текстами, читайте их через песочницу (`scripts/pipeline/sandbox/fetch_text.py`) или веб-поиск.

## Команды

```bash
npm install
npm run dev                         # http://localhost:5173 (расшифрует записи, если есть AUDIO_KEY в .env.local)
npm run validate [-- <slug>]        # проверка данных, включая сверку строк с canon.md; --strict для финальной
npm run typecheck
npm run build                       # расшифровка записей + validate + typecheck + vite build
npm run new-song -- <slug> "Title" "Artist"
npm run song-status -- <slug>       # где песня на маршруте и одна следующая команда
npm run art [-- <key>]              # пересобрать гравюры инструментов
npm run shots -- <url> <dir> <paths…>   # скриншоты iPhone/десктоп, светлая/тёмная
npm run audio:encrypt -- <slug>     # зашифровать запись перед коммитом (репозиторий публичный)
```

Аудиоконвейер (Python, `scripts/pipeline/requirements.txt`): `decrypt_audio.py`, `process_audio.py`, `separate.py`, `sections.py`, `transcribe.py`, `align.py`, `qa_sync.py`. Нужны `ffmpeg` и сеть (модели Whisper, Demucs, MMS). В облачной среде Claude Code сеть закрыта — пользуйтесь GitHub Actions или песочницей.

## Устройство кода

- `content/songs/<slug>/` — данные песни: `song.json`, `lyrics.json`, `canon.md` (оригиналы), `sources.md`. Схема — `src/data/schema.ts`, описание — `docs/data-format.md`.
- `content/audio-enc/` — записи, зашифрованные AES-256-GCM (ключ `AUDIO_KEY`).
- `src/data/timeline.ts` — строки и инструментальные части по порядку, повторы, смена голоса.
- `src/scene/` — сцена: `flow.ts` (поток строк как функция времени), `Scene.tsx`, `LineBlock.tsx`, `InstBlock.tsx`, `Field.tsx` (живой фон).
- `src/player/engine.ts` — воспроизведение, эквалайзер (Web Audio подключается только когда включён: на iPhone он останавливает звук при блокировке экрана), Media Session.
- `src/pages/` — библиотека, страница песни (`song/`: плеер, настройки, «О песне», весь текст), методология.
- `src/instruments/` — каталог инструментов, гравюры (`scripts/art/` их рисует), раскладки (`layout.ts`), контракт анимации (`animation.ts`, `docs/instruments/animation-contract.md`).
- `src/styles/tokens.css` — дизайн-токены; правила — `docs/design/design-system.md`.
- `middleware.ts` — пароль на сайт (Vercel: `SITE_PASSWORD`, `AUTH_SECRET`).

## Стиль кода

TypeScript strict, React 19 без сторонних UI-библиотек. Комментарии по-английски, тексты интерфейса и документация — по-русски, обычным регистром. Анимации сцены — функции времени (перемотка должна давать тот же кадр). Перед коммитом: `npm run validate && npm run typecheck`. Приёмка — один список, его же держит `docs/tasks/README.md`. Команды, которые 2026-10-21 уже проходили на одной машине без `AUDIO_KEY` (замер `docs/research/repo-audit.md`, в CI не заводились): `npm run validate`, `npm run typecheck`, `npx vite build`, `npx tsx src/player/background.test.ts`, `npx tsx src/player/preload.test.ts`, `npx tsx src/app/marks.test.ts`, `npm run test:layout`, `python scripts/pipeline/test_sync.py`. Без `AUDIO_KEY` `npm run build` звук не проверяет: `scripts/tools/audio-crypt.mjs` предупреждает и выходит с кодом 0.
