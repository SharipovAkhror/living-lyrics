# 11. Проверка

## Машинная

```bash
npm run validate                 # все песни
npm run validate -- <slug>       # одна песня
npm run validate -- --strict <slug>   # предупреждения тоже считаются ошибками — для статуса «готово»
npm run typecheck
```

Валидатор проверяет:
- структуру `song.json` и `lyrics.json` по схеме;
- уникальность `id`, порядок секций, границы по длительности;
- порядок слов (`s < e`, слово не раньше конца предыдущего);
- что инструменты есть в каталоге и у них есть гравюры;
- что все символы строк есть в шрифтах (Мусхаф, насталик, Cormorant);
- скорость чтения перевода (≤ 17 зн/с — норма, > 20 — предупреждение) и длину (≤ 90);
- что арабское письмо имеет транскрипцию; что языки в `song.json` совпадают со строками;
- подписи без капса; наличие `sources.md`; аудиофайлы на месте, если `audio.status = ready`;
- слово не кончается позже конца записи больше чем на 0,5 с;
- при `timing.status = aligned` в каждой группе, где есть строки (соло и хор), доказано не меньше 80 % (флага `timing-draft` у них нет). Строка «текст не найден» доказанной не считается. Пустая группа порог не блокирует.

Предупреждения (слово вышло за секцию, скорость перевода) сами по себе `npm run validate` не роняют. `--strict` роняет и их.

## Синхронизация с голосом

Её считает конвейер [стадии 5](05-alignment.md), не глаз. После прогона смотрите `docs/analysis/<slug>-qa.md`.

В начале отчёта:

- пройден ли критерий песни (`timing.status` стал `aligned` или остался `draft`). Порог песни — не меньше 80 % строк в каждой группе, где она есть;
- сколько строк выравниватель нашёл и сколько из них доказано: отдельно соло и отдельно хор;
- медиана и 90-й перцентиль расхождения начала слова у выравнивателя **до притяжения** с ближайшей атакой голоса, и то же для согласия двух выравнивателей. Соло и хор посчитаны отдельно: порог соло 0,1 с, порог хора 0,2 с. В одну цифру они не смешиваются. Притянутое время в эти цифры не входит: после притяжения расстояние до атаки обнуляется и ничего не доказывает;
- медиана |начало строки по выравнивателю − начало реплики| по найденным строкам. Реплика — третья опора: человек ставит её с точностью около 0,1–0,5 с. Если начало выравнивателя ушло от начала реплики больше чем на 0,7 с, строка не доказана, причина «расходится с субтитрами»;
- порог 0,25 с в шапке — отдельно. Им меряется сдвиг строки целиком (текст раньше или позже голоса на доли секунды). Это тревога в своём разделе, не порог доказательства слова;
- счётчик причин отказа.

Дальше таблица по строкам (группа: соло, хор или нет) и список худших мест соло и хора: id строки, время начала в записи и допритяжные расхождения. Эти места стоит прослушать. Раздел «Текст не найден в голосе» — строки, которые MMS не смог поставить на вокальную секцию. Слова в `lyrics.json` конвейер не переписывает: расхождение текста и пения остаётся флагом `timing-draft` и пометкой для правки текста. Такая строка не считается доказанной.

Строка доказана (флаг `timing-draft` снят, сайт зажигает слова по одному), если она соло или хор, первый проход уверен, начало строки не дальше 0,7 с от начала её реплики, оба выравнивателя сошлись в пределах допуска группы по временам до притяжения и каждое слово с буквами в тех же пределах попало в свою атаку. Допуск соло 0,1 с, допуск хора 0,2 с. Легато доказательством не считается. Окно первого прохода — реплика с запасом (0,8 с до начала, 0,5 с после конца, на соседнюю реплику не больше 0,5 с), со звёздочкой между словами на паузы и мелизмы. Строка без реплики ищется по своей вокальной секции. Черновые `s`/`e` окном не служат. На сайте время выравнивателя только когда строка уверенная и её начало не дальше 0,7 с от реплики. Уверенная строка дальше этого и всё, что слабее, остаются со временем реплики, без сдвига в промежуток между соседями. Окно второго выравнивателя — измеренная фраза. На соседнюю строку окно не заходит: иначе согласие меряется о чужой фразе.

Соло — строка, где ведёт один голос. Имя может быть пустым: пустой `voice` тоже соло. Хор — в `voice` есть «хор», choir, chorus или cappella. Дуэт, «все», ансамбль, оркестр и tutti не входят ни в одну группу и флаг не теряют. Строка без второго выравнивателя (азербайджанский, латынь, средневековый немецкий `gmh`, османский турецкий) тоже флаг не теряет. Если в данных язык записан как `de`, гоняется современная немецкая модель; расхождение со средневековым произношением остаётся честным провалом, подмена языка не делается. Пока `timing.status = draft`, пословная заливка выключена у всей песни, даже если у какой-то строки флага нет.

Код выхода проверки 1 значит «есть недоказанные строки», а не «прогон сломался»: воркфлоу коммитит отчёт и времена. Код 2 — стадия упала, в отчёте хвост лога.

## Визуальная

```bash
npm run dev
npm run shots -- http://localhost:5173 work/shots "/song/<slug>?t=12" "/song/<slug>?t=95"
```

Скриншоты снимаются в размере iPhone (393 × 852) и десктопа, в светлой и тёмной теме. Параметр `?t=` открывает песню на нужной секунде.

Посмотрите:
- оригинал не обрезан и не вылезает за края; длинные строки переносятся по `|`;
- арабские огласовки не налезают на строку выше; насталик не обрезан снизу;
- перевод читается на фоне (контраст);
- в инструментальных частях — правильная гравюра и подписи;
- пояснение открывается и прокручивается;
- нигде нет капса и «нейрослопа» (пафосных эпитетов, лишних восклицаний).

## На слух

Пройдите песню целиком с включённой сценой:
- у строк без флага `timing-draft` слово загорается вместе с голосом (не раньше и не позже ~0,1 с);
- строка с флагом `timing-draft` видна целиком, без пословной заливки — так и должно быть, пока проверка её не доказала;
- переводы успевают читаться;
- инструментальные части совпадают с музыкой, обратный отсчёт приводит точно к первому слову.

## Отметки владельца

ИИ не слышит, а проверка по скриптам ошибается на хоре и распевах. Последнее слово — за ушами владельца. Во время прослушивания он нажимает «Не совпадает» (на компьютере ещё клавиша M) — звук не останавливается, текст не редактируется. Список лежит в «О песне» → «Отмеченные места». Кнопка «Скопировать» даёт текст; его присылают агенту.

Формат текста:

```
Отметки «не совпадает»
Песня: <название> (<slug>)
Версия данных: <хеш коммита или дата ГГГГ-ММ-ДД>

1. <секунды с двумя знаками> с (<м:сс>)
   строка: <id строки или —>
   текст: <текст строки>
   секция: <id секции> — <подпись>
```

`Версия данных` — хеш коммита, если клиент его знает (переменная сборки `VITE_COMMIT`, 7–40 шестнадцатеричных знаков). Иначе это календарная дата копирования: в текущую сборку хеш не вшит, и дату нельзя считать коммитом.

Строка в отметке — та, которую сцена считает текущей. Она становится текущей примерно за 0,6 с до первого слова (`LEAD` в `src/scene/flow.ts`). Время — момент нажатия, а не новый тайм-код слова. Текст `проигрыш` значит инструментальную секцию (id строки нет). Текст `до первой строки` значит, что сцена ещё на заставке, до первого куска.

Для каждой отметки по порядку, и в ответе — отдельно по каждой:

1. Найдите строку по id в `content/songs/<slug>/lyrics.json`. Если id нет, смотрите секцию по её id.
2. Прослушайте окрестность ±3 с вокруг времени отметки по вокальному стему `work/<slug>/stems/vocals.wav` (стадия 3, `scripts/pipeline/separate.py`). Если стема нет — по самой записи. Рядом посмотрите отчёт `qa_sync.py`: отставание или спешка этой строки. Скрипт описан в задаче синхронизации; пока его нет в рабочей ветке, решение принимается по стему и по времени в `lyrics.json`, а отсутствие отчёта пишется в ответ.
3. Решите, что не так. Одно из трёх, не смешивая:
   - **текст** — поётся не то, что написано: слово, лишняя или пропущенная строка, повтор не отдельной строкой;
   - **порядок** — слова верные, но строка стоит не между теми соседками, что слышно;
   - **выравнивание** — текст и порядок верные, а время не совпадает с голосом.
4. Исправьте только это. Текст и порядок — в `lyrics.json` (и в `canon.md`, если меняется то, что поётся). Время — по стадии 5, измерением, а не оценкой. Соседние строки, которые ушами совпали, не переписывайте.
5. Напишите по отметке: время, id строки и что сделано. Если ушами всё совпало — так и напишите и ничего не меняйте. На хоре и распеве верьте ушам, а не спору скрипта: не подгоняйте текст под отчёт.

Отметка — замечание слушателя, не измерение. Не ставьте время нажатия в `s`/`e` слова.
