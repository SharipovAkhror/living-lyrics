# 11. Проверка

**Параллельно.** Нет. Её делают, когда предыдущие строки таблицы закрыты или честно отложены.

`song-status` ставит «проверка» в «да», только когда флагов нет и `review` пуст. Иначе строка «открыто», команда — `npm run validate -- <slug>`. Для финала — `npm run validate -- --strict <slug>`. Валидатор предупреждает, если нет `cues.json` или досье перевода, и отвергает `cues.json`, в котором есть текст реплики или лишнее поле. Предупреждение без `--strict` проверку не роняет.

Фразы `официальное видео: yt-dlp 429`, `официальное видео: просит войти`, `официальные субтитры: yt-dlp 429`, `официальные субтитры: пусто` и `обратный перевод: ждёт Gemini` из `review` не стирают, пока файла или ответа нет. Иначе `song-status` снова попросит ту же команду.

Прослушивание владельцем — не команда `song-status`. Агент доводит данные до этого места и останавливается. Владелец слушает и кнопкой «Не совпадает» отмечает места. `timing.status = verified` ставится после этого прослушивания, не заранее.

## Машинная

```bash
npm run validate                 # все песни
npm run validate -- <slug>       # одна песня
npm run validate -- --strict <slug>   # предупреждения тоже считаются ошибками — для статуса «готово»
npm run typecheck
```

Валидатор проверяет:
- структуру `song.json` и `lyrics.json` по схеме;
- уникальность `id`, порядок секций, границы по длительности;
- порядок слов (`s < e`, слово не раньше конца предыдущего);
- что инструменты есть в каталоге и у них есть гравюры;
- что все символы строк есть в шрифтах (Мусхаф, насталик, Cormorant);
- скорость чтения перевода (≤ 17 зн/с — норма, > 20 — предупреждение) и длину (≤ 90);
- что арабское письмо имеет транскрипцию; что языки в `song.json` совпадают со строками;
- подписи без капса; наличие `sources.md`; аудиофайлы на месте, если `audio.status = ready`;
- слово не кончается позже конца записи больше чем на 0,5 с;
- при `timing.status = aligned` в каждой группе, где есть строки (соло и хор), доказано не меньше 90 % (флага `timing-draft` у них нет). Строка «текст не найден» доказанной не считается. Пустая группа порог не блокирует. Цель — 100 % (goal 100 %): порог и случайный проход строки (не выше 5 %) ради процентов не опускают;
- порядок строки на её секунде: фраза транскрипта вокала не ближе к другой строке и не к стиху, которого в записи нет, если строка не помечена `text-unverified`. Если на диске есть json3, буквы строки сверяются с репликой того же языка. Переводная дорожка в эту сверку не входит. Если транскрипт и прослушивание Gemini на том же окне слышат один язык, а на экране другой, это ошибка и без `text-unverified` (`scripts/tools/sequence-check.ts`).

Предупреждения (слово вышло за секцию, скорость перевода, нет `transcript.json`) сами по себе `npm run validate` не роняют. `--strict` роняет и их.

## Порядок строк

Проверка букв до 2026-10-20 смотрела не туда, и перестановка строки на чужое время через неё проходила.

1. Валидатор спрашивал только, есть ли буквы строки где-то в `canon.md`. Какая строка стоит на какой секунде, он не спрашивал.
2. `cues.json` хранит id строки, номер реплики, язык и время и запрещает текст реплики. Позже по этому файлу не видно, что реплика — перевод.
3. Для персидского в I Have Come Alive, для латыни в Karitas и для английского глосса внутри en-GB у ONE время взято с переводной дорожки. Совпадение переводных дорожек между собой приняли за совпадение спетых букв.
4. Транскрипт вокала был грубой картой. Где он молчал или путал, оставляли реплику перевода. Ясное персидское полустишие внутри арабского окна не сравнивали со стихом, который эталон называет неспетым.
5. Запись никто не слушал. В эталоне I Have Come Alive сказано «Агент запись не слышит», в разборе — «Запись не прослушивалась».

С 2026-10-20 `npm run validate` гоняет `checkSequence`. Четыре стража, все по уже лежащим файлам:

- ошибка, если фраза транскрипта (не короче двух слов) ближе к другой строке (коэффициент Дайса по буквам не ниже 0,72), буквы другие, и эта фраза не лежит на копии тех же букв. Повтор тех же слов и фраза, которая захватывает соседнюю строку, ошибкой не считаются;
- ошибка, если фраза ближе к стиху из `docs/analysis/<slug>/recheck-alts.json` (стих, которого в записи по эталону нет): порог 0,50 и на 0,18 выше строки на экране. Флаг `text-unverified` эту ошибку снимает. Снять флаг — ошибка вернётся;
- если на диске есть json3, строка сверяется с репликой своей дорожки. Для I Have Come Alive это en-GB у английского, tr у турецкого, ar у арабского. Для Karitas турецкая дорожка у азербайджанского и арабская у арабского. Для ONE дорожка en-GB у немецкого и у арабского. Персидский и латынь в сверку букв не входят: их дорожка — перевод. Нет папки субтитров, как на CI, — сверка букв пропускается, без предупреждения. Нет `transcript.json` — предупреждение;
- ошибка, если на окне строки дольше 0,35 с и транскрипт вокала, и прослушивание Gemini (`docs/analysis/<slug>/recheck-gemini.json`) называют один и тот же язык, и этот язык не тот, что у строки на экране. Флаг `text-unverified` эту ошибку не снимает: именно он прятал арабские строки там, где оба свидетеля слышали персидский. Нет файла Gemini — проверка молчит. Файл есть у всех трёх песен. Часы отрезков Karitas (0, 250, 500, 750 с) и ONE (0, 280, 550 с) сверены с репликами, где буквы совпали: постоянного сдвига нет, время в файле не поправлялось. Переводная дорожка свидетелем языка не считается.

Молчание транскрипта ошибкой не считается: он пропускает известные места. Правка букв по-прежнему требует двух согласных источников. Переводная реплика таким источником не является.

Таблицу «строка и время → что читает транскрипт» пишет `npx tsx scripts/tools/sequence-check.ts --write` в `docs/analysis/<slug>/recheck.json`. Валидатор таблицу не переписывает. Самопроверка порогов вшита в `npm run validate`: без неё валидатор не стартует.

## Синхронизация с голосом

Её считает конвейер [стадии 5](05-alignment.md), не глаз. После прогона смотрите `docs/analysis/<slug>-qa.md`.

В начале отчёта:

- пройден ли критерий песни (`timing.status` стал `aligned` или остался `draft`). Порог песни — не меньше 90 % строк в каждой группе, где она есть. Цель — 100 %;
- сколько строк поставлено и сколько доказано: отдельно соло и отдельно хор, и отдельно по языкам. Рядом — сколько строк получили бы пословную заливку, если бы она включалась по строке. Сайт так не делает, пока песня в `draft`;
- медиана и 90-й перцентиль расхождения начала слова у выравнивателя **до притяжения** с ближайшей атакой голоса. Соло и хор посчитаны отдельно: порог соло 0,1 с, порог хора 0,2 с. В одну цифру они не смешиваются. Притянутое время в эти цифры не входит: после притяжения расстояние до атаки обнуляется и ничего не доказывает. На поставленных строках то же расстояние разложено на согласные и на гласные или связные, и посчитано, сколько слов доказано только вторым свидетелем, только stable-ts, обоими и ни одним;
- медиана |начало строки по выравнивателю − начало реплики|. Реплику ставит человек, точность около 0,1–0,3 с. Постановка и запись времени на сайт требуют не дальше 0,3 с. Дальше — «расходится с субтитрами», и на сайте остаётся время реплики;
- порог 0,25 с в шапке — отдельно. Им меряется сдвиг строки целиком (текст раньше или позже голоса на доли секунды). Это тревога в своём разделе, не порог доказательства слова;
- счётчик причин отказа.

Дальше таблица по строкам (группа: соло, хор или нет) и список худших мест соло и хора: id строки, время начала в записи и допритяжные расхождения. Эти места стоит прослушать. «Текст не найден в голосе» — только строка без реплики, у которой постановки нет или путь не прошёл структурные проверки. Слова в `lyrics.json` конвейер не переписывает. «Выравниватель не справился» — строка с официальной репликой в том же положении. Её слова неверными не называются: субтитр их уже подтвердил.

Строка доказана (флаг `timing-draft` снят), если она соло или хор и поставлена, ни одно её слово не опровергнуто и доказано не меньше доли K её слов (не меньше двух). У строки с репликой поставлена значит: структурные проверки и начало не дальше 0,3 с от реплики. Оценка MMS в отчёт идёт и строку не бракует. У строки без реплики порог калибровки остаётся, но без реплики строка не доказана. K, пороги опровержения и режим свидетелей по песне и языку читаются из `docs/analysis/bench/attack-chance.json`. Слово доказано сильной атакой и согласием одного или обоих независимых выравнивателей в пределах 0,10 с от начала того, кто поставил строку; сам постановщик себе свидетелем не служит, путь без атаки при этом закрыт. Слово без доказательства строку не бракует. Оба свидетеля, согласные между собой и далёкие от того, кто поставил строку, либо единственный далёкий свидетель с сильной атакой, которой нет у постановщика, слово опровергают, и строка не доказана. Пока файла нет — соло 0,1 с, хор 0,2 с, сила 0,5, и пройти должны все слова: либо атака, либо гласная или связное слово без атаки ближе 0,3 с и второй выравниватель в пределах 0,1 с. Интерполяция между соседями доказательством не является. Окно первого прохода — реплика с запасом (0,8 с до начала, 0,5 с после конца, на соседнюю реплику не больше 0,5 с), со звёздочкой между словами на паузы и мелизмы. Строка без реплики ищется по своей вокальной секции. Черновые `s`/`e` окном не служат. На сайте время выравнивателя только у поставленной строки, то есть не дальше 0,3 с от реплики. Всё остальное, у чего реплика есть, сажается на реплику целиком: первое слово начинается с неё, промежутки сохраняются, в промежуток между соседями строка не вдвигается. Окно второго выравнивателя — измеренная фраза. На соседнюю строку окно не заходит: иначе сверка меряется о чужой фразе.

Если для пары песня/язык допущен фонемный свидетель, роль «или» добавляет его начало к уже нужным часам, а роль «только он» доказывает слово сильной атакой и одним фонемным началом. Фонемные часы строку не ставят и слово не опровергают. Допуск пары — тот же: проход слова не выше 15 % и проход строки не выше 5 %.

Соло — строка, где ведёт один голос. Имя может быть пустым: пустой `voice` тоже соло. Хор — в `voice` есть «хор», choir, chorus или cappella. Дуэт, «все», ансамбль, оркестр и tutti не входят ни в одну группу и флаг не теряют. Азербайджанский, латынь, средневековый немецкий `gmh` и османский турецкий своего второго выравнивателя не имеют. Прогон `39082000484` померял турецкую модель на азербайджанских репликах: 22 из 26 в пределах 0,30 с, медиана |Δ| 0,202 с, против 16 из 16 и 0,141 с на турецких строках той же модели. Доля ниже и медиана хуже, модель не взята (CC-BY-4.0). Латынь на итальянской модели Common Voice — 7 из 24, медиана 0,431 с, на испанской — 5 из 24, медиана 0,504 с (обе Apache-2.0). Родного итальянского или испанского пения в этих записях нет, поэтому латынь не взята. В том прогоне правило было одно на все слова и требовало согласия одного свидетеля у каждого слова строки: у азербайджанского и латыни свидетелем оставался только stable-ts, и ни одна их поставленная строка целиком не была доказана.

Строка, которую первый проход MMS не поставил, может быть поставлена цепочкой: другое окно MMS, отрезок htdemucs_ft, stable-ts, затем второй выравниватель. Берётся первый, кто прошёл структуру и 0,30 с. Начало каждого слова должно лежать внутри секции строки, допуск 0,05 с, иначе этот шаг строку не ставит. Свидетели — остальные, не он сам. Случайный проход строки меряется отдельно по каждому постановщику, предел 5 %. Кто выше и при доле 1,00, из доказательства исключается. Опровергнутые слова перечислены в `docs/analysis/bench/refutation.md` со временем, местом в строке и тем, какой свидетель в стороне. Пороги из-за этого списка не меняются.

Прогон `39128266965` выбирает свидетеля по паре песня/язык: модель, при которой доказано больше всего строк, пока проход слова не выше 15 % и проход строки каждого постановщика не выше 5 %. Таблица — `docs/analysis/bench/whisper-choice.md`. Общее K = 0,25, случайный проход строки 0,035. Оба свидетеля потребовались у всей ONE (проход одного 0,184, оба 0,032) и у её немецкого (0,224 и 0,030). Английский I Have Come Alive проходит с одним (0,135). Арабский ONE проходит с одним (0,148). Языка короче 30 слов не было. Применённый проход слова нигде не выше 0,148. Опровергнуто 31 из 943 слов при порогах 0,20 с и 0,30 с, порог не сдвигался. На строках, поставленных другим окном MMS, оба свидетеля стоят раньше постановщика у 9 из 54; в половинах отчёта 6 из 27 и 3 из 27, и на обеих половинах сразу сдвиг не подтверждается. Поставлено и доказано: I Have Come Alive 108/66 из 120, Karitas 50/21 из 60 (азербайджанский 23/13 из 26, латынь 18/1 из 24), ONE 55/22 из 63 (немецкий 23/1 из 26, соло 21 из 37, хор 1 из 26). Пословную заливку по строке получили бы 66, 21 и 22 строки. Статус всех трёх песен остался `draft`: соло 55,0 %, 35,0 % и 56,8 %, хор ONE 3,8 %. У I Have Come Alive `large-v3` в бюджет лестницы не вошла, непоставленные строки там ставит `large-v3-turbo`. У Karitas и ONE непоставленные строки ставит `large-v3`. Сравнение моделей — в `docs/analysis/bench/whisper-witness.md`. Если в данных язык записан как `de`, гоняется современная немецкая модель и расхождение пишется в отчёт, подмена языка не делается. Пока `timing.status = draft`, пословная заливка выключена у всей песни, даже если у какой-то строки флага нет. Разбор непоставленного первого прохода, пустая таблица спора трёх часов и хор — в `docs/methodology/05-alignment.md` и `docs/analysis/bench/placement.md`.

## Визуальная

```bash
npm run dev
npm run shots -- http://localhost:5173 work/shots "/song/<slug>?t=12" "/song/<slug>?t=95"
```

Скриншоты снимаются в размере iPhone (393 × 852) и десктопа, в светлой и тёмной теме. Параметр `?t=` открывает песню на нужной секунде.

Посмотрите:
- оригинал не обрезан и не вылезает за края; длинные строки переносятся по `|`;
- арабские огласовки не налезают на строку выше; насталик не обрезан снизу;
- перевод читается на фоне (контраст);
- в инструментальных частях — правильная гравюра и подписи;
- пояснение открывается и прокручивается;
- нигде нет капса и «нейрослопа» (пафосных эпитетов, лишних восклицаний).

## На слух

Пройдите песню целиком с включённой сценой:
- у строк без флага `timing-draft` слово загорается вместе с голосом (не раньше и не позже ~0,1 с);
- строка с флагом `timing-draft` видна целиком, без пословной заливки — так и должно быть, пока проверка её не доказала;
- переводы успевают читаться;
- инструментальные части совпадают с музыкой, обратный отсчёт приводит точно к первому слову.

## Отметки владельца

ИИ не слышит, а проверка по скриптам ошибается на хоре и распевах. Последнее слово — за ушами владельца. Во время прослушивания он нажимает «Не совпадает» (на компьютере ещё клавиша M) — звук не останавливается, текст не редактируется. Список лежит в «О песне» → «Отмеченные места». Кнопка «Скопировать» даёт текст; его присылают агенту.

Формат текста:

```
Отметки «не совпадает»
Песня: <название> (<slug>)
Версия данных: <хеш коммита или дата ГГГГ-ММ-ДД>

1. <секунды с двумя знаками> с (<м:сс>)
   строка: <id строки или —>
   текст: <текст строки>
   секция: <id секции> — <подпись>
```

`Версия данных` — хеш коммита, если клиент его знает (переменная сборки `VITE_COMMIT`, 7–40 шестнадцатеричных знаков). Иначе это календарная дата копирования: в текущую сборку хеш не вшит, и дату нельзя считать коммитом.

Строка в отметке — та, которую сцена считает текущей. Она становится текущей примерно за 0,6 с до первого слова (`LEAD` в `src/scene/flow.ts`). Время — момент нажатия, а не новый тайм-код слова. Текст `проигрыш` значит инструментальную секцию (id строки нет). Текст `до первой строки` значит, что сцена ещё на заставке, до первого куска.

Для каждой отметки по порядку, и в ответе — отдельно по каждой:

1. Найдите строку по id в `content/songs/<slug>/lyrics.json`. Если id нет, смотрите секцию по её id.
2. Прослушайте окрестность ±3 с вокруг времени отметки по вокальному стему `work/<slug>/stems/vocals.wav` (стадия 3, `scripts/pipeline/separate.py`). Если стема нет — по самой записи. Рядом посмотрите отчёт `qa_sync.py`: отставание или спешка этой строки. Скрипт описан в задаче синхронизации; пока его нет в рабочей ветке, решение принимается по стему и по времени в `lyrics.json`, а отсутствие отчёта пишется в ответ.
3. Решите, что не так. Одно из трёх, не смешивая:
   - **текст** — поётся не то, что написано: слово, лишняя или пропущенная строка, повтор не отдельной строкой;
   - **порядок** — слова верные, но строка стоит не между теми соседками, что слышно;
   - **выравнивание** — текст и порядок верные, а время не совпадает с голосом.
4. Исправьте только это. Текст и порядок — в `lyrics.json` (и в `canon.md`, если меняется то, что поётся). Время — по стадии 5, измерением, а не оценкой. Соседние строки, которые ушами совпали, не переписывайте.
5. Напишите по отметке: время, id строки и что сделано. Если ушами всё совпало — так и напишите и ничего не меняйте. На хоре и распеве верьте ушам, а не спору скрипта: не подгоняйте текст под отчёт.

Отметка — замечание слушателя, не измерение. Не ставьте время нажатия в `s`/`e` слова.
