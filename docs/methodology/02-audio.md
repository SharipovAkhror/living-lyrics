# 2. Аудио

**Параллельно.** Нет, пока нет файла. Текст по источникам можно собирать раньше, секунды не ставить.

**Цель:** один раз получить запись того же ролика, что и видео с субтитрами, привести её к форматам доставки и больше к этому не возвращаться. Слушатель потом только выбирает качество в настройках.

## Где брать

По убыванию качества. Для новой песни обычный путь — пункт 3, если владелец дал ссылку на официальное видео. Пункт 1 — если он прислал файл, в том числе после неудачной попытки скачать.

1. **Файл, который дал владелец** (купленный lossless или AAC 256). Лучше всего. Его кладут в `work/<slug>/source.m4a`.
2. **Магазины с загрузкой:** Qobuz, Bandcamp, 7digital — FLAC или AAC 256. Файл всё равно приносит владелец. Агент магазин сам не открывает.
3. **Официальное видео** — одна ссылка из `sources.md`. На машине владельца `song-status` печатает команду: дорожка 140 (AAC) в `work/<slug>/source.m4a`. Видео 360p того же ролика — строка «видео», формат 18, не эта стадия.
4. Неофициальные загрузки — нет. У них бывает другой мастеринг, сдвинутое начало, обрезки.

> Записи защищены авторским правом. Сайт закрыт паролем и предназначен для личного использования. Скачивание с видеоплатформ может нарушать их правила — при возможности используйте купленный файл. В `song.json → audio.provenance` всегда указывайте, откуда файл.

Одна попытка. Если ответ 429, в `review` дописывают ровно: `официальное видео: yt-dlp 429`. Если страница просит войти: `официальное видео: просит войти`. Повторять команду, менять клиент и ждать в цикле не нужно. Дальше файл присылает владелец. `song-status` эти две фразы видит и скачивание больше не просит.

`scripts/pipeline/fetch_audio.sh` не запускать. Он берёт лучшую звуковую дорожку (часто не 140) и отдельное видео, и часы могут разъехаться с субтитрами.

Оценка файла: `ffprobe` (кодек, битрейт, частота, длительность). Дорожка 140 — AAC около 128 кбит/с. Лучше бывает только купленный файл без потерь. Числа `gainDb` и `sha256` пишет `process_audio.py`, не рука.

Команда звука, которую печатает `song-status` (адрес подставляет из `sources.md`). Её не заменяют другими флагами и не подменяют `fetch_audio.sh`:

```bash
python -m yt_dlp --no-playlist --js-runtimes node --extractor-args "youtube:player_client=tv,web_embedded" -f 140 -o "work/<slug>/source.m4a" "<адрес>"
```

Видео этой командой не качается. Формат 18 (360p) — строка «видео», стадия 9.

## Обработать

```bash
python3 scripts/pipeline/process_audio.py <slug>
```

Что делает скрипт:

| Шаг | Как | Зачем |
|---|---|---|
| Проверка | `ffprobe`: кодек, битрейт, частота, каналы, длительность | убедиться, что файл целый |
| `high.m4a` | если исходник AAC — перепаковка без перекодирования; если lossless — AAC 256 кбит/с; если Opus/MP3 — AAC 256 (без «улучшения» качества, просто совместимость с Safari) | основное качество |
| `saver.m4a` | AAC 96 кбит/с, стерео | мобильная сеть |
| Громкость | EBU R128 (`loudnorm`, первый проход): интегральная громкость и true peak → `gainDb = −14 − LUFS` | плеер выравнивает громкость между песнями, **не меняя файл** |
| `peaks.json` | RMS по 50 мс, нормированный 0…1 | живой фон сцены и форма таймлайна |
| `song.json` | заполняет `audio`, `duration` | |

Правила:
- **Никогда не «улучшайте» сжатый звук** перекодированием в больший битрейт ради цифры. Высокий битрейт для Opus → AAC нужен только чтобы не потерять ещё.
- Не обрезайте тишину в начале и не нормализуйте файл: тайм-коды привязаны к исходной временной шкале.
- Если у записи в начале долгие аплодисменты или разговор — всё равно оставьте. Сцена покажет титульную карточку.

## Критерий готовности

- `public/audio/<slug>/high.m4a`, `saver.m4a`, `peaks.json` существуют;
- `song.json → audio.status = "ready"`, заполнены `gainDb` и `provenance`;
- `duration` совпадает с длительностью файла до 0,1 с;
- песня играет на сайте, кнопки качества переключаются.

## Шифрование

Что агент говорит и делает без ключа — один раз в README, раздел «Если у шага нет входа». Здесь только строка таблицы.

Шифр — условие коммита записи и публикации (стадия 12), не стена перед текстом, видео и остальными стадиями. Когда `process_audio.py` положил открытый m4a в `public/audio/<slug>/`, `song-status` показывает отдельную строку «шифр» и идёт дальше.

- Шифр есть (`content/audio-enc/<slug>/high.m4a.enc`) — строка «да».
- Открытый файл есть, а `AUDIO_KEY` нет — строка «ждёт ключа», в таблице текст «шифр: ждёт ключа». Следующая команда — следующая незакрытая стадия.
- Ключ уже лежит в `.env.local` (64 шестнадцатеричных знака), шифра ещё нет — команда `npm run audio:encrypt -- <slug>` печатается на стадии 12, перед `git add`.

Скрипт пишет `content/audio-enc/<slug>/*.m4a.enc` и открытый файл не удаляет. Повторно `process_audio.py` из-за шифра не запускают. В git открытый m4a не кладут: репозиторий публичный, в коммит входит только шифр.

`provenance.kind` после измерения файла — `file`. Ссылка на ролик остаётся в `provenance.ref` и в `sources.md`.

**Готово, когда** строка «запись» — «да»: `audio.status = ready`, `duration` больше 1, provenance заполнен, и есть либо шифр, либо открытый файл. Строка «шифр» догоняется к коммиту, не раньше.
