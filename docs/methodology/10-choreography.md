# 10. Сцена

**Вход.** `song.json` и `lyrics.json` после стадий 3–8. Отдельного макета под песню нет.

**Команды.** Нет. Не создавайте файл в `src/scene/`, `src/pages/` или `src/instruments/` ради одной песни. Единственные данные, которые сцена читает сверх текста: `em` (одно ключевое слово), `br` (перенос на цезуре), `voice`, ключи инструментов, палитра в `song.json`. Поле `fx` не заполняйте: это след старой сцены, новые песни его не используют.

**Выход.** Ноль строк кода. Песня появляется на `/song/<slug>`, потому что библиотека читает папку.

**Машинная проверка.** `npm run song-status -- <slug>`: строка «сцена» всегда «да» с текстом «код под песню не нужен». Если захотелось открыть редактор кода, вернитесь к данным.

## Что сцена уже умеет

Поток строк — функция времени (`src/scene/flow.ts`). Перемотка даёт тот же кадр. Настраивать тайминги анимации в коде не нужно.

- Текущая строка крупно, под ней перевод. Следующие видны заранее, мельче. Предыдущая уходит вверх.
- Пока `timing.status` равен `draft` или у строки стоит `timing-draft`, строка загорается целиком. Пословной заливки нет. Это сделано специально: заливка мимо голоса хуже пустой.
- Когда время слов измерено, слова заливаются в направлении чтения. Для письма справа налево заливка идёт справа налево.
- Повтор в данных — отдельная строка, и поток делает отдельный шаг. Пометку «повтор» сцена ставит сама.
- Смена голоса берётся из `line.voice` или `section.voice`.
- Инструментальная секция показывает гравюры ключей из каталога. Раскладку выбирает `src/instruments/layout.ts`. Ручной `layout` — редкий случай, он описан в стадии 9.
- Тап по строке начинает игру с неё.

## Язык и письмо без нового кода

Язык строки — любой код ISO 639 из `src/data/iso639.ts`. Незнакомый код валидатор отклоняет и пишет, какого вида код нужен. Добавлять язык в перечень в `schema.ts` не надо.

Письмо — код из `SCRIPT_CODES` (`src/data/schema.ts`): латиница, кириллица, арабское, иврит, греческое, армянское, грузинское, деванагари и другие индийские, китайское, японское, корейское и остальные из того списка. Опечатка вроде `Latm` не проходит. Редкого исторического письма, которого в списке нет, хватает одной строки в `SCRIPT_CODES` на весь проект, не модуля песни.

Незнакомое письмо сцену не роняет. Кроме `Arab`, строка рисуется гарнитурой `f-serif`. Знаков, которых в ней нет, добирает системный шрифт. Отдельный шрифт под песню не подключайте.

Направление справа налево сцена сейчас включает для `Arab`. Список `RTL_SCRIPTS` в схеме шире (иврит, сирийское, тхана и другие). Пока `src/data/timeline.ts` не начнёт брать этот список, иврит идёт слева направо. Это известный зазор, он закрывается одной правкой таймлайна на все песни. В `review` такой песни напишите: «направление письма иврита ждёт общей правки timeline». Монгольское вертикальное письмо не поддерживается: берите `Cyrl` и вопрос в `review`.

Палитра читается из `song.json`. Новый цвет в CSS под песню не заводится.

## Что посмотреть глазами

Когда запись уже расшифровывается локально (`AUDIO_KEY` в `.env.local`):

```bash
npm run dev
npm run shots -- http://localhost:5173 work/shots "/song/<slug>?t=<секунда>"
```

Три-четыре места: первая вокальная строка, строка с `em`, повтор, инструментальная секция. Снимки — телефон и десктоп, светлая и тёмная тема. Смотрите, что перевод не обрезан и гравюра не перекрыла текст. Сервер после просмотра остановите.

Пока тайм-коды `draft`, на снимке не ищите пословную заливку: её нет, и это норма.

## Типичные ошибки

- Компонент `SongSpecial.tsx` под одну газель.
- Подкрутить константу в `flow.ts`, чтобы одна строка «успела». Сокращается перевод (стадия 6), не сцена.
- Заполнить `fx`.
- Поставить два `em` в одной строке. Валидатор предупреждает.
- Подключить шрифт в `app.css` ради одной новой письменности.
