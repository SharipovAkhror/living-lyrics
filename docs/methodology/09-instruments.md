# 9. Инструменты и гравюры

Во время инструментальных частей сцена показывает гравюры инструментов — каждую на своей подложке, с названием, названием в оригинале и исполнителем. Инструментов может быть сколько угодно: сцена сама решает, как их разложить на экране. Гравюры векторные, в одном стиле: тонкий контур, гравировальная штриховка, геометрические розетки.

Все гравюры и проба раскладок — на странице `/instruments`.

## Как отметить инструменты в песне

1. Определите, что звучит в инструментальной секции (видео, буклет, тембр — см. [стадию 3](03-structure.md)).
2. Запишите ключи в `instruments` — **ведущий первым**: тот, кто солирует или держит мелодию. Дальше — по важности, ударные обычно в конце.
3. Перечисляйте только то, что действительно слышно. Больше четырёх-пяти ключей — уже «ансамбль»: лучше `["qanun", "oud", "ensemble"]`, чем восемь ключей подряд.
4. Исполнителей пишите как `«Имя Фамилия (уд)»` — сцена поставит имя под нужной гравюрой. Без скобок имена раздаются по порядку ключей.
5. `layout` обычно не нужен (ниже — когда нужен).

```json
{ "kind": "instrumental", "instruments": ["tar", "kamancheh", "daf"], "performers": ["Имя Фамилия (тар)"] }
```

## Каталог

`src/instruments/list.ts` — ключ, название, название в оригинале, семейство, происхождение, одна фраза описания. В `lyrics.json` — только ключи отсюда; валидатор это проверяет.

| Семейство | Ключи |
|---|---|
| струнные щипковые | `oud` уд · `qanun` канун · `tanbur` танбур · `baglama` баглама · `tar` тар · `guitar` гитара фламенко · `harp` арфа |
| струнные ударные | `santur` сантур |
| смычковые | `kamancheh` кяманча · `erhu` эрху · `violin` скрипка · `cello` виолончель · `double-bass` контрабас |
| духовые | `ney` най · `zurna` зурна · `duduk` дудук |
| ударные | `daf` даф · `bendir` бендир · `riq` рик · `darbuka` дарбука · `tombak` томбак |
| клавишные | `piano` фортепиано (рояль) |
| голоса | `choir` хор (хоровая книга на аналое) · `voice` голос (поющий в профиль) |
| ансамбль | `ensemble` — уд, най и даф вместе; им же сцена заменяет ключ без гравюры |

Гравюры есть у всех ключей каталога. Чего в каталоге нет — добавьте (ниже).

## Как сцена раскладывает инструменты

Раскладку считает `src/instruments/layout.ts` (чистые функции; проверка — `npm run test:layout`), рисует `src/scene/InstrumentStage.tsx`. На вход — число инструментов, размер свободного места и пропорции гравюр (`src/instruments/art.json`, пишется `npm run art`), на выход — прямоугольник, слой, поворот и подпись для каждой гравюры.

| Режим (`layout`) | Как выглядит | Для скольких |
|---|---|---|
| `single` | одна гравюра крупно | 1 (остальные — в «+N») |
| `pair-sides` | две рядом, чуть развёрнуты друг к другу | 2 |
| `pair-diagonal` | одна слева сверху, другая справа снизу, с небольшим нахлёстом | 2 |
| `stack` | столбиком, подпись справа от рисунка | 2–4 |
| `fan` | веером, как карты: первая сверху, остальные выглядывают по сторонам | 3–5 |
| `hero-insets` | ведущий крупно, остальные — маленькими вставками в свободных углах той же рамки | 2–4 |
| `grid` | сетка | от 3 |

Автоматический выбор:

- перебираются все режимы, подходящие к числу инструментов; для каждого считается размер самой маленькой гравюры;
- режим отбрасывается, если гравюра выходит меньше читаемой: 20 % короткой стороны, но не меньше 84 и не больше 150 px;
- из оставшихся побеждает самый крупный с поправкой на форму экрана: на узком (телефон) — `stack`, на широком — `pair-sides`, на почти квадратном — `pair-diagonal`; для четырёх на ноутбуке — `hero-insets`; с пяти — `grid`;
- если не помещается никак — показываются первые инструменты, остальные собираются в «+N» (имена — в подсказке).

Что получается на типичных экранах (наименьшая гравюра, px):

| Экран | 1 | 2 | 3 | 4 | 5–6 | 7–8 |
|---|---|---|---|---|---|---|
| iPhone 390 × 600 | single 358 | stack 204 | stack 169 | grid 166 | grid 142 | grid 107 |
| iPhone SE 320 × 440 | single 288 | stack 196 | grid 140 | grid 140 | grid 90 | grid 85 |
| ноутбук 1200 × 700 | single 540 | pair-sides 540 | grid 356 | hero-insets 245 | grid 256 | grid 255 |

## Когда задавать `layout` вручную

Почти никогда: автоматический выбор подстраивается под экран, ручной — нет. Задавайте, когда автоматика спорит со смыслом:

- **`hero-insets`** — один солирует, остальные аккомпанируют (таксим уда над ударными), а автоматика поставила всех на равных;
- **`single`** — слышен по сути один инструмент, остальные едва различимы; они уйдут в «+N»;
- **`pair-diagonal` / `pair-sides`** — диалог двух инструментов (вопрос — ответ), когда важно показать их парой;
- **`fan`** — плотный тутти из трёх-пяти, где важен ведущий, но видны все.

Ручной режим соблюдается, только пока гравюры остаются читаемыми; на маленьком экране сцена всё равно выберет сама. Если режим не подходит к числу инструментов (`pair-sides` при трёх), валидатор предупредит.

## Как добавить инструмент

1. Запись в `src/instruments/list.ts`: ключ (латиница, через дефис), название, название в оригинале, семейство, происхождение, одна спокойная фраза описания.
2. Сверьте устройство по источникам: форма корпуса, число струн и колков, ладов, отверстий, где подставка, чем закрыт корпус. Пропорции — в сантиметрах, переведите в пиксели и запишите в комментарий генератора (образец — `tar.mjs`, `cello.mjs`).
3. Генератор `scripts/art/instruments/<key>.mjs` на примитивах `scripts/art/lib.mjs`: контуры `smooth`, `chainSmooth` (контур с углами), `boutOutline` (корпус скрипичного семейства), штриховка `shade` и `fillHatch`, мембраны `stipple`, колки `peg`, лады `fretYs`, перекрытия `a.begin()` … `a.hidden(shape)`. Длинногрифые лютни — `scripts/art/lute.mjs`, эфы и завиток — `cello.mjs`.
4. Соберите и посмотрите:
   ```bash
   npm run art -- <key>          # src/instruments/svg/<key>.svg, src/instruments/art.json, work/art/preview.html
   node scripts/art/shoot.mjs    # PNG в work/art/ — светлая и тёмная тема
   ```
   Откройте PNG и проверьте вблизи и в маленьком размере (около 120 px — так гравюра выглядит в сетке на телефоне): нет ли лишних линий, бугристых кривых, линий, просвечивающих сквозь деку или мембрану, неверных пропорций.
5. `npm run validate && npm run typecheck`.

## Стиль (обязательно)

| Параметр | Значение |
|---|---|
| Холст | `viewBox="0 0 400 400"`, инструмент вписан в медальон радиусом 186. Другой viewBox допустим — сцена впишет гравюру по пропорциям, не растягивая |
| Цвет | только `currentColor` — сцена красит гравюру цветом песни |
| Заливки | нет, кроме `.fillin` (тон под штриховкой, прозрачность 12 %) и мелких тёмных деталей (`.h` с `fill`: отверстия, чёрные клавиши, ноты) |
| Контур | 1,2–1,7 для силуэта, 0,6–1,0 для деталей |
| Штриховка | 0,35–0,55, шаг 1,3–3; тень — с той стороны, куда не падает свет (свет сверху слева) |
| Ракурс | фронтальный или три четверти, лёгкий наклон (−45°…+65°) для динамики |
| Детали | те, что узнаются: розетки, число струн/хоров, лады, колки, кольца дафа, отверстия ная и дудука, тарелочки рика |
| Перекрытия | что закрыто (обечайка под декой, задний обод под мембраной), прячется маской `a.begin()` … `a.hidden(shape)`, а не просвечивает |
| Вес файла | до ~60 КБ (числа округлены до 0,1) |

## Классы для анимации

| Класс | Что делает на сцене |
|---|---|
| `.d` с `pathLength="1"` | контур «прорисовывается» по мере `progress` |
| `.h` | штриховка проявляется после контуров |
| `.fillin` | тон под штриховкой |
| `.frame` | медальон; на маленьких подложках скрыт |
| `.str` | струны слегка дрожат, только когда есть звук (`energy` > 0) |
| `.skin` | мембраны (даф, бендир, рик, томбак, тар, кяманча) пульсируют с громкостью |
| `.breath-dot` | дыхание у мундштука ная и у губ поющего |

Прорисовка и появление — функции времени, которые передаёт сцена (`progress`, `presence`): перемотка даёт тот же кадр. Все движения микро: амплитуда не больше 1 px, без медленных колебаний около 0,2 Гц, отключаются при «Уменьшении движения».

## Критерий готовности

Ключ есть в каталоге, гравюра есть, в обеих темах читается с первого взгляда и в размере около 120 px, файл не тяжелее ~60 КБ; у секции ведущий инструмент стоит первым.

## Объёмные модели

Гравюра остаётся рисунком по умолчанию. Объём добавляется рядом и не заменяет файл SVG: нет модели, нет WebGL, включено уменьшение движения или слабое устройство — сцена показывает гравюру.

Сборка (без Blender):

```
npm run art3d -- daf
```

Без ключа команда собирает все инструменты, подключённые в `scripts/art3d/build.mjs`. Общие тела (вращение, лофт, трубки струн, тор колец, обечайка) живут в `scripts/art3d/lib.mjs`. На выходе `public/instruments/3d/<key>.glb`, манифест `<key>.json` и общий `index.json`. Рендер сам узнаёт новые ключи из индекса.

Имена узлов и морфов — таблица в `docs/tasks/instruments-3d.md` и контракт `docs/instruments/animation-contract.md`: корень `instrument`, `part-string-<n>` с морфом `vibrate`, `part-skin` с морфом `hit`, `part-jingles`, клип `idle`. Высота после нормировки — 1, центр в начале координат, инструмент смотрит в камеру (+Z). Бюджет: не больше 60 тысяч треугольников и 1,5 МБ после meshopt. Ссылки на справочники пропорций — в шапке скрипта инструмента и в `docs/instruments/credits.md`.

На сцене песни один холст WebGL на все инструменты кадра. В галерее `/instruments` у карточки с моделью свой холст: карточку можно повернуть и подвигать входы. Стиль (гравюра или материалы) один на сайт и лежит в настройках песни.
