# 9. Инструменты и гравюры

**Параллельно.** Да, вместе со стадиями 4, 6 и 5. Время слов не нужно.

## Строка «видео»

Обычный путь новой песни — одна команда `song-status` за раз. Готово, когда есть три файла: `docs/analysis/<slug>/vision.json` с непустым `frames`, `docs/analysis/<slug>/fusion.json` и `docs/analysis/<slug>/entries.md`. Не требуется, чтобы у каждой инструментальной секции уже стояли `entries`. Звуковое распознавание (CLAP, `instruments.py`, задание `features` и `instruments`) эту строку не закрывает и само в `lyrics.json` ключи не пишет.

1. Нет кадров и нет файла `work/<slug>/video.*`, ссылка есть, скачивание не остановлено. Команда — та же, что у звука, формат 18 (360p), один ролик:

```bash
python -m yt_dlp --no-playlist --js-runtimes node --extractor-args "youtube:player_client=tv,web_embedded" -f 18 -o "work/<slug>/video.mp4" "<адрес>"
```

Одна попытка. Ответ 429 или страница входа — те же фразы `review`, что в стадии 2: `официальное видео: yt-dlp 429` или `официальное видео: просит войти`. Повторно не запускать. Файл в git не класть.

2. Видео лежит, кадров нет. Просмотр запускает Claude · Lead, не Grok. Задание — `scripts/instrument_id/prompts/watch-video.md`, путь видео подставляют вместо `{{VIDEO}}`. `song-status` в строке команды оставляет `npm run song-status -- <slug>`, а вызов пишет в абзаце:

```bash
python "$(python -c "import sys; sys.path.insert(0, 'scripts/tools'); from aos_home import aos_home; print(aos_home(), end='')")/ops/agents/agy_run.py" . gemini-3.8-flash-high - 2350s scripts/instrument_id/schema/vision.json work/<slug>/watch-prompt.md --task "watch-video <slug>"
# work/<slug>/watch-prompt.md — копия scripts/instrument_id/prompts/watch-video.md с путём видео вместо {{VIDEO}}
```

Задание начинается с вида ролика: концерт, лирик-видео, статичная картинка или другое. В ответ это поле `video_type` (`concert`, `lyric_video`, `static`, `other`). Поле необязательное: старый `vision.json` без него проходит `npm run validate`. У лирик-видео в заметке кадра пишут, что титры есть и где они на экране; буквы титров — стадия 4, задание `scripts/instrument_id/prompts/read-captions.md`, не этот просмотр. У концерта собирают инструменты, как раньше.

Поле `structured_output` записывают в `docs/analysis/<slug>/vision.json`. `agy_run.py` (настройка владельца `agentic-os-live`) сам пишет расход в журнал; `agy` напрямую не вызывают. Журнал сам песню не закрывает. Если это не Claude · Lead, в отчёте пишут, что видео ждёт просмотра, и `agy` не вызывают.

3. Кадры есть, нет `fusion.json`: `python scripts/instrument_id/run.py fuse <slug>`. Сведение титров, кадров и звука, если звук уже распознан. Одного звука для инструмента недостаточно.
4. Сведение есть, нет `entries.md`: `python scripts/instrument_id/run.py entries <slug> --write`. Пишет отчёт и поля `instruments`, `entries`, `performers`. Правило — «титры и чёткий кадр» или «три плана», оно ниже. Строки и время слов не трогает. Флаг `--write` не добавляют, когда `entries.md` уже есть: строка «видео» к этому моменту уже «да».

Если ссылки и файла видео нет, или скачивание остановлено фразой в `review`, строка «видео» — «отложено». Строка «инструменты» отдельно: все ключи есть в каталоге. Пока ключ не опознан — `ensemble` и `attribution-unverified`.

`python scripts/instrument_id/run.py watch <slug>` — другой местный путь (листы кадров, другая модель). `song-status` его не печатает. Вместо напечатанной команды его не запускают.

Во время инструментальных частей сцена показывает гравюры инструментов — каждую на своей подложке, с названием, названием в оригинале и исполнителем. Инструментов может быть сколько угодно: сцена сама решает, как их разложить на экране. Гравюры векторные, в одном стиле: тонкий контур, гравировальная штриховка, геометрические розетки.

Все гравюры и проба раскладок — на странице `/instruments`.

## Как отметить инструменты в песне

1. Определите, что звучит в инструментальной секции (видео, буклет, тембр — см. [стадию 3](03-structure.md)).
2. Запишите ключи в `instruments` — **ведущий первым**: тот, кто солирует или держит мелодию. Дальше — по важности, ударные обычно в конце. Если есть `entries`, этот порядок совпадает с порядком первого вступления.
3. Перечисляйте только то, что действительно слышно. В секции может быть до восьми ключей: сцена сама решает, сколько из них помещается, остальные собирает в «ещё N». Когда несколько инструментов звучат сразу и по отдельности не вступают, безымянный тутти по-прежнему пишет ключ `ensemble`. Когда инструменты вступают по очереди, каждый слышимый ключ пишется в `entries` со своим временем. `ensemble` остаётся для безымянного тутти и для инструмента, которого ещё нет в каталоге.
4. Исполнителей пишите как `«Имя Фамилия (уд)»` — сцена поставит имя под нужной гравюрой. Без скобок имена раздаются по порядку ключей. Имя ставьте, только когда титры называют одного исполнителя на этот инструмент.
5. `entries` — `[{ "key", "at", "until?" }]`, секунды от начала записи, внутри секции. Порядок массива — порядок появления на маленьком экране. `until` опускают, когда инструмент играет до конца секции. В вокальной секции это сопровождение, не певец.
6. `layout` обычно не нужен (ниже — когда нужен).

```json
{
  "kind": "instrumental",
  "instruments": ["tar", "kamancheh", "daf"],
  "performers": ["Имя Фамилия (тар)"],
  "entries": [
    { "key": "tar", "at": 12.4 },
    { "key": "kamancheh", "at": 28.0, "until": 46.0 },
    { "key": "daf", "at": 41.2 }
  ]
}
```

## Как получить инструменты по звуку

Это звуковое предложение. Строку «видео» оно не закрывает, и `song-status` его не просит вместо просмотра. В `lyrics.json` закрытый набор CLAP не переносят.

Скрипты общие: в них нет констант под конкретную запись. Считается в GitHub Actions. На телефоне анализ не запускается.

Задание — файл `jobs/<slug>.json` и push своей ветки (нужен секрет `AUDIO_KEY`):

```json
{ "slug": "<slug>", "stages": ["features", "instruments"] }
```

Раннер расшифрует запись, при отсутствии стемов разделит её Demucs `htdemucs` на четыре стема и закоммитит результат. Стадии описаны в `scripts/pipeline/sandbox/run.sh`. Локально, если есть ffmpeg и зависимости `scripts/pipeline/requirements.txt`:

```bash
cd scripts/pipeline
python3 features.py --self-test           # без звука
python3 instruments.py --self-test
python3 features.py <slug>                # нужны work/<slug>/source.* и четыре стема
python3 instruments.py <slug>
```

### Огибающие для анимации

`scripts/pipeline/features.py` пишет `public/audio/<slug>/features.json`. Дорожки `loud`, `onset`, `bright`, `drums`, `bass`, `other`, `vocals`: 0…1, 20 значений в секунду. Громкость стемов нормируется к 95-му перцентилю смеси (0 — на 40 дБ тише), поэтому тихий стем не раздувается до единицы. Яркость — спектральный центроид между 5-м и 95-м перцентилем этой записи. Огибающие считает librosa (ISC). Доли `beats` ставит `beat_this` (веса `final0`, MIT), без DBN и без madmom; если трекер не сработал, доли пробует librosa. Поля `beats` нет, когда пульс не устойчив: меньше восьми долей, интервалы вне 40–240 ударов в минуту или скачут сильнее трети локальной медианы. Файл компактный, значения остаются 0…1: два знака после запятой. Если gzip (так файл отдаёт сервер) тяжелее ~150 КБ, скрипт переписывает его с одним знаком. Несжатый запасной предел — ~900 КБ. Имя трекера в файл не пишется, оно есть в логе стадии (`FEATURES … bytes=… gzip=… beats=…`). `sustain` и `breath` считает сцена (`driveAt`), в файл они не входят.

### Кто и когда играет

`scripts/pipeline/instruments.py` пишет предложение и **не трогает** `lyrics.json`:

- `docs/analysis/<slug>-instruments.json` — открытые отрезки и отдельно `data_proposal` (закрытый набор);
- `docs/analysis/<slug>-instruments.md` — таблица «для данных» и ниже открытое распознавание.

Карта голоса уже занимает `docs/analysis/<slug>.md`. Папку с тем же именем рядом создать нельзя, поэтому отчёт называется `<slug>-instruments`, а не `docs/analysis/<slug>/instruments.json`.

Модель — LAION CLAP `laion/clap-htsat-unfused` (карточка весов: Apache-2.0; статья arXiv:2211.06687 — CC BY 4.0). Это HTS-AT без склейки длинных кусков и текстовая башня RoBERTa, обученные на LAION-Audio-630K. Музыкальный чекпойнт `laion/larger_clap_music` не используется: у опубликованной текстовой проекции веса почти нулевые, и разные подсказки дают один и тот же вектор (попарный косинус около 0,9997). Скрипт печатает этот косинус и не пишет отчёт, если медиана не ниже 0,98: иначе «победитель» — шум четвёртого знака. У каждого ключа `src/instruments/list.ts`, кроме `ensemble`, есть английская подсказка по устройству инструмента. Второй, общий список (литавры, малый и большой барабаны, тарелки, табла, дхолак, тамбурин, рамочный барабан, ситар, балабан, рабаб, альт, поперечная флейта, кларнет, саксофон, труба, аккордеон, орган, синтезатор, группа смычковых, бас-гитара) сообщается, когда побеждает, и никогда не записывается ключом каталога. Веса PANNs не ставятся: у репозитория кода нет файла лицензии, на Zenodo написано только Open. Essentia не используется (AGPL). AST не ставится: открытые подсказки каталога CLAP уже покрывает, а фиксированные метки AudioSet не совпадают с ключами каталога один к одному.

Окно 2,5 с (допустимо 1–3, переменная `CLAP_WINDOW`). Шаг: ударные 1,5 с, бас и «прочее» 2 с, смесь 3 с. Окно тише порога энергии пропускается. Подсказка считается активной, когда её косинус — ближайший, она впереди тишины и впереди второй подсказки, и так хотя бы на двух окнах подряд. Вероятность softmax при десятках подсказок почти равна `1/N`, поэтому порогом она не служит: в отчёте она остаётся как справка, не как доля истины. Короткие вспышки короче 1,5 с (ударные — 1 с) отбрасываются, дырки короче 2 с (ударные — 1 с) склеиваются. Сходство — косинус CLAP. Этот проход — открытое распознавание, оно остаётся в отчёте. В данные песни его не переносят: для них действуют правила ниже.

Ударные считаются по стему ударных отдельно: какой ключ предложен (даф, бендир, дарбука, литавры и остальные из каталога и дополнительного списка), плотность ударов в каждой секции (почти нет / редко / умеренно / плотно / очень плотно), ровность интервалов. Тар в подсказке — персидская лютня с двойной чашей, не рамочный барабан. Балабан не подменяется дудуком, бас-гитара — контрабасом: чужой ключ каталога скрипт не подставляет.

На смеси мелодические подсказки глушатся там, где стем вокала громкий: иначе поющий выглядит как инструмент. Голос и хор в гравюры сопровождения не переносятся, в отчёте они отдельным списком.

В json-отчёте поле `diagnostics.text_pairs` — попарный косинус текстовых подсказок, `diagnostics.stems` — по стемам: сколько окон вообще громкие, отрыв лучшей подсказки от тишины, отрыв от второй подсказки, разброс косинусов. Если медиана попарного косинуса текста около единицы, чекпойнт мёртвый: отчёт не пишется, модель меняют. Если текст живой, а отрыв от второй подсказки на всех записях одного прогона около нуля, модель на этих подсказках не разделяет тембры: порог `COSINE_EPS` меняют один раз для метода и прогон повторяют. Под одну песню порог не подстраивают.

### Что попадает в данные песни

В `lyrics.json` попадают поля `instruments`, `entries` и `performers` инструментальных секций. Подпись секции меняется, только когда видео показывает хор вместо солиста или аплодисменты вместо пения. Заметка под гравюрой меняется только у аплодисментов. Строки, слова и время не трогаются. Неверный инструмент на сцене хуже пустого места. Время вступления берётся из видео концерта: склейка камеры — не уход инструмента, один кадр — не присутствие.

Команда `python scripts/instrument_id/run.py entries <slug>` читает кадры `docs/analysis/<slug>/vision.json`, список проверенных ошибок `docs/analysis/<slug>/vision-review.json`, титры `song.json` и признаки `public/audio/<slug>/features.json`. С флагом `--write` она записывает поля выше. Отчёт — `docs/analysis/<slug>/entries.md`. Звук (`instrument-id.json`) в отчёте отмечен, где он совпал с кадром. Сам по себе он инструмент не ставит и не снимает. Проверка правила — `python scripts/instrument_id/run.py entries --selftest` (она же входит в `run.py selftest`).

1. **Присутствие в песне.** Инструмент может появиться, если титры называют его — по идентификатору или по семье — и видео видит его в игре хотя бы на одном крупном или среднем плане с уверенностью не ниже 0,8. Либо видео видит его в игре на трёх разных планах: кадры разнесены не меньше чем на 8 секунд, план крупный или средний (первое слово поля `note`: `close` или `medium`), уверенность не ниже 0,85. Это называется «устойчиво по видео», титры для этого пути не нужны. Одиночный кадр, даже очень уверенный, в данные не идёт: он остаётся в списке «проверить». Общий план, зал и титры на экране не считаются. `orchestra`, `choir` и `voice` — группы, не солисты: оркестр на общем плане не раскладывается на угаданные инструменты. Титр «оркестр» не называет скрипку.

   Группа в титрах сама по себе инструмент не называет. Исключение одно: если титры называют группу, к которой инструмент относится («ударные» или «перкуссия» — рамочные барабаны, дарбука и остальные семьи из `percussionFamilies`), хватает двух чётких планов с уверенностью не ниже 0,85, разнесённых не меньше чем на 8 секунд. Один план при такой группе по-прежнему только «проверить». Уверенность 0,8 для этого пути не считается: порог 0,8 остаётся у инструмента, названного по имени или по семье.

   Кадр, который человек проверил и признал неверным, лежит в `vision-review.json`: `time_s`, `instrument`, `verdict: "wrong"`, `note`. Такой кадр не считается. Соседние кадры того же инструмента ближе чем на 8 секунд — это тот же план, они тоже не считаются. Исключения в коде под конкретную секунду нет.

2. **Секция и вступление.** В проигрыш попадают инструменты, принятые по правилу 1 и увиденные в этой секции на чётком кадре. Порядок вступлений — по первому появлению. Если рисуемых инструментов больше восьми, остаются семь самых заметных, остальные собираются в `ensemble`: отдельной гравюры «оркестр» в каталоге нет. Заметность в секции — число чётких кадров (крупный или средний план), умноженное на их среднюю уверенность. При равенстве выше средняя уверенность, затем более ранний кадр, затем идентификатор. Голос и хор в эту семёрку не входят: они и есть секция. `entries[].at` — время первого чёткого кадра в секции. Если в пределах двух секунд раньше на подходящем стеме есть атака, время сдвигается к ней. Стем `other` — для струнных и духовых, `drums` — для ударных. Поле `until` не ставится.

   Секция, где стояли только `voice` или `choir`, переписывается. Первым ключом остаётся голос или хор, и пластина выходит в начале секции. Принятые инструменты, которые видно в игре, добавляются вступлениями. Хор становится ключом и подписью «Хор», когда кадров с поющим хором больше, чем кадров с поющим солистом. Один солист оставляет `voice` и прежнюю подпись. Слушающий человек (`playing: false`) солистом не считается. Общий план для этого сравнения годится: хор часто снят широко. Для инструмента по-прежнему нужен крупный или средний план.

   Аплодисменты и поклоны, когда никто не играет, — не голос и не ансамбль. Подпись «Аплодисменты», список инструментов пустой, заметка «Аплодисменты и поклоны, пения нет.» Пустой список сцена не подменяет ансамблем: гравюры нет. Если в секции кто-то играет, один кадр хлопка её аплодисментами не делает. Вокальная секция со словами инструменты на сцену не получает: в это время сцена показывает строки. Кадр инструмента там остаётся в отчёте и в данные песни не пишется. Детектор по стему «other» запускается отдельно: `python scripts/instrument_id/run.py applause`. Он пишет `docs/analysis/<slug>/applause.json` и заново пороги не подбирает. `lyrics.json` эта команда не меняет. Число секций с подписью «Аплодисменты» видно в `song-status`, строка «инструменты».

3. **Гравюра.** Идентификатор кадра сопоставляется с ключом каталога (`scripts/instrument_id/labels.json`, поле `catalogKey`). Нет своей гравюры — инструмент не рисуют чужой: в `instruments` его нет, в отчёте строка «нужна гравюра» (идентификатор, где звучит, сколько планов). Гравюра фламенко остаётся только у `guitar-flamenco`. Классическая гитара — ключ `guitar-classical`. Кадры, которые распознавание пометило `guitar-acoustic`, на этих концертах показывают ту же гитару с нейлоновыми струнами, щелевой головкой и подставкой без гольпеадора: у `guitar-acoustic` поле `aliasOf` указывает на `guitar-classical`, один переход, без своей пластины и без гравюры фламенко. Электрогитара по-прежнему без гравюры. Оркестровая перкуссия — ключ `orchestral-percussion`: на единственном чётком кадре (I Have Come Alive, 524 с) видны оркестровые колокола, подвесная тарелка и колотушка. Литавр на нём нет, поэтому котёл не нарисован, и класс `timpani` гравюры не получает. `ensemble` остаётся для безымянного тутти и для свёртки тех, кто не вошёл в семь самых заметных. Аплодисменты `ensemble` не получают.

Имя исполнителя пишется как «Имя (инструмент)», только когда титры называют ровно одного человека на этот ключ. Уже стоящее имя сохраняется, если инструмент в секции остался. Весь список титров на каждую секцию не копируется.

Звуковой отчёт выше по-прежнему пишет предложение в `docs/analysis/<slug>-instruments.md` и сам `lyrics.json` не трогает. В данные песни его закрытый набор не переносят: для сцены решает видео вместе с титрами, как в трёх правилах выше.

Проверка: таблица секций в `docs/analysis/<slug>/entries.md`, затем `npm run validate` (ключ есть в каталоге, время внутри секции) и `npm run typecheck`.

## Как сцена раскладывает инструменты

Раскладку считает `src/instruments/layout.ts` (чистые функции; проверка — `npm run test:layout`), рисует `src/scene/InstrumentStage.tsx`. На вход — число инструментов, размер свободного места и пропорции гравюр (`src/instruments/art.json`, пишется `npm run art`), на выход — прямоугольник, слой, поворот и подпись для каждой гравюры.

| Режим (`layout`) | Как выглядит | Для скольких |
|---|---|---|
| `prominence` | ряд по главности: первый крупнее, общая линия основания | 1–4, автоматический |
| `single` | одна гравюра крупно | 1 (остальные не показываются) |
| `pair-sides` | две рядом, чуть развёрнуты друг к другу | 2 |
| `pair-diagonal` | одна слева сверху, другая справа снизу, с небольшим нахлёстом | 2 |
| `stack` | столбиком, подпись справа от рисунка | 2–4 |
| `fan` | веером, как карты: первая сверху, остальные выглядывают по сторонам | 3–5 |
| `hero-insets` | ведущий крупно, остальные — маленькими вставками в свободных углах той же рамки | 2–4 |
| `grid` | сетка | от 3 |

Автоматический выбор — `prominence`:

- на телефоне (коробка уже 560 CSS-пикселей) в кадре до четырёх: три в ряд, четыре — два ряда по два. Читаемый минимум ниже, 11 % короткой стороны и не меньше 44 px, чтобы четвёрка не схлопывалась в одну гравюру;
- на среднем экране, от 560 и уже 1000 CSS-пикселей, в ряду не больше трёх. На широком, от 1000, не больше четырёх;
- первый инструмент в масштабе 1, следующие примерно 0,8, 0,7 и 0,65; рисунки одного ряда стоят на одной линии основания, промежутки ровные, подписи не налезают на рисунки;
- на коробке от 560 px гравюра меньше читаемой (20 % короткой стороны, но не меньше 56 px и не больше 150 px) в ряд не берётся: показывается меньше инструментов, а не мельче;
- лишние просто не рисуются. Плашки «ещё N» нет.

На странице песни и в галерее автоматика одна и та же. Короткий широкий экран не переключает ряд на равные клетки: меняется только вёрстка страницы (строка, сноска, плеер). Ручной режим из таблицы выше по-прежнему можно задать в данных.

## Сцена

Раскладка считает прямоугольники для списка, который сцена держит, пока состав не сменится. Кого включить, решает `src/scene/cast.ts`. Список зависит от секций и от ширины коробки, не от секунды внутри секции: перемотка не перескакивает состав.

Все места заняты с начала состава. Появление — каскад прозрачности примерно за секунду, не прорисовка контура по одному. Музыкальное вступление (`entries`, поле `at`) яркость не включает и не выключает место: до него гравюра стоит приглушённо, около 35 % яркости, без движения. С вступления яркость следует стему семьи (около 60 %, когда стем молчит, и полная, когда он громкий), плюс ореол цветом песни, короткий импульс на атаке и дыхание у протяжного звука. Стемов четыре, поэтому два инструмента одной семьи оживают вместе; сцена этого не скрывает. Формула — `plateLife` в `src/instruments/animation.ts`.

Состав меняется только на границе секции. Если с прошлой смены прошло меньше восьми секунд, остаётся прежний состав: короткая секция не подменяет гравюры. Общий инструмент соседних секций остаётся в том же месте ряда и не входит заново; новичок проявляется в первой свободной клетке. Пустая клетка закрывается, поэтому пластина правее дырки может сдвинуться влево: пустого места в ряду нет. Уход и приход — перекрёстным затуханием прозрачности целого блока. Инструмент, который ушёл и вернулся уже после выдержки, входит заново. Перемотка на ту же секунду даёт тот же кадр, накопленного состояния нет.

Ширина считается по коробке сцены, не по окну. Порядок — порядок в `instruments` (ведущий первый, он и самый крупный); ключ, который есть только в `entries`, встаёт после них. Дальше предела список не идёт.

- На телефоне (коробка уже 560 CSS-пикселей) видны три в ряд или четыре квадратом два на два. Размер по главности, но читаются все: четвёрка не выбрасывается из-за узкой строки.
- На среднем экране, включая машину уже 1000 CSS-пикселей, в ряду до трёх.
- На широком экране в ряду до четырёх. Остальные из данных не рисуются. На низком окне коробка — это высота сцены над плеером, и тот же предел применяется к ней.

Пластина `ensemble` остаётся, только если в секции меньше двух названных инструментов. Иначе она не встаёт между ними и не занимает их место: в ряд идут сами названные, в том же порядке.

Появление состава — каскад прозрачности: при полной анимации последняя пластина доходит примерно за секунду, при спокойной чуть быстрее, при «Без анимации» почти сразу. Смена состава — перекрёстное затухание. Движется только `transform`, `opacity` и `filter`. Сглаживание симметричное. «Без анимации» и системное уменьшение движения оставляют яркость и убирают импульс.

Секция, где ключи только `voice` и `choir`, не разыгрывает очередь и не подставляет оркестр. Гравюры стоят всю секцию, размер по порядку в списке, в пределах того же предела ширины. Подпись проигрыша в этом случае — «Голос», «Хор» или «Голос и хор». Атака на таких пластинах приглушена: остаётся тихий воздух.

Если рядом с голосом или хором в списке есть инструменты, места всё равно заняты с начала состава. Голос или хор светлеет с начала секции, инструменты — со своего `entries`. Пустой список инструментов — пустая сцена (аплодисменты). Ансамбль туда не подставляется. Подпись секции видна в шапке.

Короткий широкий экран (высота до 640 CSS-пикселей при ширине от 700, в том числе 800×480, 960×540, 1024×600 и 1280×480) — отдельная раскладка страницы, не колонка. Строка крупная относительно высоты, перевод читается, пояснение — сноска над плеером, а не узкий столбец. Кнопки плеера в один ряд, касание не меньше 44. Шапка короче: остаётся название. Ряд гравюр на этом экране считается тем же правилом главности.

Числа кадра берутся из `features.json` через `stageDrive` (`src/scene/stageDrive.ts`): контур на сцене уже нарисован, яркость и движение идут от стема. Пока файла нет, гравюра после вступления стоит на покое около 60 % и не дрожит. Струны движутся от `sustain` и `pulse`, мембрана — от `pulse`, кольца и дыхание — от своих входов, лёгкий наклон — от доли. Формулы и два вида («рисунок» и «реалистичный») — в контракте анимации.

## Когда задавать `layout` вручную

Почти никогда: автоматический выбор подстраивается под экран, ручной — нет. Задавайте, когда автоматика спорит со смыслом:

- **`hero-insets`** — один солирует, остальные аккомпанируют (таксим уда над ударными), а автоматика поставила всех на равных;
- **`single`** — слышен по сути один инструмент, остальные едва различимы; они не рисуются;
- **`pair-diagonal` / `pair-sides`** — диалог двух инструментов (вопрос — ответ), когда важно показать их парой;
- **`fan`** — плотный тутти из трёх-пяти, где важен ведущий, но видны все.

Ручной режим соблюдается, только пока гравюры остаются читаемыми; на маленьком экране сцена всё равно выберет сама. Если режим не подходит к числу инструментов (`pair-sides` при трёх), валидатор предупредит.

## Как добавить инструмент

1. Запись в `src/instruments/list.ts`: ключ (латиница, через дефис), название, название в оригинале, семейство, происхождение, одна спокойная фраза описания.
2. Сверьте устройство по источникам: форма корпуса, число струн и колков, ладов, отверстий, где подставка, чем закрыт корпус. Пропорции — в сантиметрах, переведите в пиксели и запишите в комментарий генератора (образец — `tar.mjs`, `cello.mjs`).
3. Генератор `scripts/art/instruments/<key>.mjs` на примитивах `scripts/art/lib.mjs`: контуры `smooth`, `chainSmooth` (контур с углами), `boutOutline` (корпус скрипичного семейства), штриховка `shade` и `fillHatch`, мембраны `stipple`, колки `peg`, лады `fretYs`, перекрытия `a.begin()` … `a.hidden(shape)`. Длинногрифые лютни — `scripts/art/lute.mjs`, эфы и завиток — `cello.mjs`.
4. Соберите и посмотрите:
   ```bash
   npm run art -- <key>          # src/instruments/svg/<key>.svg, src/instruments/art.json, work/art/preview.html
   node scripts/art/shoot.mjs    # PNG в work/art/ — светлая и тёмная тема
   ```
   Откройте PNG и проверьте вблизи и в маленьком размере (около 120 px — так гравюра выглядит в сетке на телефоне): нет ли лишних линий, бугристых кривых, линий, просвечивающих сквозь деку или мембрану, неверных пропорций.
5. `npm run validate && npm run typecheck`.

## Стиль (обязательно)

| Параметр | Значение |
|---|---|
| Холст | `viewBox="0 0 400 400"`, инструмент вписан в медальон радиусом 186. Другой viewBox допустим — сцена впишет гравюру по пропорциям, не растягивая |
| Цвет | только `currentColor` — сцена красит гравюру цветом песни |
| Заливки | нет, кроме `.fillin` (тон под штриховкой, прозрачность 12 %) и мелких тёмных деталей (`.h` с `fill`: отверстия, чёрные клавиши, ноты) |
| Контур | 1,2–1,7 для силуэта, 0,6–1,0 для деталей |
| Штриховка | 0,35–0,55, шаг 1,3–3; тень — с той стороны, куда не падает свет (свет сверху слева) |
| Ракурс | фронтальный или три четверти, лёгкий наклон (−45°…+65°) для динамики |
| Детали | те, что узнаются: розетки, число струн/хоров, лады, колки, кольца дафа, отверстия ная и дудука, тарелочки рика |
| Перекрытия | что закрыто (обечайка под декой, задний обод под мембраной), прячется маской `a.begin()` … `a.hidden(shape)`, а не просвечивает |
| Вес файла | до ~60 КБ (числа округлены до 0,1) |

## Классы для анимации

| Класс | Что делает на сцене |
|---|---|
| `.d` с `pathLength="1"` | контур прорисовывается по `--draw` |
| `.h` | штриховка проявляется после контуров (`--hatch`) |
| `.fillin` | тон под штриховкой |
| `.frame` | медальон; на маленьких подложках скрыт |
| `.str` | струны сдвигаются на `--str-x` / `--str-y` (от `sustain` и `pulse`) |
| `.skin` | мембрана масштабируется по `--skin` (от `pulse`) |
| `.breath`, `.breath-dot` | воздух у отверстия, прозрачность `--breath-o`. На микрофон класс не ставится: капсула читает `--breath-o` и едва качается в скобе, примерно на 1,2°. Наклон вперёд нарисован; в покое дополнительного качания нет |
| `.part-jingles` | кольца сдвигаются на `--jingle` |
| `.part-bow` | смычок ходит на `--bow` |

Прорисовка, появление и дрожание — функции секунды воспроизведения: перемотка даёт тот же кадр. Бесконечной CSS-анимации нет. На сильном щипке струна уходит примерно на 3 px, чтобы удар было видно на неподвижном кадре; тихая атака остаётся меньше пикселя. «Без анимации» и системное уменьшение движения оставляют контур и останавливают дрожание.

## Критерий готовности

Ключ есть в каталоге, гравюра есть, в обеих темах читается с первого взгляда и в размере около 120 px, файл не тяжелее ~60 КБ; у секции ведущий инструмент стоит первым.

## Объёмные модели

Гравюра остаётся рисунком по умолчанию. Объём добавляется рядом и не заменяет файл SVG: нет модели, нет WebGL, включено уменьшение движения или слабое устройство — сцена показывает гравюру.

Сборка (без Blender):

```
npm run art3d -- daf
```

Без ключа команда собирает все инструменты, подключённые в `scripts/art3d/build.mjs`. Общие тела (вращение, лофт, трубки струн, тор колец, обечайка) живут в `scripts/art3d/lib.mjs`. На выходе `public/instruments/3d/<key>.glb`, манифест `<key>.json` и общий `index.json`. Рендер сам узнаёт новые ключи из индекса.

Имена узлов и морфов — таблица в `docs/tasks/instruments-3d.md` и контракт `docs/instruments/animation-contract.md`: корень `instrument`, `part-string-<n>` с морфом `vibrate`, `part-skin` с морфом `hit`, `part-jingles`, клип `idle`. Высота после нормировки — 1, центр в начале координат, инструмент смотрит в камеру (+Z). Бюджет: не больше 60 тысяч треугольников и 1,5 МБ после meshopt. Ссылки на справочники пропорций — в шапке скрипта инструмента и в `docs/instruments/credits.md`.

На сцене песни один холст WebGL, и только пока выбран реалистичный вид и проигрыш стоит в кадре. Рисуются модели тех ключей, для которых есть GLB; остальные в том же кадре остаются гравюрами. В галерее `/instruments` у карточки дафа и уда свой холст с материалами: карточку можно повернуть и подвигать входы. Отдельного выбора «объём · гравюра» нет. В настройках песни два пункта: «рисунок» и «реалистичный».

## Своё распознавание

Классификатор живёт в `scripts/instrument_id/`. Он не читает титры и не правит `scripts/pipeline/instruments.py`. Исследование и выбор энкодера — `docs/research/instrument-recognition.md`, список классов — `docs/instruments/taxonomy.md` и `scripts/instrument_id/labels.json`.

Обучение одной командой, из корня репозитория, тем питоном, где стоят torch и остальные пакеты из `scripts/instrument_id/requirements.txt` (torch — с индекса CPU, не CUDA):

```
work/instrument_id/venv/Scripts/python scripts/instrument_id/run.py all
```

Команда качает TinySOL и обучающий IRMAS с Zenodo, если файлы ещё не лежат в `work/instrument_id/data/` и их md5 сходится, считает признаки EfficientAT mn10_as (окно 2 с) и учит линейную голову. Порог отказа выбирается на проверке так, чтобы точность принятых ответов была не ниже 90 %, и только потом замораживается на тесте. Отчёт — `docs/analysis/instrument-id-eval.md`. Веса головы — `scripts/instrument_id/weights/`. Они некоммерческие, потому что IRMAS на Zenodo помечен CC BY-NC-SA 4.0. Энкодер и записи в git не входят.

На новой песне, когда `work/<slug>/source.m4a` уже расшифрован:

```
python scripts/instrument_id/run.py songs
```

Три песни без локального ключа слушает `.github/workflows/instrument-id.yml`. Запуск как у основного конвейера: файл `jobs/instrument-id/<имя>.json` (поле `slug` или `slugs`) либо `workflow_dispatch`, когда файл задания уже есть в ветке по умолчанию. Глоб `jobs/*.json` подпапку не берёт, основной конвейер от этого файла не стартует. Секрет `AUDIO_KEY` расшифровывает запись на раннере. В коммит попадают только json и markdown в `docs/analysis/`, сам файл задания из коммита удаляется. Пока файла задания нет в ветке по умолчанию, кнопка ручного запуска на GitHub не видна. Глаза в это задание не входят.

Окно 2 с, шаг 1 с. Отрезок начинается после двух принятых окон подряд и кончается после двух окон без этой метки. На якорях задание сравнивает смесь и стем Demucs (`other` для мелодических, `drums` для ударных, `vocals` для голоса) и пишет выбор в `docs/analysis/instrument-id-stems.json`. Если стем ни на одной песне не хуже и в сумме ошибается реже, задание повторяет шаг `htdemucs` и в решение идут четыре стема, не смесь. Иначе остаётся смесь. Чужой семье на стеме ответ выбрасывается, а не подменяется. Класса без примеров модель не назовёт. Если не уверена в инструменте, может назвать семью («смычковые», «рамочный барабан», «лютня»). Окно, которое открытое множество считает чужим, не получает ни инструмента, ни семьи.

Добавить пример инструмента, не заводя аккаунт и не беря ключ:

1. Класс уже должен быть в `labels.json` (семья из списка, `catalogKey` или пусто — гравюра `guitar` только у фламенко). Новый язык и новое письмо для этого не нужны.
2. Найти файл с явной лицензией и прямой загрузкой. Берутся CC BY, CC BY-SA, CC0, явный public domain и Free Art License. Не берутся NC, ND, Public Domain Mark и карточка без лицензии. Freesound, Europeana и закрытые карточки Hugging Face без ключа не открываются — их пропускают. YouTube и другие видеохостинги для обучающих клипов не качаются. Видео самой песни — строка «видео» в начале этой страницы, не этот список.
3. Дописать название файла Commons или запись Zenodo в каталог `scripts/instrument_id/sources_fetch.py`. Имя файла меткой не считается: на карточке должны сойтись лицензия и описание инструмента. Один человек и одна пьеса в двух файлах — одна запись.
4. Собрать клипы из корня репозитория:

```
work/instrument_id/venv/Scripts/python scripts/instrument_id/sources_fetch.py <id>
```

Команда ходит в официальный API Commons, представляется адресом репозитория, ждёт между запросами и на 429 читает `Retry-After`. Сырьё остаётся в `work/instrument_id/sources-raw/`, клипы — в `work/instrument_id/extra/<id>/`. Окно 2 с без нахлёста, не больше 10 клипов с одной записи (у длинного файла уда потолок 16, иначе после откладывания живой пьесы в обучении не остаётся 15). В git попадает только `scripts/instrument_id/sources/<id>.csv`: адрес, лицензия, автор, запись, отрезок, имя клипа и флаг. Сомнительный клип (голос поверх, ансамбль, чужой инструмент, слишком коротко) получает флаг и в обучение не идёт. Класс входит в голову только при двух условиях. Первое: 15 принятых клипов из 3 разных записей. Второе, для класса из своего манифеста: на тестовой записи, которой не было в обучении, точность не ниже 0,8 и полнота не ниже 0,3 при опоре не меньше 8 окон. Порог лежит в `labels.json` (`heldOutRecording`). Кто не прошёл, в голову не входит, даже если клипов хватает. Число считается на голове, где этот класс ещё есть, затем голова переучивается без него. Классы TinySOL и IRMAS вторым условием не режутся: их разбиение исполнителя не держит. Счёт и причина нехватки клипов — `docs/analysis/instrument-id-sources.json`.

Разбиение не режет запись. В тест уходит самая крупная запись, после которой в обучении остаётся не меньше 15 клипов; при равенстве размера берётся запись Commons, а не библиотека нот. Это и есть чужая запись второго условия. Вторая такая запись, если обучение всё ещё не меньше 15, уходит в долю порога. Окна одной записи в разные доли не попадают.

5. Дальше снова `all` и страница таксономии: `python scripts/instrument_id/taxonomy.py --write-doc`.

Отрезок нашей песни, который подтвердили два источника, пишется в `docs/analysis/<slug>/confirmed.json`. Эти отрезки не попадают в закоммиченную голову сами: публичные эмбеддинги и расшифрованная запись обычно лежат на разных машинах. Когда обе есть рядом, `python scripts/instrument_id/run.py loso` доучивает проверку на подтверждённых отрезках других песен. Удержанная песня и якоря в это обучение не входят. Если чего-то нет, команда пишет причину и не подставляет число. Так набор растёт от уже разобранных песен, без нового сервиса и без чужого ключа.

Просмотр концерта для новой песни — строка «видео» в начале этой страницы и `scripts/instrument_id/prompts/README.md`. В Actions глаз нет: там нет входа в Antigravity. `run.py watch` ссылку не открывает и `song-status` его не просит. Нет файла видео и нет кадров — строка «видео» либо печатает одну загрузку формата 18, либо становится «отложено», пустой json не пишут.

Ключ `GEMINI_API_KEY` не нужен. Запасной вызов Gemini API включается только явным `--backend gemini-api` и без ключа сразу останавливается.

Сведение звука, кадра и титров: `python scripts/instrument_id/run.py fuse <slug>`. Время берётся из звука или из кадра. Титры имя подтверждают, но минуту не ставят. Принятый отрезок — это титры плюс время из звука или кадра, либо согласие звука и кадра. Согласие звука и кадра без титров принимается с пометкой «нет в титрах». Один источник попадает только в список «проверить» и решением не считается. Инструмент, которого нет в титрах, одним звуком не вводится.

Вызов, которым позже можно заменить или дополнить CLAP, описан в `scripts/instrument_id/contract.py`: файл записи на входе, отрезки на выходе, титров на входе нет.
