# Как добавить песню

Этот раздел — регламент для ИИ-агента (и для человека, который его проверяет). На входе есть **только ссылка на песню или аудиофайл**. Текста, перевода, тайм-кодов, имён музыкантов агенту не дают: всё это он находит и делает сам по шагам ниже.

На выходе — папка `content/songs/<slug>/` и файлы в `public/audio/<slug>/`, которые проходят `npm run validate` без ошибок. Песня открывается на сайте и идёт «за музыкой»: слова подсвечиваются в момент, когда их поют.

## Главные правила

1. **Ничего не выдумывать.** Ни строки текста, ни имени, ни даты, ни атрибуции. Если факт не подтверждён источником или самой записью — он помечается флагом и попадает в список `review` в `song.json`. Пустое поле лучше неверного.
2. **Оригинал — то, что поётся.** На экране сверху стоит ровно то, что звучит, на том языке и тем письмом, со всеми повторами. Канонический текст из дивана — опора, но не замена записи.
3. **Перевод — для чтения в темпе песни.** Строка перевода должна успевать прочитаться, пока звучит строка оригинала (≤ 17 знаков в секунду). Всё, что в перевод не поместилось, уходит в пояснение.
4. **Пояснение — по делу.** Термины, игра слов, аллюзии, контекст, разночтения. Без пафоса, без восклицаний, без «священный», «предвечный» и «сокровенный» в каждой фразе.
5. **Без капса.** Ни в подписях, ни в заголовках, ни в метках. Обычный регистр, как в предложении.
6. **Проверка — машиной и глазами.** `npm run validate` и скриншоты (`npm run shots`) перед каждой отправкой.

## Статусы

- `timing.status`: `draft` (оценка) → `aligned` (автоматическое выравнивание) → `verified` (проверено человеком в редакторе).
- Флаги строк и секций: `text-unverified`, `timing-draft`, `translation-draft`, `comment-draft`, `attribution-unverified`. Снимайте флаг только когда проверка действительно сделана.
- `review` в `song.json` — открытые вопросы простым языком. Песня считается готовой, когда список пуст, флагов нет, а `npm run validate -- --strict <slug>` проходит.

## Структура репозитория

```
content/songs/<slug>/
  song.json        метаданные, палитра, аудио, статусы
  lyrics.json      секции, строки, слова с тайм-кодами, переводы, пояснения
  sources.md       откуда что взято и что не подтверждено
public/audio/<slug>/
  high.m4a         основная запись (AAC)
  saver.m4a        облегчённая (AAC 96 кбит/с)
  peaks.json       огибающая громкости для сцены и таймлайна
work/<slug>/       рабочие файлы: исходник, стемы, транскрипты, кадры (не коммитятся)
scripts/pipeline/  скрипты обработки аудио и выравнивания (Python)
scripts/tools/     валидатор, заготовка песни, скриншоты (Node)
src/instruments/   каталог инструментов и гравюры
docs/              эта методология, формат данных, дизайн
```

Формат файлов описан в [docs/data-format.md](../data-format.md), JSON-схемы для автодополнения — в `docs/schema/`.
