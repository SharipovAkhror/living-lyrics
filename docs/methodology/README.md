# Как добавить песню

Одна страница-маршрут. После каждого шага запускайте `npm run song-status -- <slug>`. Инструмент печатает таблицу стадий и **одну** следующую команду. Выполните её. Если команда снова `song-status`, абзац над ней — ручной шаг: файлы сами не правятся.

Навык `.claude/skills/add-song/SKILL.md` и раздел «Если вас попросили добавить песню» в `AGENTS.md` ведут сюда. Если старый абзац спорит с этой страницей о том, откуда берётся запись, верна эта страница. Кто делает шаг и что нужно от владельца — [new-song-route.md](new-song-route.md). Команды — здесь и в файле стадии.

## Что вам дают

Владелец пишет «добавь песню» и ссылку на **официальное видео**. Файл записи можно прислать вместо ссылки или вдобавок. Больше ничего не нужно до прослушивания в конце.

Звук (дорожка 140) и видео 360p берутся из этого одного ролика на машине владельца: тогда время субтитров, видео и записи совпадает. Команду печатает `song-status`. Одна попытка. Если ответ 429 или страница просит войти, в `review` пишется фраза из стадии 2, и повторно команду не запускают: файл присылает владелец. Чужой ролик, другой концерт и `scripts/pipeline/fetch_audio.sh` не использовать. Текст субтитров в git не кладётся.

Текста, перевода и тайм-кодов не дают. Их находите и пишете по стадиям ниже. Чего не подтвердили источником или файлом — флаг и пункт в `review`. Пустое поле лучше догадки.

## Как устроены тяжёлые шаги

| Где вы | Запись и видео | Demucs, границы, выравнивание |
|---|---|---|
| Машина владельца | `song-status` печатает `yt-dlp`: дорожка 140 и, отдельно, видео 360p того же ролика. Облако YouTube часто не открывает | Если на ветке есть `.github/workflows/pipeline.yml`: файл `jobs/<slug>.json`, push, результат приходит коммитом. Если файла конвейера нет, `song-status` пишет «отложено» и не просит создавать задание |
| Есть Python и ffmpeg | Файл владельца копируют в `work/<slug>/source.m4a` (имя `source.*`, не `.json`). Дальше команда `song-status` | Локально: `scripts/pipeline/*.py`, как напечатает `song-status` |
| Нет ffmpeg или Python | Обработать файл нечем. Текст собирайте по стадии 4, секунды не ставьте | Границы секций не выдумывайте. В таблице канона в столбце «с» ставьте «?» |

Перед коммитом открытый m4a шифруется: `npm run audio:encrypt -- <slug>`. Это условие стадии 12, не следующих стадий. Без `AUDIO_KEY` таблица показывает «шифр: ждёт ключа» и ведёт дальше. В git попадает `content/audio-enc/<slug>/*.m4a.enc`. Каталог `public/audio/` и `work/` не коммитятся. Репозиторий публичный. Ключ `AUDIO_KEY` живёт в `.env.local`, в git его нет.

Расход исполнителей учитывает настройка владельца (`agentic-os-live/ops/usage/`): просмотр видео через `agy_run.py` записывается сам. Сводка сама по себе песню не закрывает.

Шаблоны папки — `docs/methodology/templates/` (в приложении на `/method` их нет, это файлы репозитория). `npm run new-song` копирует их в `content/songs/<slug>/`.

## Правила, которые не меняются от песни к песне

1. Оригинал на экране — то, что поётся, каждый повтор отдельной строкой. Буквы берутся из `canon.md`, не из слуха.
2. Перевод читается, пока строка звучит: не больше 17 знаков в секунду. Считает инструмент по длительности пения (конец последнего слова минус начало первого), не на глаз. Что не поместилось — в пояснение.
3. Пояснение по делу, обычным регистром, без капса.
4. Новая песня не требует нового модуля. Язык — код ISO 639 из `src/data/iso639.ts`. Письмо — код из `SCRIPT_CODES` в `src/data/schema.ts`. Инструмент, которого нет в каталоге, — запись и гравюра по стадии 9, не компонент песни. Палитра уже лежит в `song.json`.

## Если у шага нет входа

Исполнитель не останавливается. Он выбирает самый дешёвый обход, делает его и пишет в журнал песни `docs/analysis/<slug>/route.md`, что заменил и почему. То же коротко — в отчёте. Одна строка журнала — один обход: чего не было, что сделано вместо, почему. Текст песни в журнал не переписывают.

Остановка только там, где нужен человек: вход в аккаунт, оплата, ключ `AUDIO_KEY`. Тогда исполнитель делает всё остальное, что от этого шага не зависит. Шифр без ключа останавливает только коммит записи. Пустые субтитры закрывают титрами экрана и Whisper, не ожиданием файла.

## Стадии

У каждой стадии один и тот же порядок: вход, команды, выход, машинная проверка, типичные ошибки, и строка **Параллельно** — можно ли вести её рядом с другими. Подробности — в файле стадии. Код под песню на стадии 10 не пишется.

Таблица `song-status` идёт в том порядке, в каком один агент получает следующую команду. Номер строки — номер файла стадии (`4б` и `4в` живут в файле 4, `6б` — в файле 6, `9б` — в файле 9). Строки «состав», «реплики», «досье» и «видео» можно вести параллельно с переводом, пояснениями и временем слов, как только есть их вход. Прослушивание владельцем команды не имеет: агент до него доходит и останавливается.

### 1. Приём — [01-intake.md](01-intake.md)

- Вход: ссылка на официальное видео или файл владельца, название и исполнитель, если они уже известны.
- Команды: `npm run new-song -- <slug> "Название" "Исполнитель"`, затем `npm run song-status -- <slug>`.
- Выход: `content/songs/<slug>/` с `song.json`, `lyrics.json`, `sources.md`, `canon.md`. В `sources.md` есть адрес `https://` официального видео или строка `Файл: имя.m4a`. Строка «пустой шаблон» удалена. Язык-заглушка `en` заменён.
- Машинная проверка: строка «приём» — «да». Пока в `review` висит пункт про язык-заглушку `en` и в `languages` только `en`, строка остаётся «нет».
- Параллельно: нет. Без карточки остальные стадии не начинают.
- Типичные ошибки: оставить `en`; посчитать «Файл: нет» источником; выдумать год, альбом или музыкантов; записать чужой ролик.

### 2. Запись — [02-audio.md](02-audio.md)

- Вход: ссылка из `sources.md` или файл владельца.
- Команды: только то, что печатает `song-status`. По ссылке это одна команда `python -m yt_dlp` на дорожку 140 в `work/<slug>/source.m4a`. Потом `process_audio.py`. Шифр в эту очередь не входит: строка «шифр» видна в таблице, а `npm run audio:encrypt -- <slug>` печатается на стадии 12. По файлу — положить его в `work/<slug>/source.m4a` и те же команды. `fetch_audio.sh` не запускать.
- Выход: `audio.status = ready`, `duration` больше 1 и совпадает с файлом, `provenance.kind = file`, открытый `high.m4a` или шифр. Шифр `content/audio-enc/<slug>/high.m4a.enc` обязателен к коммиту, не к следующей стадии.
- Машинная проверка: строка «запись» — «да». Строка «шифр» без ключа — «ждёт ключа», текст «шифр: ждёт ключа», следующая команда уходит дальше. Если в `review` есть «официальное видео: yt-dlp 429» или «официальное видео: просит войти», скачивание больше не просят.
- Параллельно: нет, пока нет файла. Текст по источникам можно собирать, секунды не ставить.
- Типичные ошибки: вторая попытка после 429; коммит открытого m4a; выдумать `gainDb` и `sha256`; скачать другой ролик, чем тот, чьи субтитры пойдут в реплики.

### 3. Структура — [03-structure.md](03-structure.md)

- Вход: обработанная запись.
- Команды: как напечатает `song-status`. Локально это `separate.py`, затем `sections.py`. Через Actions — `jobs/<slug>.json` со стадиями `separate` и `sections`, и только если на ветке есть `pipeline.yml`.
- Выход: в `lyrics.json` вокальные и инструментальные секции. Ключи инструментов из каталога. Неопознанное — `ensemble` и флаг `attribution-unverified`.
- Машинная проверка: строка «структура» — «да» (есть хотя бы одна вокальная строка). Если ни Python с ffmpeg, ни конвейера нет, строка — «отложено», и следующая команда уходит в текст.
- Параллельно: да, вместе с текстом, переводом и видео, когда карточка есть. Границы без стемов или конвейера не выдумывать.
- Типичные ошибки: нарисовать границы на слух. После прогона Actions карта голоса лежит в `docs/analysis/<slug>/sections.suggested.json`, черновик распознавания — в `transcript.json` той же папки. Секунды из этих файлов в текст не копируют.

### 4. Текст — [04-text.md](04-text.md)

- Вход: название, исполнитель, официальная страница или субтитры, шаблон `canon.md`.
- Команды: поиск по шагам стадии 4. Субтитры официального видео — одна попытка `yt-dlp --skip-download --write-subs` (звук не качается). Если их нет, `song-status` печатает команду `agy` (`gemini-3.8-flash-high`) для титров экрана и, когда стем уже есть, Whisper. Затем правка `canon.md` и `lyrics.json`.
- Выход: эталон с источниками и пометкой «Подтверждено: 1 источник» или «Подтверждено: 2 источника»; последовательность; расхождения. Каждая спетая строка находится в эталоне. Буквы — из канона, порядок и время — по свидетелям (субтитры, титры экрана, Whisper). Когда строки уже лежат в `lyrics.json`, в `song.json` заполнен `parts`. Реплики официальных субтитров — `docs/analysis/<slug>/cues.json`: время и id, без текста.
- Машинная проверка: строка «текст» — «да», когда канон не шаблон и все вокальные строки находятся в эталоне. Строка «состав» — «да», когда каждая вокальная строка входит ровно в одну часть. Строка «реплики» — «да», когда `cues.json` покрывает каждую вокальную строку. Если субтитры не скачались, в `review` одна из фраз «официальные субтитры: yt-dlp 429» или «официальные субтитры: пусто». Пока видеофайл есть и титры не прочитаны, строка ещё не «отложено»: `song-status` печатает чтение. Когда свидетелей больше нечем снять, строка становится «отложено», а не циклом.
- Параллельно: да, вместе со стадиями 6, 7, 8, 9 и 5, как только строки лежат в `lyrics.json`. Реплики ждут id строк. Состав перевода не ждёт.
- Типичные ошибки: взять текст с сайта «lyrics» как эталон; склеить повторы в одну строку; переписать канон по Whisper; положить текст субтитров в `cues.json`.

### 5. Тайм-коды — [05-alignment.md](05-alignment.md)

- Вход: текст, который уже сходится с каноном, и запись.
- Команды: если есть `pipeline.yml` — `jobs/<slug>.json` со стадиями `separate`, `align`, `qa`, как печатает `song-status`. Локально — только когда Python и ffmpeg уже поставили стемы. Секунды руками не двигать. Страницы `/song/<slug>/edit` в проекте нет.
- Выход: у каждого слова `s` и `e`, `timing.status` = `aligned` или `verified`.
- Машинная проверка: строка «тайм-коды» — «да», когда `timing.status` равен `aligned` или `verified`. Пока конвейера на ветке нет, строка — «отложено», публикация не открывается, и `song-status` не просит файл `jobs/<slug>.json`.
- Параллельно: да, вместе со стадиями 4, 6, 7 и 9, когда строки уже есть. Реплики, если они не отложены, лучше иметь до задания: выравнивание берёт их окном. Без реплик задание всё равно допустимо, окно тогда — секция.
- Типичные ошибки: оставить `draft` и назвать песню готовой; растянуть слово «чтобы красиво легло»; создать задание на ветке без `pipeline.yml`.

### 6. Перевод — [06-translation.md](06-translation.md), стандарт — [translation-standard.md](translation-standard.md)

- Вход: строки с измеренной или черновой длительностью. Если тайм-коды ещё черновик, скорость всё равно считается по тем `s`/`e`, которые уже лежат в строке. Черновик не повод писать простыню.
- Команды: подстрочник, смысл по стандарту, строка для чтения, остаток в пояснение. Проверка: `npm run song-status -- <slug>` и `npm run validate -- <slug>`.
- Выход: у каждой вокальной строки `tr.ru`, скорость не выше 17 зн/с. Досье — `docs/analysis/translation/<slug>.md`: на строку источник и принятая формулировка. Обратный перевод делает другая модель по вызову Claude · Lead.
- Машинная проверка: строка «перевод» — «да», когда скорость в норме. Строка «досье» — «да», когда в файле есть каждый id, слова «Источник» и «Принято» и помета обратного перевода. Если Gemini недоступен, в `review` пишут «обратный перевод: ждёт Gemini», строка становится «ждёт».
- Параллельно: да, вместе со стадиями 4, 5, 7 и 9. Черновик времени не повод писать простыню и не повод ждать выравнивания.
- Типичные ошибки: подстрочник на экран; мерить паузу до следующей строки; считать скорость на глаз; выдумать обратный перевод, не получив его от другой модели.

### 7. Пояснения — [07-comment.md](07-comment.md)

- Вход: фрагменты `canon.md` и инструментальные секции.
- Команды: одно пояснение на фрагмент — автор, форма, контекст — у первой его секции или первой строки. У проигрыша поле `note`. Секция только с `voice` или `choir` ничего не требует. Затем `song-status`.
- Выход: у каждого спетого фрагмента есть это пояснение. У проигрыша есть `note`. Пояснение отдельной строки — только если перевод не передал термин, игру слов или аллюзию. Строка с `em` пояснения не требует: пара `**…**` уже стоит в переводе.
- Машинная проверка: строка «пояснения» — «да». Машина не ищет строки, где перевод что-то потерял: это чек-лист в файле стадии. Валидатор предупреждает, если в `comment` попали слова «субтитр», «титр», «транскрипт», whisper, «распознава», «слухом», «ухом», «не проверен», «реплика».
- Параллельно: да, вместе со стадиями 4, 6, 5 и 9.
- Типичные ошибки: пустое пояснение к каждой секции и к каждому `em`; редакторская заметка в `comment`; строка из одних знаков вместо секции `voice`; решить, что секция с `voice` и ещё одним инструментом заметки не требует.

### 8. Транскрипция — [08-transliteration.md](08-transliteration.md)

- Вход: строки с письмом `Arab` или `Aran`.
- Команды: заполнить `translit` по таблицам стадии 8.
- Выход: кириллица как поётся.
- Машинная проверка: `npm run validate -- <slug>` не предупреждает о пустом `translit`. Строка «транскрипция» — «да». Латиница и кириллица транскрипцию не требуют: пустое поле у них — норма.
- Параллельно: да, как только есть строки арабским письмом. Тайм-коды не нужны.
- Типичные ошибки: научная транслитерация с диакритикой; транскрипция «как в словаре», а не как в записи.

### 9. Инструменты — [09-instruments.md](09-instruments.md)

- Вход: видео того же ролика, что и запись, титры `song.json` и каталог `src/instruments/list.ts`.
- Команды: как печатает `song-status`, строка «видео». Сначала видео 360p (формат 18), затем просмотр Claude · Lead по `scripts/instrument_id/prompts/watch-video.md` (Grok `agy` не вызывает). Просмотр начинается с вида ролика. Затем `python scripts/instrument_id/run.py fuse <slug>` и `python scripts/instrument_id/run.py entries <slug> --write`. Пока ключ не опознан: `ensemble` и `attribution-unverified`.
- Выход: `vision.json` с кадрами и, у нового просмотра, с `video_type`. Старый файл без этого поля остаётся годным. Дальше `fusion.json`, `entries.md`. Все ключи есть в каталоге. Вступление — по правилу «титры и чёткий кадр» или «три плана». У лирик-видео буквы титров идут в стадию 4, не в этот файл.
- Машинная проверка: строка «видео» — «да», когда эти три файла есть. Если ссылки и файла видео нет, или скачивание остановлено фразой в `review`, строка — «отложено». Строка «инструменты» — «да», когда валидатор не ругает неизвестный ключ. Звуковое распознавание само по себе строку «видео» не закрывает.
- Параллельно: да, вместе со стадиями 4, 6 и 5. Время слов не нужно.
- Типичные ошибки: восемь ключей «на всякий случай»; имя музыканта без буклета или титра; принять инструмент по одному кадру; вызвать `agy` из задачи Grok.

### 10. Сцена — [10-choreography.md](10-choreography.md)

- Вход: готовые данные стадий 3–8.
- Команды: нет. `em` и `br` уже поля строки. Поле `fx` не заполнять.
- Выход: ноль файлов в `src/`.
- Машинная проверка: строка «сцена» всегда «да».
- Параллельно: работы нет.
- Типичные ошибки: компонент, хук или страница под одну песню.

### 11. Проверка — [11-qa.md](11-qa.md)

- Вход: песня, у которой предыдущие строки таблицы закрыты или честно отложены.
- Команды: `npm run validate -- <slug>`, для финала `npm run validate -- --strict <slug>`, `npm run typecheck`.
- Выход: пустые `review` и флаги. Предупреждения на чужих старых песнях не стирайте вместе со своим текстом.
- Машинная проверка: строка «проверка» — «да». Валидатор отдельно предупреждает, если нет `cues.json` или досье, и отвергает `cues.json`, в котором есть текст реплики.
- Параллельно: нет. Её делают, когда предыдущие строки закрыты или честно отложены.
- Типичные ошибки: снять `text-unverified`, не открыв источник; обнулить `review`, не ответив на вопрос; стереть фразу «ждёт Gemini» или «yt-dlp 429», не получив файл.

### 12. Публикация — [12-publish.md](12-publish.md)

- Вход: строки 1–11 закрыты, тайм-коды не `draft`.
- Команды: как напечатает `song-status`. Сначала шифр, если его ещё нет и ключ уже есть. Затем `git add` папки песни, шифра, `docs/analysis/<slug>` и досье перевода, если эти пути есть. Без ключа коммит записи не начинается.
- Выход: коммит в свою ветку. В `main` не сливать. Push — только если задание это прямо разрешает. Прослушивание — владелец, после этого коммита, не команда агента.
- Машинная проверка: строка «публикация» — «да», и команда называется сама.
- Параллельно: нет.
- Типичные ошибки: `git add public/audio`; коммит `work/`; коммит при `timing.status = draft`; слить ветку в `main` самим.

## Статусы

- `timing.status`: `draft` (оценки или пусто) → `aligned` (выравнивание доказало строки) → `verified` (владелец прослушал запись; кнопка «Не совпадает» ничего не оставила, либо отметки уже разобраны). Редактора тайм-кодов нет. Пока стоит `draft`, сайт не заливает слова по времени.
- Флаги строк и секций: `text-unverified`, `timing-draft`, `translation-draft`, `comment-draft`, `attribution-unverified`. Снимайте флаг после проверки, не до неё.
- `review` в `song.json` — открытые вопросы обычными фразами. Песня готова, когда список пуст, флагов нет, тайм-коды не черновик и `npm run validate -- --strict <slug>` проходит.

Порядок одной следующей команды: приём, запись, структура, текст, состав, реплики, перевод, досье, пояснения, транскрипция, видео, инструменты, тайм-коды, проверка. Строка «шифр» в таблице есть и команду забирает только на публикации, когда остальные строки закрыты. Пока конвейера нет, текст и перевод идут при черновых секундах, а публикация всё равно ждёт выравнивания. Пока тайм-коды «черновик» и конвейер на ветке есть, задание просят после видео и инструментов, не вместо состава, реплик и досье.
