# Дорога новой песни: кто что делает и откуда

Взгляд оркестратора на маршрут из [README.md](README.md): какой агент делает каждый шаг и что нужно от владельца. Порядок команд и проверки — по-прежнему в README и файлах стадий. Команду печатает `npm run song-status -- <slug>`. Прослушивание владельцем (шаг 9) этой команды не имеет: агент до него доходит и останавливается. Слияние в `main` (шаг 10) делает оркестратор, не исполнитель песни.

Шаги таблицы и строки `song-status`:

| Шаг | Строки `song-status` | Файл стадии |
|---|---|---|
| 1. Приём | «приём», затем «запись» (дорожка 140, обработка). Шифр — условие коммита на шаге 10, не стена перед текстом. Без ключа строка «шифр» показывает «шифр: ждёт ключа», и `song-status` идёт дальше. Видео 360p — не эта команда | [01-intake.md](01-intake.md), [02-audio.md](02-audio.md) |
| 2. Строки по субтитрам | «реплики». Если субтитров нет — титры экрана и Whisper, файл у владельца не ждут | [04-text.md](04-text.md) |
| 3. Текст и состав | «текст», «состав» | [04-text.md](04-text.md) |
| 4. Перевод | «перевод», «досье» | [06-translation.md](06-translation.md), [translation-standard.md](translation-standard.md) |
| 5. Пояснения | «пояснения» | [07-comment.md](07-comment.md) |
| 6. Время слов | «тайм-коды». Один агент получает задание после видео и инструментов. Параллельная ветка может начать раньше, когда строки уже есть | [05-alignment.md](05-alignment.md) |
| 7. Инструменты | «видео», «инструменты». `agy` вызывает Claude · Lead. через `agy_run.py` настройки владельца, он пишет расход; отдельной строки песни у журнала нет | [09-instruments.md](09-instruments.md) |
| 8. Проверка | «проверка» | [11-qa.md](11-qa.md) |
| 9. Прослушивание | команды нет | [11-qa.md](11-qa.md), раздел «Отметки владельца» |
| 10. Публикация | «публикация» — коммит в свою ветку. Слияние в `main` — не эта команда | [12-publish.md](12-publish.md) |

Строки «структура», «транскрипция» и «сцена» остаются в таблице `song-status`. Структура — [03-structure.md](03-structure.md), транскрипция — [08-transliteration.md](08-transliteration.md), сцена — [10-choreography.md](10-choreography.md): кода под песню нет. Шаги 3–7 по-прежнему идут параллельно, каждый в своей ветке. Один агент всё равно получает одну следующую команду: самую раннюю незакрытую строку.

## Откуда приходит песня

Владелец пишет в чат Claude Code — с компьютера или с телефона (Remote Control): «добавь песню» и ссылку на **официальное видео** (YouTube). Файл записи можно прислать вместо ссылки или вдобавок. Больше от владельца ничего не нужно до прослушивания в конце.

Звук и видео берутся из одного ролика: тогда время субтитров, видео и записи совпадает. `song-status` печатает это двумя командами, не скриптом `scripts/pipeline/fetch_audio.sh`: сначала дорожка 140 (строка «запись»), позже формат 18 (строка «видео»).

## Шаги

| № | Шаг | Кто | Что получается | Где смотреть |
|---|---|---|---|---|
| 1 | Приём | Claude · Lead | на машине владельца `yt-dlp`: звук (дорожка 140) и видео 360p в `work/<slug>/`; карточка песни; титры из описания видео. Шифр — перед коммитом записи, не перед следующими шагами | `npm run song-status -- <slug>` |
| 2 | Строки по субтитрам | Claude · Lead | официальные дорожки субтитров → время строк ±0,3 с (`docs/analysis/<slug>/cues.json`, без текста субтитров). Пустые субтитры: титры экрана и Whisper, буквы из канона | Dashboard, `cues.json` |
| 3 | Текст и состав | Grok · Text | `canon.md` по изданиям, каждый повтор — строка, «Состав песни» (книги, авторы, издания) | «О песне» → «Состав» |
| 4 | Перевод | Grok · Translation, проверка — Gemini | перевод по стандарту научного перевода, досье с источниками на каждую строку, обратный перевод Gemini | `docs/analysis/translation/<slug>.md` |
| 5 | Пояснения | Grok · Text | пояснения по делу, со ссылками | сайт, «Пояснение» |
| 6 | Время слов | GitHub Actions, Grok · Sync | Demucs, MMS, Whisper; доказанные строки; пословная подсветка включается при 90 % в каждой группе, цель — 100 % | `docs/analysis/<slug>-qa.md` |
| 7 | Инструменты | Gemini · Watch, Grok · Entries | Gemini смотрит видео; вступления по правилу «титры + кадр» или «три плана»; недостающие рисунки — Grok · Art | сцена в проигрышах |
| 8 | Проверка | Claude · Lead | `validate`, `song-status`, кадры на iPhone, компьютере и экране машины | Dashboard |
| 9 | Прослушивание | владелец | слушает, кнопкой «Не совпадает» отмечает места | «О песне» → «Отмеченные места» |
| 10 | Публикация | Claude · Lead | слияние в `main` → сайт обновляется сам (Vercel) | сайт |

Шаги 3–7 идут параллельно, каждый — в своей ветке. Оркестратор принимает каждый по отдельности. Где песня на дороге — видно в Dashboard.

## Чего маршрут не требует

Нового кода под песню, API-ключей, сторонних сервисов, кроме уже подключённых (Claude Code, GitHub, Vercel, Grok Build, Antigravity).
