# 5. Пословные тайм-коды

**Цель:** у каждого слова время начала `s` и конца `e` измерено по голосу, а не оценено. Сайт включает пословную заливку только там, где два независимых выравнивателя и атака голоса сошлись. Текст слов скрипт не меняет.

Синхронизацию делают скрипты. Тяжёлые шаги (Demucs, MMS, модели WhisperX) считаются на GitHub Actions: публичный репозиторий, раннер 4 ядра / 16 ГБ, таймаут 150 минут. Локально на Windows записей нет (они зашифрованы, ключ `AUDIO_KEY` только в секрете репозитория) и нет ffmpeg.

## Запуск

Положить в ветку файл `jobs/<slug>.json` и запушить её. Пример для I Have Come Alive:

```json
{"slug": "i-have-come-alive", "stages": ["separate", "align", "qa"]}
```

Поля:

| Поле | Смысл |
|---|---|
| `slug` | папка `content/songs/<slug>`. Если поля нет, берётся имя файла |
| `stages` | какие стадии запустить. По умолчанию `separate`, `align`, `qa` |
| `align` | дополнительные аргументы `align.py`, списком строк |
| `qa` | дополнительные аргументы `qa_sync.py`. `--apply` стадия `qa` добавляет сама |

Стадии, если их заказать: `decrypt`, `separate`, `sections`, `transcribe`, `align`, `qa`. Для тайм-кодов достаточно трёх из примера: расшифровка записи подключается сама, когда стема ещё нет. `sections` и `transcribe` тайм-коды не пишут.

Воркфлоу: `.github/workflows/pipeline.yml`. Он стартует от пуша `jobs/*.json` в любую ветку. Ручной запуск (`workflow_dispatch`) сработает, только когда этот файл воркфлоу есть в `main`; пока его там нет, запускайте файлом задания. Раннер коммитит результат в ту же ветку и удаляет файл задания. Удаление снова трогает `jobs/*.json`, поэтому следом приходит короткий пустой запуск: заданий уже нет, он сразу выходит.

Секрет `AUDIO_KEY` (64 шестнадцатеричных знака) обязателен. Без него воркфлоу падает на первом шаге.

Пока идёт прогон, в эту ветку лучше ничего не пушить: раннер делает `git pull --rebase` перед своим коммитом.

## Стадии

Рабочий каталог на раннере — `work/<slug>/`. В репозиторий из него попадает только отчёт проверки.

1. **Расшифровка.** `content/audio-enc/<slug>/high.m4a.enc` → `work/<slug>/source.m4a`.
2. **Стемы.** Demucs `htdemucs` → `work/<slug>/stems/vocals.wav`. Между запусками стем лежит в кэше Actions `work/stem-cache`: FLAC, зашифрованный тем же `AUDIO_KEY` (AES-256-GCM). Имя файла включает хэш записи, поэтому новый исходник не подхватит старый стем. Повторный прогон той же записи отделение не пересчитывает.
3. **Выравнивание** (`align.py`). Известный текст строк ставится на вокальный стем. Пишет `s`/`e`, помечает каждую вокальную строку флагом `timing-draft` и оставляет `timing.status = draft`. Границы секций не двигает (для этого есть отдельный флаг `--move-sections`, конвейер его не передаёт).
4. **Проверка** (`qa_sync.py --apply`). Сверяет уже записанные времена с голосом и со вторым выравнивателем. Снимает `timing-draft` только у доказанных строк. Ставит `timing.status = aligned` только если критерий песни пройден, иначе оставляет `draft` и пишет причину в `timing.notes`. Текст слов и времена `s`/`e` на этом шаге не меняются. Отчёт копируется в `docs/analysis/<slug>-qa.md`.

Код выхода `qa_sync.py`: 0 — критерий пройден и нет проваленных сольных строк; 1 — проверка дошла до конца, но есть строки не в такт (воркфлоу всё равно коммитит результат); 2 — стадия упала, в отчёт пишется хвост лога.

`timing.status = verified` ни `align.py`, ни `qa_sync.py --apply` не перезаписывают: это ручная отметка, что человек уже принял время.

## Два выравнивателя

Первый — torchaudio MMS forced aligner (модель `MMS_FA`). Буквенные вероятности считаются по всему стему один раз (50 кадров в секунду, кусками по 30 с, кэш `work/<slug>/align-emission.npy`), затем текст ищется поиском Витерби. Арабское письмо и прочие нелатинские строки перед этим латинизируются (uroman). Латиница нормализуется к a–z: апостроф выбрасывается, `ı` → `i`, `ß` → `ss`.

Второй — другие веса, не вторая обёртка над тем же MMS_FA. Пакет `ctc-forced-aligner` по умолчанию использует те же веса, поэтому он не вызывается.

- Там, где язык есть в таблице WhisperX, берётся его акустическая модель: английский, немецкий, испанский, французский, итальянский — из torchaudio; арабский, персидский, турецкий и остальные из той же таблицы — с Hugging Face. Это выравнивание известного текста, без распознавания и без диаризации.
- Азербайджанский и латынь в таблице WhisperX нет. Для них второй выравниватель — `facebook/mms-1b-all` со своим адаптером (`azj-script_latin`, `lat`), по исходному письму, без uroman.
- Средневековый немецкий (`gmh`) и османский турецкий (`ota`) своего адаптера не имеют. Подмена современным немецким или турецким не делается: такая строка остаётся недоказанной. Если в данных язык записан как `de`, конвейер честно гоняет современную немецкую модель WhisperX; расхождение со средневековым произношением должно всплыть как провал проверки, а не как подмена модели.

На одной строке работает только один второй выравниватель. Модели грузятся по одному языку и выгружаются. Соло, в котором первый выравниватель не уверен, вторым не гоняется.

Первый выравниватель уверен в строке (`good`), когда средняя вероятность букв ≥ 0,30, разрыв с лучшей альтернативой ≤ 1,2 и найденное начало не дальше 0,5 с от якоря общего прохода. Иначе строка остаётся черновиком: старые времена сохраняются, текст в голосе не найден.

## Атака голоса

Начало измеренного слова притягивается к ближайшему пику атаки на вокальном стеме, если пик не дальше 0,10 с. Пик — локальный максимум кривой атаки (середина спектра, верх, фронт громкости) не ниже 0,5, где 1 — 95-й перцентиль этой записи; соседние пики ближе 40 мс схлопываются. Дальше 0,10 с начало не двигается: это уже провал проверки, а не поправка.

Слово без своей атаки может быть легато: голос уже звучит, и предыдущее слово кончилось не раньше чем за 0,20 с. Первое слово фразы после паузы легато не считается — у него обязана быть атака. Атака, уже отданная предыдущему слову, для следующего не доказательство.

## Что считается доказанной строкой

Флаг `timing-draft` снимается только если одновременно:

- строка сольная: в `voice` строки или секции назван один исполнитель. Пусто, «все», связка через « и », хор, choir, chorus, cappella, ансамбль, оркестр, tutti — не соло. У I Have Come Alive это 38 сольных строк из 60 вокальных;
- первый выравниватель уверен (`good`) и текст строки с момента прогона не менялся;
- у каждого слова с буквами второй выравниватель поставил начало не дальше 0,10 с от начала первого выравнивателя (сравнение до притяжения к атаке);
- каждое такое слово либо в 0,10 с от своей атаки, либо легато;
- проверка сдвига строки целиком не говорит «рано», «поздно» или «нет голоса».

Хор и дуэт флаг не теряют: в стеме голоса смешаны, и атака может принадлежать другому.

`timing.status = aligned` ставится, когда доказана хотя бы одна сольная строка. У всех таких строк расхождение начала слова с атакой ≤ 0,10 с по построению (медиана и 90-й перцентиль пишутся в отчёт и в `timing.notes`). Если не доказана ни одна, статус остаётся `draft`, флаг стоит на всех вокальных строках, причина — в `timing.notes`.

Сайт включает пословную заливку, когда `timing.status` не `draft`, и выключает её у строки с флагом `timing-draft` (`src/scene/Scene.tsx`). Поэтому доказанные строки могут загораться по словам, пока соседние ещё показываются целиком. Это сознательный выбор: иначе одна непрошедшая строка гасила бы заливку у всех доказанных.

## Отчёт

`docs/analysis/<slug>-qa.md`:

- пройден ли критерий песни, сколько сольных строк доказано и не доказано;
- медиана и 90-й перцентиль расхождения начала слова с атакой у доказанных строк (и то же расхождение до притяжения к атаке);
- почему остальные строки не доказаны;
- худшие сольные места: id строки и время начала, чтобы их можно было прослушать;
- строки, чей текст MMS не нашёл в голосе (вероятное расхождение текста и пения; слова в `lyrics.json` при этом не переписываются);
- таблица по строкам: соло или нет, сдвиг строки целиком, решение.

Подробности чтения отчёта — в [стадии 11](11-qa.md).

## Статусы

| `timing.status` | Когда |
|---|---|
| `draft` | время ещё оценка, либо проверка не доказала ни одной сольной строки. Причина в `timing.notes` |
| `aligned` | проверка доказала хотя бы одну сольную строку. Недоказанные строки остаются с `timing-draft` |
| `verified` | человек принял время. Скрипты его не перезаписывают |

Флаг `timing-draft` на строке: сайт показывает строку целиком, без пословной заливки. Снимает его только `qa_sync.py --apply`.

## Критерий готовности

- `npm run validate` не ругается на порядок слов и на слово, которое кончается позже записи больше чем на 0,5 с.
- Если `timing.status = aligned`, хотя бы у одной вокальной строки нет флага `timing-draft`.
- В `docs/analysis/<slug>-qa.md` у доказанных сольных строк 90-й перцентиль расхождения с атакой ≤ 0,1 с, а непрошедшие строки перечислены с причиной.
