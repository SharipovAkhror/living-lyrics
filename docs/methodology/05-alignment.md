# 5. Пословные тайм-коды

**Цель:** у каждого слова время начала `s` и конца `e` измерено по голосу, а не оценено. Сайт включает пословную заливку только там, где два независимых выравнивателя и атака голоса сошлись. Текст слов скрипт не меняет.

Синхронизацию делают скрипты. Тяжёлые шаги (Demucs, MMS, модели WhisperX) считаются на GitHub Actions: публичный репозиторий, раннер 4 ядра / 16 ГБ, таймаут 150 минут. Локально на Windows записей нет (они зашифрованы, ключ `AUDIO_KEY` только в секрете репозитория) и нет ffmpeg.

## Запуск

Положить в ветку файл `jobs/<slug>.json` и запушить её. Пример для I Have Come Alive:

```json
{"slug": "i-have-come-alive", "stages": ["separate", "align", "qa"]}
```

Поля:

| Поле | Смысл |
|---|---|
| `slug` | папка `content/songs/<slug>`. Если поля нет, берётся имя файла |
| `stages` | какие стадии запустить. По умолчанию `separate`, `align`, `qa` |
| `align` | дополнительные аргументы `align.py`, списком строк |
| `qa` | дополнительные аргументы `qa_sync.py`. `--apply` стадия `qa` добавляет сама |

Стадии, если их заказать: `decrypt`, `separate`, `sections`, `transcribe`, `align`, `qa`. Для тайм-кодов достаточно трёх из примера: расшифровка записи подключается сама, когда стема ещё нет. `sections` и `transcribe` тайм-коды не пишут.

Воркфлоу: `.github/workflows/pipeline.yml`. Он стартует от пуша `jobs/*.json` в любую ветку. Ручной запуск (`workflow_dispatch`) сработает, только когда этот файл воркфлоу есть в `main`; пока его там нет, запускайте файлом задания. Раннер коммитит результат в ту же ветку и удаляет файл задания. Удаление снова трогает `jobs/*.json`, поэтому следом приходит короткий пустой запуск: заданий уже нет, он сразу выходит.

Секрет `AUDIO_KEY` (64 шестнадцатеричных знака) обязателен. Без него воркфлоу падает на первом шаге.

Пока идёт прогон, в эту ветку лучше ничего не пушить: раннер делает `git pull --rebase` перед своим коммитом.

## Стадии

Рабочий каталог на раннере — `work/<slug>/`. В репозиторий из него попадает только отчёт проверки.

1. **Расшифровка.** `content/audio-enc/<slug>/high.m4a.enc` → `work/<slug>/source.m4a`.
2. **Стемы.** Demucs `htdemucs` без `--two-stems` → `work/<slug>/stems/{vocals,drums,bass,other}.wav`. Ударные, бас и остальное нужны следующей задаче (признаки звука для анимации); конвейер их считает и не смешивает обратно. Между запусками все четыре стема лежат в кэше Actions `work/stem-cache`: FLAC, зашифрованный тем же `AUDIO_KEY` (AES-256-GCM). Имя файла включает хэш записи и пометку четырёх стемов, поэтому новый исходник и старый кэш из одного только вокала не подхватываются. Повторный прогон той же записи отделение не пересчитывает. Веса моделей в репозиторий не кладутся.
3. **Выравнивание** (`align.py`). Известный текст строк ставится на вокальный стем. Пишет `s`/`e`, помечает каждую вокальную строку флагом `timing-draft` и оставляет `timing.status = draft`. Границы секций не двигает (для этого есть отдельный флаг `--move-sections`, конвейер его не передаёт).
4. **Проверка** (`qa_sync.py --apply`). Сверяет начало слова у выравнивателя **до притяжения** с атакой голоса и со вторым выравнивателем. Снимает `timing-draft` только у доказанных строк. Ставит `timing.status = aligned` только если доказано не меньше 80 % сольных строк, иначе оставляет `draft` и пишет долю и причины в `timing.notes`. Текст слов и времена `s`/`e` на этом шаге не меняются. Отчёт копируется в `docs/analysis/<slug>-qa.md`.

Код выхода `qa_sync.py`: 0 — критерий пройден и нет проваленных сольных строк; 1 — проверка дошла до конца, но есть строки не в такт (воркфлоу всё равно коммитит результат); 2 — стадия упала, в отчёт пишется хвост лога.

`timing.status = verified` ни `align.py`, ни `qa_sync.py --apply` не перезаписывают: это ручная отметка, что человек уже принял время.

## Два выравнивателя

Первый — torchaudio MMS forced aligner (модель `MMS_FA`). Буквенные вероятности считаются по всему стему один раз (50 кадров в секунду, кусками по 30 с, кэш `work/<slug>/align-emission.npy`), затем текст ищется поиском Витерби. Арабское письмо и прочие нелатинские строки перед этим латинизируются (uroman). Латиница нормализуется к a–z: апостроф выбрасывается, `ı` → `i`, `ß` → `ss`.

Второй — WhisperX, другие веса, не второй MMS. Пакет `ctc-forced-aligner` по умолчанию использует те же веса MMS_FA, а `facebook/mms-1b-all` — тот же семейный акустический контур, поэтому ни тот, ни другой не вызываются. Веса MMS (лицензия CC-BY-NC 4.0) качаются в кэш раннера и в репозиторий не коммитятся.

- WhisperX берётся там, где в его таблице уже есть модель: английский, немецкий, испанский, арабский, персидский, турецкий, а также французский, итальянский и остальные языки той же таблицы. Английский, немецкий, испанский, французский и итальянский — из torchaudio; арабский, персидский, турецкий и прочие — с Hugging Face. Это выравнивание известного текста, без распознавания и без диаризации.
- Азербайджанский, латынь, средневековый немецкий (`gmh`) и османский турецкий (`ota`) своего чекпоинта в этой таблице не имеют. Второго выравнивателя у них нет, и строка остаётся недоказанной. Подмена современным немецким или турецким не делается. Если в данных язык записан как `de`, конвейер гоняет современную немецкую модель WhisperX; расхождение со средневековым произношением всплывает как провал проверки.

Окно второго выравнивателя — фраза, которую построчный проход уже поставил на голос. К ней можно добавить до 2 с, но окно обрывается на соседней измеренной строке и не длиннее 12 с. Граница секции — забор с запасом 0,5 с, не 2 с. Черновые `s`/`e` слов в `lyrics.json` окном не служат и соседом не считаются: это неточные черновики, а не карта голоса.

Откуда брались секунды расхождения на английском. Общий проход Витерби по всей песне сажал первую английскую строку на более ранний вокализ (окно от 27 с при пении около 100 с), и второй выравниватель уезжал на следующий припев (68 с). Якорь, вышедший из своей секции больше чем на 2 с, выбрасывается; вместо него каждая секция выравнивается в своём окне (границы карты ± 15 с). Отдельная ошибка: запас 2 с на строках, которые стоят вплотную, отдавал WhisperX ещё и следующую фразу. На «You have lit the fire / I have come alive» расхождение было 1,1–1,9 с при том, что сама строка по сдвигу была в такт. Теперь окно не заходит на соседнюю измеренную строку. До ±1 с вокруг уже притянутых времён окно не сужается: иначе второй только пересказывает первого.

Турецкая модель WhisperX поставляется с языковой моделью; для выравнивания она не нужна, поэтому при отсутствии пакета `pyctcdecode` берётся обычный CTC-токенайзер того же чекпоинта.

## Особенности репертуара

- **Мелизмы.** Одна гласная тянется на 3–6 секунд — это нормально для мавваля и мугама. Выравниватель помечает буквы, а конец слова дотягивается по голосу, не оценкой.
- **Хор и солист одновременно.** Строка выравнивается по главному голосу; в пояснении секции объясняется, что тексты накладываются. Хор и дуэт не соло, флаг `timing-draft` у них остаётся.
- **Повторы.** Каждое повторение — отдельная строка, иначе выравниватель перепрыгивает на следующее такое же место.

На одной строке работает только один второй выравниватель. Модели грузятся по одному языку и выгружаются. Соло, в котором первый выравниватель не уверен, вторым не гоняется. Латиница первого выравнивателя теряет апостроф (`I've` → `ive`). WhisperX апостроф оставляет, если он есть в словаре модели. Начало слова в обоих случаях — первая буква, поэтому апостроф сам по себе не сдвигает строку на секунду; расхождение начала всё равно видно в отчёте.

Первый выравниватель уверен в строке (`good`), когда средняя вероятность букв ≥ 0,30, разрыв с лучшей альтернативой ≤ 1,2 и найденное начало не дальше 0,5 с от якоря общего прохода. Иначе строка остаётся черновиком: старые времена сохраняются, текст в голосе не найден.

## Атака голоса

Начало измеренного слова притягивается к ближайшему пику атаки на вокальном стеме, если пик не дальше 0,10 с. Пик — локальный максимум кривой атаки (середина спектра, верх, фронт громкости) не ниже 0,5, где 1 — 95-й перцентиль этой записи; соседние пики ближе 40 мс схлопываются. Дальше 0,10 с начало не двигается.

Притяжение меняет только записанное `s`. После него расстояние от записанного начала до той же атаки равно нулю — это не измерение. Проверка и отчёт берут начало первого выравнивателя **до** притяжения и сравнивают его с ближайшей атакой, которая не принадлежит предыдущему слову. Атака предыдущего слова — это пик не позже его допритяжного начала плюс 0,10 с.

## Что считается доказанной строкой

Флаг `timing-draft` снимается только если одновременно:

- строка сольная: в `voice` строки или секции назван один исполнитель. Пусто, «все», связка через « и », хор, choir, chorus, cappella, ансамбль, оркестр, tutti — не соло. У I Have Come Alive после пересборки текста это 103 сольных строки из 105 вокальных;
- первый выравниватель уверен (`good`) и текст строки с момента прогона не менялся;
- у строки есть второй выравниватель, и у каждого слова с буквами он поставил начало не дальше 0,10 с от начала первого (оба времени — до притяжения);
- у каждого такого слова начало первого выравнивателя до притяжения не дальше 0,10 с от ближайшей своей атаки. Легато доказательством не считается: нет отдельной атаки — строка не доказана.

Хор и дуэт флаг не теряют: в стеме голоса смешаны, и атака может принадлежать другому. Сдвиг строки целиком (порог 0,25 с) в отчёте остаётся тревогой, но в pass/fail не входит: он считается уже по записанным временам.

`timing.status = aligned` ставится, только когда доказано не меньше 80 % сольных строк. 30 из 38 (78,9 %) — ещё `draft`, 31 из 38 (81,6 %) — уже `aligned`. Строка «текст не найден в голосе» в числитель не входит и в знаменателе остаётся. Иначе статус `draft`, флаг стоит на недоказанных строках, доля и причины — в `timing.notes`. Медиана и 90-й перцентиль в отчёте — это допритяжное расхождение у доказанных строк, не расстояние после притяжения.

Сайт включает пословную заливку, когда `timing.status` не `draft`, и выключает её у строки с флагом `timing-draft` (`src/scene/Scene.tsx`). Поэтому доказанные строки могут загораться по словам, пока соседние ещё показываются целиком. Это сознательный выбор: иначе одна непрошедшая строка гасила бы заливку у всех доказанных.

## Отчёт

`docs/analysis/<slug>-qa.md`:

- пройден ли критерий песни (не меньше 80 % сольных строк), сколько доказано и не доказано;
- медиана и 90-й перцентиль допритяжного расхождения начала слова с атакой у доказанных строк и согласие двух выравнивателей. Порог слова 0,1 с. Порог 0,25 с — это сдвиг строки целиком, он подписан отдельно;
- почему остальные строки не доказаны;
- худшие сольные места: id строки и время начала, чтобы их можно было прослушать;
- строки, чей текст MMS не нашёл в голосе (вероятное расхождение текста и пения; слова в `lyrics.json` при этом не переписываются);
- таблица по строкам: соло или нет, сдвиг строки целиком, решение.

Подробности чтения отчёта — в [стадии 11](11-qa.md).

## Статусы

| `timing.status` | Когда |
|---|---|
| `draft` | время ещё оценка, либо доказано меньше 80 % сольных строк. Доля и причины в `timing.notes` |
| `aligned` | доказано не меньше 80 % сольных строк. Недоказанные строки остаются с `timing-draft` |
| `verified` | человек принял время. Скрипты его не перезаписывают |

Флаг `timing-draft` на строке: сайт показывает строку целиком, без пословной заливки. Снимает его только `qa_sync.py --apply`.

## Критерий готовности

- `npm run validate` не ругается на порядок слов и на слово, которое кончается позже записи больше чем на 0,5 с.
- Если `timing.status = aligned`, доказано не меньше 80 % сольных строк (у них нет флага `timing-draft`).
- В `docs/analysis/<slug>-qa.md` у доказанных сольных строк 90-й перцентиль допритяжного расхождения с атакой ≤ 0,1 с, а непрошедшие строки перечислены с причиной.
