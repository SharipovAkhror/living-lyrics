# 5. Пословные тайм-коды

**Цель:** у каждого слова время начала `s` и конца `e` измерено по голосу, а не оценено. Сайт включает пословную заливку только там, где два независимых выравнивателя и атака голоса сошлись. Текст слов скрипт не меняет.

Синхронизацию делают скрипты. Тяжёлые шаги (Demucs, MMS, модели WhisperX) считаются на GitHub Actions: публичный репозиторий, раннер 4 ядра / 16 ГБ, таймаут 150 минут. Локально на Windows записей нет (они зашифрованы, ключ `AUDIO_KEY` только в секрете репозитория) и нет ffmpeg.

## Запуск

Положить в ветку файл `jobs/<slug>.json` и запушить её. Пример для I Have Come Alive:

```json
{"slug": "i-have-come-alive", "stages": ["separate", "align", "qa"]}
```

Поля:

| Поле | Смысл |
|---|---|
| `slug` | папка `content/songs/<slug>`. Если поля нет, берётся имя файла |
| `stages` | какие стадии запустить. По умолчанию `separate`, `align`, `qa` |
| `align` | дополнительные аргументы `align.py`, списком строк |
| `qa` | дополнительные аргументы `qa_sync.py`. `--apply` стадия `qa` добавляет сама |

Стадии, если их заказать: `decrypt`, `separate`, `sections`, `transcribe`, `diagnose`, `align`, `qa`. Для тайм-кодов достаточно трёх из примера: расшифровка записи подключается сама, когда стема ещё нет. Прогон с `align` или `qa` сам считает карту секций и черновик распознавания и кладёт их в `docs/analysis/<slug>/`. Сами тайм-коды эти две стадии не пишут.

Воркфлоу: `.github/workflows/pipeline.yml`. Он стартует от пуша `jobs/*.json` в любую ветку. Ручной запуск (`workflow_dispatch`) сработает, только когда этот файл воркфлоу есть в `main`; пока его там нет, запускайте файлом задания. Раннер коммитит результат в ту же ветку и удаляет файл задания. Удаление снова трогает `jobs/*.json`, поэтому следом приходит короткий пустой запуск: заданий уже нет, он сразу выходит.

Секрет `AUDIO_KEY` (64 шестнадцатеричных знака) обязателен. Без него воркфлоу падает на первом шаге.

Пока идёт прогон, в эту ветку лучше ничего не пушить: раннер делает `git pull --rebase` перед своим коммитом.

## Стадии

Рабочий каталог на раннере — `work/<slug>/`, его в репозиторий не кладут. Из него копируются отчёт проверки `docs/analysis/<slug>-qa.md`, карта секций `docs/analysis/<slug>/sections.suggested.json` и черновик распознавания `docs/analysis/<slug>/transcript.json`. Карта и распознавание появляются и тогда, когда в задании названы только `align` и `qa`: слабому агенту они нужны, а `work/` он не видит. Времена слов из этих двух файлов не берутся. Это разбор, не доказательство.

1. **Расшифровка.** `content/audio-enc/<slug>/high.m4a.enc` → `work/<slug>/source.m4a`.
2. **Стемы.** Demucs `htdemucs` без `--two-stems` → `work/<slug>/stems/{vocals,drums,bass,other}.wav`. Ударные, бас и остальное нужны следующей задаче (признаки звука для анимации); конвейер их считает и не смешивает обратно. Между запусками все четыре стема лежат в кэше Actions `work/stem-cache`: FLAC, зашифрованный тем же `AUDIO_KEY` (AES-256-GCM). Имя файла включает хэш записи и пометку четырёх стемов, поэтому новый исходник и старый кэш из одного только вокала не подхватываются. Повторный прогон той же записи отделение не пересчитывает. Веса моделей в репозиторий не кладутся.
3. **Выравнивание** (`align.py`). Известный текст строк ставится на вокальный стем. Пишет `s`/`e`, помечает каждую вокальную строку флагом `timing-draft` и оставляет `timing.status = draft`. Границы секций не двигает (для этого есть отдельный флаг `--move-sections`, конвейер его не передаёт).
4. **Проверка** (`qa_sync.py --apply`). Сверяет начало слова у выбранного выравнивателя **до притяжения** с атакой голоса и начало строки с репликой. Слово на гласную или связное без своей атаки может пройти вторым выравнивателем. Снимает `timing-draft` только у доказанных строк. Ставит `timing.status = aligned` только если в каждой группе, где она есть (соло и хор), доказано не меньше 80 % строк. Иначе оставляет `draft` и пишет долю и причины в `timing.notes`. Текст слов и времена `s`/`e` на этом шаге не меняются. Отчёт копируется в `docs/analysis/<slug>-qa.md`. Перед выравниванием воркфлоу собирает оценки всех песен задания и пишет порог в `docs/analysis/bench/calibration.json`. Если сбор не удался, выравнивание со старым порогом 0,30 не запускается.

Код выхода `qa_sync.py`: 0 — критерий пройден и нет проваленных строк соло и хора; 1 — проверка дошла до конца, но есть строки не в такт (воркфлоу всё равно коммитит результат); 2 — стадия упала, в отчёт пишется хвост лога.

`timing.status = verified` ни `align.py`, ни `qa_sync.py --apply` не перезаписывают. Это отметка после прослушивания владельцем: кнопка «Не совпадает» ничего не оставила, либо присланные отметки уже разобраны. Редактора тайм-кодов нет.

## Два выравнивателя

Первый — torchaudio MMS forced aligner (модель `MMS_FA`). Буквенные вероятности считаются по всему стему один раз (50 кадров в секунду, кусками по 30 с, кэш `work/<slug>/align-emission.npy`), затем текст ищется поиском Витерби. Арабское письмо и прочие нелатинские строки перед этим латинизируются (uroman). Огласовки при этом не снимаются: uroman переносит фатху, касру и дамму в гласные, шадду — в удвоение согласной, сукун отбрасывает. Без огласовок остались бы одни согласные, хотя буквы те же. Латиница нормализуется к a–z: апостроф выбрасывается, `ı` → `i`, `ß` → `ss`.

Второй — WhisperX, другие веса, не второй MMS. Пакет `ctc-forced-aligner` по умолчанию использует те же веса MMS_FA, а `facebook/mms-1b-all` — тот же семейный акустический контур, поэтому ни тот, ни другой не вызываются. Веса MMS (лицензия CC-BY-NC 4.0) качаются в кэш раннера и в репозиторий не коммитятся.

- WhisperX берётся там, где в его таблице уже есть модель: английский, немецкий, испанский, арабский, персидский, турецкий, а также французский, итальянский и остальные языки той же таблицы. Английский, немецкий, испанский, французский и итальянский — из torchaudio; арабский, персидский, турецкий и прочие — с Hugging Face. Это выравнивание известного текста, без распознавания и без диаризации.
- Азербайджанский, латынь, средневековый немецкий (`gmh`) и османский турецкий (`ota`) своего чекпоинта в этой таблице не имеют. Второго выравнивателя у них нет, и связное слово без атаки на этих языках не доказывается. Подмена современным немецким или турецким не делается. Если в данных язык записан как `de`, конвейер гоняет современную немецкую модель WhisperX. Слово, у которого атака уже есть, из-за отсутствия второй модели не бракуется.

Черновые `s`/`e` в `lyrics.json` окном поиска не служат. У трёх песен это уже время реплики официальных субтитров: `docs/analysis/<slug>/cues.json` (`line`, `cue`, `lang`, `start`, `end`; текста реплики в файле нет). Запись — звук того же видео, поэтому часы реплики совпадают с файлом. Реплику ставит человек, точность порядка 0,1–0,5 с.

Окно поиска строки — её реплика с запасом: 0,8 с до начала и 0,5 с после конца показа. На соседнюю реплику окно заходит не больше чем на 0,5 с, иначе текст ищется на чужой фразе. Карта секции — ограда, не окно: дальше 0,5 с за её край поиск не выходит. Внутри окна — один проход Витерби по словам этой строки. Между словами стоит повторяемая «звёздочка»: лишний столбец с логарифмом 0, не выученный токен модели. Пауза и долгий мелизм уходят в неё, буква садится на свой лучший кадр и не растягивается на следующую строку. Строка без реплики ищется по всей своей вокальной секции; если текст туда не влезает, проход повторяется с запасом 2 с. Конец слова дотягивается по активности голоса, не дальше 4 с и не дальше следующего слова. Один кадр буквы концом слова не считается.

Реплика — опора начала строки. Начало строки по выравнивателю (первое слово с буквами, до притяжения) пишется на сайт, только если строка поставлена: оценка не ниже порога калибровки, структурные проверки прошли и начало не дальше 0,3 с от реплики. Дальше на сайт идёт время реплики. Отдельного допуска 0,7 с больше нет: ровно 0,3 с ещё пишется, 0,31 с уже оставляет реплику. Время реплики само доказательством не становится.

Так вышло из замера на I Have Come Alive (`docs/analysis/i-have-come-alive/locate.md`). Старый поиск брал окно от конца предыдущей строки. На английском куплете, где текст почти наверняка верен, окно уезжало на 2–6 с позже фразы. Постановка в этом позднем окне расходилась с якорем общего прохода, и строка помечалась «текст не найден». При этом тот же текст, выровненный по всей секции или внутри фразы Whisper, садился на голос. Порог согласия с общим якорем выбрасывал верную постановку. Этот порог больше не ворота. Whisper со словными временами в замере подтвердил место фразы, но его начало в медиане на 0,70 с в стороне от кадра буквы, поэтому временем он не служит и вторым выравнивателем не считается. Когда у строки появилась официальная реплика, окном стала она, а не вся секция.

Второй выравниватель (WhisperX) запускается на строке группы соло или хор, если первый проход уверен. Окно — поставленная фраза плюс до 2 с, обрыв на соседней измеренной строке, не длиннее 12 с. Фраза, целиком вне секции, обратно в секцию не затаскивается. До ±1 с вокруг уже притянутых времён окно не сужается: иначе второй только пересказывает первого.

Турецкая модель WhisperX поставляется с языковой моделью; для выравнивания она не нужна, поэтому при отсутствии пакета `pyctcdecode` берётся обычный CTC-токенайзер того же чекпоинта.

## Особенности репертуара

- **Мелизмы.** Одна гласная тянется на 3–6 секунд — это нормально для мавваля и мугама. Выравниватель помечает буквы, а конец слова дотягивается по голосу, не оценкой.
- **Хор.** Строка, в `voice` которой есть «хор», choir, chorus или cappella, — отдельная группа, даже если рядом назван солист («Сами Юсуф и хор»). Допуск атаки у хора 0,2 с. Второй выравниватель в этот допуск не входит: его время пишется в отчёт. Доказанная хоровая строка получает пословную заливку. Дуэт (связка « и » без хоровой пометки), «все», ансамбль, оркестр и tutti не входят ни в соло, ни в хор: в стеме голоса смешаны, флаг `timing-draft` у них остаётся.
- **Повторы.** Каждое повторение — отдельная строка, иначе выравниватель перепрыгивает на следующее такое же место.

На одной строке работает только один второй выравниватель. Модели грузятся по одному языку и выгружаются. Строка, в которой первый выравниватель не уверен, вторым не гоняется. Латиница первого выравнивателя теряет апостроф (`I've` → `ive`). WhisperX апостроф оставляет, если он есть в словаре модели. Начало слова в обоих случаях — первая буква, поэтому апостроф сам по себе не сдвигает строку на секунду; расхождение начала всё равно видно в отчёте.

Строка поставлена (`good`), когда одновременно:

- оценка не ниже порога из `docs/analysis/bench/calibration.json`. Порог выбран по всем строкам с репликой трёх песен сразу, не по одной. Сравниваются средняя вероятность букв (она уже нормирована на длину), среднее по словам и минимум по словам. Берётся порог с максимумом строк, у которых |начало − реплика| ≤ 0,3 с, при доле принятых по оценке строк с |Δ| > 0,7 с не выше 2 % (ложных × 50 ≤ принятых; 1 из 50 проходит, 1 из 49 нет). При равенстве побеждает меньшее число ложных, затем более высокий порог, затем средняя по буквам. Разрыв с другой меткой в отбор не входит: он пишется в отчёт;
- структурные проверки, независимо от оценки: слова с буквами идут по порядку; нет съеденного слова (пропуск или два начала ближе 0,02 с); нет двух подряд промежутков между началами короче 0,06 с. Последнее слово на короткость не проверяется: звезда держит мелизм, а всплеск буквы — один кадр, и по длине всплеска почти каждая строка выглядела бы съеденной. Конец последней буквы не позже начала следующей реплики больше чем на 0,05 с;
- |начало − реплика| не больше 0,3 с. Строка без реплики не ставится.

Путь есть, но строка не поставлена — это `weak`: время реплики остаётся, между соседями строка не сдвигается. Пути нет — `draft`. Уверенная строка, которая ушла дальше реплики (у Karitas `shushtari-s2` расхождение 3,56 с), на сайте остаётся со временем реплики. Без файла калибровки код откатывается к средней по буквам 0,30: это запас для проверки, не порог пения, и воркфлоу с ним не выравнивает.

Таблица выбранного порога — `docs/analysis/bench/calibration.md`, и она же ниже. Список песен пишется с переводом строки в конце: без него `while read` не читает последнюю строку. Если в таблице нет песни из задания, выбор отменяется и выравнивание не запускается. Прогон `39069466435` так выпал (нет ONE, 180 строк). Полный прогон `39071285298` собрал все 243 строки с репликой трёх песен и выбрал ту же оценку: средняя по буквам, порог 0,412102. Принято 72, из них |Δ| ≤ 0,3 с — 63, между 0,3 и 0,7 с — 8, дальше 0,7 с — 1 (1,39 %, уложилось в 2 %). Структуру не прошли 12 из принятых. Поставлено 54. Среднее по словам даёт те же 63 близких и ту же одну ложную, но порог ниже (0,405), поэтому побеждает средняя по буквам. Минимум по словам ставит меньше. Немецкий в принятые не вошёл: ни одна строка не набрала 0,412. Старую оценку 0,30 порогом пения не ставить.

Сравнение подходов на эталоне реплики — `scripts/pipeline/bench_align.py`. Для каждого выравнивателя стенд пишет долю строк, чьё начало не дальше 0,3 с и 0,7 с от реплики, медиану и 90-й перцентиль модуля этой разницы по языкам и время на CPU. Отдельно тот же замер на вокале htdemucs, htdemucs_ft, MDX и Mel-RoFormer, на одном и том же отрезке начала записи: полная песня на этих моделях в лимит раннера не входит. Веса моделей в репозиторий не коммитятся. Числа прогона `39046364767` — `docs/analysis/bench/align.md`.

По этим числам первый выравниватель остаётся MMS-CTC со звёздочкой, стем — htdemucs, четыре дорожки. MMS кладёт начало в 0,3 с от реплики у 178 из 243 строк, медиана 0,186 с. stable-ts — 39 из 243, медиана 0,5 с. WhisperX на английском 14 из 16 против 13 из 16 у MMS (медианы 0,185 и 0,192 с): одной строки мало, чтобы делить конвейер по языкам. На немецком WhisperX слабее, 7 из 26, медиана 0,504 с. Персидский, турецкий и арабский стенд записал нулями: ленивый импорт `from transformers import Wav2Vec2ForCTC` после пакетов стенда (NeMo, audio-separator) отвечает `ModuleNotFoundError`, хотя класс в пакете есть. Это не имя чекпоинта и не свойство пения. Конвейер песни эти пакеты не ставит, и на прогоне песен те же три модели грузились. Импорт теперь при такой ошибке берёт класс из `transformers.models.wav2vec2.modeling_wav2vec2` и печатает версии torch и transformers. htdemucs_ft на первых 240 с I Have Come Alive даёт 35 из 38 против 34 из 38 у htdemucs при отделении 493 с против 124 с, поэтому стем не меняется.

Чекпоинты второго выравнивателя для трёх языков, веса в репозиторий не коммитятся:

- арабский — `jonatasgrosman/wav2vec2-large-xlsr-53-arabic`, Apache-2.0, дообучение XLSR-53 на Common Voice;
- персидский — `jonatasgrosman/wav2vec2-large-xlsr-53-persian`, Apache-2.0, Common Voice 6.1;
- турецкий — `mpoyraz/wav2vec2-xls-r-300m-cv7-turkish`, CC-BY-4.0, Common Voice 7. Это не серия jonatasgrosman; модель уже стоит в таблице WhisperX. Карточка требует указания автора. Сайт некоммерческий, замена не нужна, пока модель грузится.

Нули стенда, которые не являются оценкой качества и повторно не гонялись: huang-2025 падает на `np.Inf` в NumPy 2 и умеет только en/de/fr/es/it; NeMo не встал (`torchvision::nms`), и он только английский; MDX закончился кодом 1 у audio-separator; Mel-RoFormer — `StopIteration` через 741,7 с. Эти дыры не могут сменить связку для арабского, персидского, турецкого, азербайджанского и латыни, поэтому повторный прогон не запускался.

## Атака голоса

Начало измеренного слова притягивается к ближайшему пику атаки на вокальном стеме, если пик не дальше 0,10 с. Пик — локальный максимум кривой атаки (середина спектра, верх, фронт громкости) не ниже 0,5, где 1 — 95-й перцентиль этой записи; соседние пики ближе 40 мс схлопываются. Дальше 0,10 с начало не двигается.

Притяжение меняет только записанное `s`. После него расстояние от записанного начала до той же атаки равно нулю — это не измерение. Проверка и отчёт берут начало первого выравнивателя **до** притяжения и сравнивают его с ближайшей атакой, которая не принадлежит предыдущему слову. Атака предыдущего слова — это пик не позже его допритяжного начала плюс допуск группы: 0,10 с у соло и 0,20 с у хора. Притяжение само остаётся в пределах 0,10 с у всех. Хор, у которого атака дальше 0,10 с, но не дальше 0,20 с, доказан, а записанное начало на пик не сдвигается.

## Что считается доказанной строкой

Флаг `timing-draft` снимается только если одновременно:

- строка входит в группу. Соло — один ведущий голос; имя может быть пустым. Хор — в `voice` есть «хор», choir, chorus или cappella. Дуэт, «все», ансамбль, оркестр и tutti не входят ни туда, ни туда и флаг не теряют. У I Have Come Alive все 120 вокальных строк — соло, включая строки без имени;
- строка поставлена (`good`): порог калибровки, структурные проверки и |Δ| ≤ 0,3 с, и текст строки с момента прогона не менялся. Нет реплики — строка не поставлена и не доказана. Дальше 0,3 с — причина «расходится с субтитрами», если путь есть и структура прошла. На сайт в этом случае пишется время реплики;
- у каждого слова с буквами выполнен один из двух путей. Путь атаки: начало до притяжения не дальше 0,10 с от своей атаки у соло и 0,20 с у хора. Путь второго выравнивателя — только если слово на гласную или связное (легато: конец предыдущей буквы не дальше 0,20 с; мелизм: слово из одних гласных или всплеск длиннее 0,80 с), атаки ближе 0,3 с нет, и второй выравниватель ставит то же начало не дальше 0,10 с, в том числе у хора. Согласная без атаки этим путём не проходит. Нет второго начала — связное слово без атаки не доказано. Интерполяция между соседними словами доказательством не является. Атака ближе 0,3 с, но дальше допуска группы, закрывает оба пути;
- второй выравниватель на поставленных строках по-прежнему пишется в отчёт (сошёлся, разошёлся, поставил не все слова, времени нет). В отказ он входит только на пути без атаки.

Сдвиг строки целиком (порог 0,25 с) в отчёте остаётся тревогой, но в pass/fail не входит: он считается уже по записанным временам.

`timing.status = aligned` ставится, только когда **каждая группа, в которой есть строки**, доказана не меньше чем на 80 %. Пустая группа порог не блокирует. 30 из 38 (78,9 %) — ещё `draft`, 31 из 38 (81,6 %) — уже проходит свою группу. Строка «текст не найден в голосе» в числитель не входит и в знаменателе остаётся. Иначе статус `draft`, флаг стоит на недоказанных строках, доля и причины — в `timing.notes`. Медиана и 90-й перцентиль считаются отдельно по соло и по хору, только у доказанных строк и только до притяжения. В одну цифру пороги 0,10 с и 0,20 с не смешиваются.

Сайт включает пословную заливку, когда `timing.status` не `draft`, и выключает её у строки с флагом `timing-draft` (`src/scene/Scene.tsx`). Поэтому доказанные строки могут загораться по словам, пока соседние ещё показываются целиком. Это сознательный выбор: иначе одна непрошедшая строка гасила бы заливку у всех доказанных.

## Отчёт

`docs/analysis/<slug>-qa.md`:

- пройден ли критерий песни (не меньше 80 % в каждой группе, где она есть), сколько строк поставлено и сколько доказано, соло и хор отдельно, и сколько строк получили бы пословную заливку, если бы она включалась по строке. Сайт так не делает: заливка включается на всю песню, когда статус не `draft`;
- по языкам: строк, поставлено, доказано;
- распределение «начало слова → ближайшая атака» на поставленных строках, отдельно для согласных и для гласных или связных, и сколько слов доказано атакой, сколько вторым выравнивателем, сколько не доказано;
- медиана и 90-й перцентиль допритяжного расхождения начала слова с атакой, отдельно по соло (порог 0,1 с) и по хору (порог 0,2 с). Порог 0,25 с — это сдвиг строки целиком, он подписан отдельно;
- медиана |начало строки по выравнивателю − начало реплики|. Допуск постановки и записи времени на сайт — 0,3 с;
- почему остальные строки не доказаны;
- худшие места соло и хора: группа, id строки и время начала, чтобы их можно было прослушать;
- «Текст не найден в голосе» — только строки без реплики, у которых постановки нет или путь не прошёл структуру. Слова там, скорее всего, не те;
- «Выравниватель не справился» — строка с официальной репликой, у которой постановки нет или путь не прошёл структуру и с репликой не сошёлся. Слова с субтитром неверными не называются;
- таблица по строкам: группа (соло, хор или нет), сдвиг строки целиком, решение.

Подробности чтения отчёта — в [стадии 11](11-qa.md).

## Статусы

| `timing.status` | Когда |
|---|---|
| `draft` | время ещё оценка, либо в какой-то существующей группе доказано меньше 80 % строк. Доля и причины в `timing.notes` |
| `aligned` | в каждой группе, где есть строки, доказано не меньше 80 %. Недоказанные строки остаются с `timing-draft` |
| `verified` | владелец прослушал запись и принял время (кнопка «Не совпадает»). Скрипты его не перезаписывают |

Флаг `timing-draft` на строке: сайт показывает строку целиком, без пословной заливки. Снимает его только `qa_sync.py --apply`.

## Критерий готовности

- `npm run validate` не ругается на порядок слов и на слово, которое кончается позже записи больше чем на 0,5 с.
- Если `timing.status = aligned`, в каждой группе, где есть строки, доказано не меньше 80 % (у них нет флага `timing-draft`).
- В `docs/analysis/<slug>-qa.md` у доказанного соло 90-й перцентиль допритяжного расхождения с атакой ≤ 0,1 с, у доказанного хора ≤ 0,2 с, а непрошедшие строки перечислены с причиной.
