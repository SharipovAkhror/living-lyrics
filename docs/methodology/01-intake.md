# 1. Приём и опознание записи

**Параллельно.** Нет. Без карточки остальные стадии не начинают.

**Вход.** Ссылка на официальное видео или файл записи от владельца. Названия и исполнителя может не быть: тогда их даёт файл (теги, имя), описание ролика и официальная страница, не память.

**Команды.**

```bash
npm run new-song -- <slug> "Название" "Исполнитель"
npm run song-status -- <slug>
```

Оба аргумента в кавычках обязательны. Исполнителя по умолчанию нет: если имя не подтверждено, в кавычки поставьте то, что написано у файла, и вопрос в `review`. Скрипт создаёт `content/songs/<slug>/` из `docs/methodology/templates/`: `song.json`, `lyrics.json`, `sources.md`, `canon.md`.

Дальше после каждого сохранения снова `npm run song-status -- <slug>`. Одну напечатанную команду и выполняйте.

**Выход.** Папка песни. В `sources.md` есть рабочая ссылка или имя файла. В `song.json` нет языка-заглушки. На вопрос «какая это запись?» можно ответить одной строкой, и у каждого факта в `song.json` есть строка в `sources.md`.

**Машинная проверка.** `npm run song-status -- <slug>`: строка «приём» — «да». Пока в `sources.md` стоит комментарий «пустой шаблон» или нет ни адреса `https://`, ни строки `Файл: имя.m4a`, строка будет «нет». Текст «Файл: нет» источником не считается. Пока `languages` равен `["en"]` и в `review` остаётся пункт про заглушку, приём тоже «нет»: замените код на языки записи. У настоящей английской песни пункт про заглушку из `review` удаляют, когда `en` уже не заглушка, а спетый язык.

## Шаги

1. **Выберите slug.** Латиница, нижний регистр, дефисы: `i-have-come-alive`. Вторая версия той же песни — суффикс: `one-live-amsterdam`. Папка с таким именем не должна уже лежать в `content/songs/`.
2. **Запишите, откуда запись.** В `sources.md`, раздел «Запись», одно из двух, дословно:
   - адрес официального видео целиком, с `https://`;
   - `Файл: имя.m4a` — то имя, которое прислал владелец.
   Скачивание само на этом шаге не запускают. Когда приём закрыт, `song-status` печатает одну команду стадии 2. Чужой ролик с тем же названием сюда не пишите.
3. **Назовите запись одной строкой.** Исполнитель, название, студия или концерт (где и когда, если это написано), длительность до секунды. Откуда брать:
   - файл: имя, теги (`ffprobe -hide_banner file.m4a`, если `ffprobe` есть), длительность;
   - официальная страница релиза, описание официального видео, буклет, страница трека на площадке, где виден этот же хронометраж.
   Если длительность файла и длительность ролика расходятся больше чем на секунду, это разные версии. В `review` так и напишите. Тайм-коды от другой версии не подходят.
4. **Остальные источники.** Удалите строку «пустой шаблон». Всё, чего на странице и в описании ролика нет (имена музыкантов, лад, год), — в раздел «Не подтверждено», не в `song.json`. Титры из описания видео, если они там написаны, перепишите в `credits`: это ещё не вступления инструментов.
5. **Поправьте `song.json` только подтверждённым.**
   - `languages`: уберите `en`, если английский не поётся. Коды — ISO 639, список в `src/data/iso639.ts`, пояснение в `docs/data-format.md`. Примеры из наших песен: `fa`, `ar`, `az`, `tr`, `la`, `de`, `en`. Османский — `ota`, средневерхненемецкий — `gmh`. Неверный код валидатор называет по-русски.
   - `duration`: оставьте `1`, пока стадия 2 не измерит файл. Число с обложки или из памяти не пишите.
   - `audio.status`: оставьте `missing`, пока нет шифра или открытого `high.m4a`.
   - `palette`: цвета заготовки — заглушка, про неё уже есть пункт `review`. Замените их цветами обложки, когда обложка будет перед глазами. Три-четыре цвета в `field`. Контраст акцента — в [дизайн-системе](../design/design-system.md).
   - `poets`, `credits`, `featuring`, `release`, `performance`, `titleOriginal`: только если строка есть на странице, в буклете или в тегах файла. Иначе поле не заполняйте, вопрос оставьте в `review`.
6. **Канон на этом шаге не сочиняйте.** Файл `canon.md` пустой по шаблону. Как искать стихи — стадия 4. `song-status` сам перейдёт туда, если запись ещё нельзя обработать.
7. **Снова** `npm run song-status -- <slug>`.

## Пример опознания, уже сделанный в проекте

`content/songs/karitas/song.json`, поле `audio.provenance`: файл пришёл от владельца, хронометраж 977,05 с, ссылка на официальное видео записана в `ref`. Для новой песни та же ссылка в `sources.md` — вход стадии 2: `song-status` печатает команду на машине владельца. `provenance.kind` = `file`, когда файл уже измерен.

## Типичные ошибки

- Запустить `scripts/pipeline/fetch_audio.sh`. Он берёт лучшую звуковую дорожку, часто не 140, и отдельное видео. Команду даёт `song-status`.
- Оставить `languages: ["en"]` у персидской или арабской песни.
- Вписать музыкантов из другого концерта с тем же названием.
- Подобрать палитру «под настроение», не глядя на обложку.
- Считать приём закрытым, не удалив строку «пустой шаблон».
