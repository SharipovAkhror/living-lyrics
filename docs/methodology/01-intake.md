# 1. Приём и опознание записи

**Параллельно.** Нет. Без карточки остальные стадии не начинают.

**Вход.** Ссылка на официальное видео или файл записи от владельца. Названия и исполнителя может не быть: тогда их даёт файл (теги, имя), описание ролика и официальная страница, не память.

**Команды.**

```bash
npm run new-song -- <slug> "Название" "Исполнитель" <live|studio|single|other> "Подпись версии"
npm run song-status -- <slug>
```

Название, исполнитель и подпись версии — в кавычках. Вид версии — одно из четырёх слов: `live`, `studio`, `single`, `other`. Без подписи или с неверным видом скрипт папку не создаёт и печатает, чего не хватает. Исполнителя по умолчанию нет: если имя не подтверждено, в кавычки поставьте то, что написано у файла, и вопрос в `review`. Скрипт создаёт `content/songs/<slug>/` из `docs/methodology/templates/`: `song.json`, `lyrics.json`, `sources.md`, `canon.md`. В `song.json` сразу лежит `version`.

Дальше после каждого сохранения снова `npm run song-status -- <slug>`. Одну напечатанную команду и выполняйте.

**Выход.** Папка песни. В `sources.md` есть рабочая ссылка или имя файла. В `song.json` нет языка-заглушки. На вопрос «какая это запись?» отвечает `version.label`, и у каждого факта в `song.json` есть строка в `sources.md`.

**Машинная проверка.** `npm run song-status -- <slug>`: строка «приём» — «да», строка «версия» печатает вид и подпись. Пока в `sources.md` стоит комментарий «пустой шаблон» или нет ни адреса `https://`, ни строки `Файл: имя.m4a`, строка «приём» будет «нет». Текст «Файл: нет» источником не считается. Пока `languages` равен `["en"]` и в `review` остаётся пункт про заглушку, приём тоже «нет»: замените код на языки записи. У настоящей английской песни пункт про заглушку из `review` удаляют, когда `en` уже не заглушка, а спетый язык. Песня без `version` не проходит `npm run validate`. `song-status` в этом случае таблицу не печатает, а просит починить `song.json`.

## Шаги

1. **Выберите slug.** Латиница, нижний регистр, дефисы: `i-have-come-alive`. Папка с таким именем не должна уже лежать в `content/songs/`. Если та же песня уже есть в другой версии, slug новый, с суффиксом версии: `karitas-amsterdam-2022`. Старую папку не переименовывают.

   **Какую версию брать.** Ту, что звучит в официальном видео, которое прислал владелец. Название может совпадать у концерта, студии и другого года. Берётся только этот ролик. Другой концерт, студийный сингл и выпуск другого года — отдельные песни со своим slug, даже если название одно.

   `version.kind`:
   - `live` — живой концерт или сборка концерта;
   - `studio` — студийный альбом;
   - `single` — отдельный сингл, и по видео не видно, что это концерт;
   - `other` — страница не даёт выбрать одно из трёх. Вопрос остаётся в `review`, подпись — только из того, что на странице написано.

   `version.label` — короткая строка по-русски под названием. В неё попадает только то, что написано у этого видео, на его официальной странице или в буклете.
   - концерт: `Концерт <название>, <город> <год>`. Название — имя концерта. Если страница отдельно называет фестиваль и программу, в подпись берётся программа. Год — год вечера, не год альбома, который вышел позже. Город по-русски, если источник так пишет;
   - студия: `Студийная, <альбом> <год>`;
   - сингл: название релиза и год, как они написаны. Формулу концерта не подставлять;
   - `other`: одна короткая строка из фактов страницы.

   Если город в источнике только латиницей и русского написания в карточке ещё нет, оставьте написание источника и вопрос в `review`. Не переводите город по памяти.

   Уже лежащие песни, для сверки формулы. Karitas и ONE: `Концерт When Paths Meet, Амстердам 2022`. Концерт When Paths Meet на Holland Festival, Het Concertgebouw, Амстердам, 6 июня 2022; альбом When Paths Meet вышел в 2023. I Have Come Alive: `Концерт Beyond the Stars, Дубай 2021`. Вечера Beyond the Stars, Al Wasl Plaza, октябрь 2021; в источнике город записан как Dubai, в подписи этой песни принято «Дубай» — обратно на Dubai не переписывать. Альбом Beyond the Stars (Live) — 2022, это не год вечера.

2. **Запишите, откуда запись.** В `sources.md`, раздел «Запись», одно из двух, дословно:
   - адрес официального видео целиком, с `https://`;
   - `Файл: имя.m4a` — то имя, которое прислал владелец.
   Скачивание само на этом шаге не запускают. Когда приём закрыт, `song-status` печатает одну команду стадии 2. Чужой ролик с тем же названием сюда не пишите.
3. **Назовите запись одной строкой.** Это `version.label` плюс длительность до секунды. Откуда брать:
   - файл: имя, теги (`ffprobe -hide_banner file.m4a`, если `ffprobe` есть), длительность;
   - официальная страница релиза, описание официального видео, буклет, страница трека на площадке, где виден этот же хронометраж.
   Если длительность файла и длительность ролика расходятся больше чем на секунду, это разные версии. В `review` так и напишите. Тайм-коды от другой версии не подходят.
4. **Остальные источники.** Удалите строку «пустой шаблон». Всё, чего на странице и в описании ролика нет (имена музыкантов, лад, год), — в раздел «Не подтверждено», не в `song.json`. Титры из описания видео, если они там написаны, перепишите в `credits`: это ещё не вступления инструментов.
5. **Поправьте `song.json` только подтверждённым.**
   - `languages`: уберите `en`, если английский не поётся. Коды — ISO 639, список в `src/data/iso639.ts`, пояснение в `docs/data-format.md`. Примеры из наших песен: `fa`, `ar`, `az`, `tr`, `la`, `de`, `en`. Османский — `ota`, средневерхненемецкий — `gmh`. Неверный код валидатор называет по-русски.
   - `duration`: оставьте `1`, пока стадия 2 не измерит файл. Число с обложки или из памяти не пишите.
   - `audio.status`: оставьте `missing`, пока нет шифра или открытого `high.m4a`.
   - `palette`: цвета заготовки — заглушка, про неё уже есть пункт `review`. Замените их цветами обложки, когда обложка будет перед глазами. Три-четыре цвета в `field`. Контраст акцента — в [дизайн-системе](../design/design-system.md).
   - `version`: подпись, которую вы передали в `new-song`. Сверьте её со страницей видео. Если название концерта, город или год другие — поправьте `label` и `kind`. Поле не удаляйте: без него проверка не проходит.
   - `poets`, `credits`, `featuring`, `release`, `performance`, `titleOriginal`: только если строка есть на странице, в буклете или в тегах файла. Иначе поле не заполняйте, вопрос оставьте в `review`. `release` и `performance` — факты, из которых собрана подпись, а не замена ей.
6. **Канон на этом шаге не сочиняйте.** Файл `canon.md` пустой по шаблону. Как искать стихи — стадия 4. `song-status` сам перейдёт туда, если запись ещё нельзя обработать.
7. **Снова** `npm run song-status -- <slug>`.

## Пример опознания, уже сделанный в проекте

`content/songs/karitas/song.json`, поле `audio.provenance`: файл пришёл от владельца, хронометраж 977,05 с, ссылка на официальное видео записана в `ref`. Для новой песни та же ссылка в `sources.md` — вход стадии 2: `song-status` печатает команду на машине владельца. `provenance.kind` = `file`, когда файл уже измерен.

## Типичные ошибки

- Запустить `scripts/pipeline/fetch_audio.sh`. Он берёт лучшую звуковую дорожку, часто не 140, и отдельное видео. Команду даёт `song-status`.
- Оставить `languages: ["en"]` у персидской или арабской песни.
- Вписать музыкантов из другого концерта с тем же названием.
- Взять в `version` другой концерт, студийный сингл или год, чем в официальном видео владельца.
- Оставить песню без `version` или придумать город и год, которых нет у этого видео.
- Подобрать палитру «под настроение», не глядя на обложку.
- Считать приём закрытым, не удалив строку «пустой шаблон».
