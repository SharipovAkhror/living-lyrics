## Как работать

- **Записи** приносит владелец файлом в чат (скачивает своим Telegram-ботом; облако с YouTube не качает). Записи в репозитории только зашифрованы: `content/audio-enc/<slug>/high.m4a.enc` (AES-256-GCM, ключ `AUDIO_KEY`). Ключ есть в Vercel (скрытый) и в секретах GitHub Actions; владельцу ключ отправлен файлом. Для локального `npm run dev` со звуком положите его в `.env.local` строкой `AUDIO_KEY=…`.
- **Тяжёлые шаги** (отделение голоса, выравнивание, признаки звука) — в GitHub Actions: проверено, что раннер расшифровывает записи (`.github/workflows/audio-check.yml`, `docs/analysis/actions-check.md`). Рабочий конвейер `pipeline.yml` — в ветке `wip/sync-tools` (T1). Статус запусков: `https://api.github.com/repos/SharipovAkhror/living-lyrics/actions/runs`.
- **Сеть облачной среды Claude Code** закрыта для большинства сайтов (WebSearch работает; GitHub и PyPI доступны). Страницы читать через Vercel Sandbox (`scripts/pipeline/sandbox/fetch_text.py`). На десктопе этих ограничений нет.
- `.claude/settings.json` разрешает рутинные команды без подтверждений.
- **Исполнители.** Задачи с кодом выполняет Grok; задачи «посмотреть видео» — Gemini 3.8 Flash через Antigravity владельца (`agy -p …`, по подписке, без ключей; его `view_file` читает локальный видеофайл целиком, ссылку YouTube не открывает). Оркестрирует обоих Claude Code: Грок и Gemini друг другом не управляют. Задачи из `docs/BACKLOG.md` выполняет Grok через плагин Grok Build (модель grok-4.7, усилие high): каждая — в своём worktree `../living-lyrics-wt/<имя>`, ветка `grok/<имя>`, без правок STATUS и BACKLOG. Claude Code проверяет (дифф, validate, typecheck, сборка, выборочная сверка с источниками), вливает в `main` и пушит; владелец разрешил пушить после проверки без отдельного вопроса. Каждая задача Grok сохраняется сессией в `~/.grok/sessions` (по папке задачи): `grok sessions list` и `grok -r` в папке worktree открывают её чат. Мост плагина иногда считает задачу «идущей» после её конца (процесс grok не выходит) — верить журналу Grok.

## Что есть

- **Сцена — поток строк** (`src/scene/flow.ts`, `Scene.tsx`, `LineBlock.tsx`, `InstBlock.tsx`): текущая строка на матовой подложке в верхней трети, следующие видны заранее, повторы — отдельные строки с пометкой, смена голоса подписана. Тап по строке — играть с неё.
- **Пословная заливка выключена, пока тайминг не доказан** (`timing.status = draft` или флаг `timing-draft`): строка загорается целиком, отсчётов «через…» нет. Слова рисуются одним слоем; бледность — прозрачностью слова (нет двоения на соединениях букв).
- **Плеер**: дорожка с отмеченными проигрышами, ⏮ ▶︎ ⏭ (тап — строка, удержание — перемотка), подписанные «Перевод», «Пояснение», «Весь текст», «Настройки»; «О песне» — кто поёт и играет; одна шторка настроек.
- **Инструменты**: 25 гравюр (`scripts/art/`), 3D даф и уд (вид «реалистичный»), галерея `/instruments`. В проигрыше инструменты вступают по очереди (`src/scene/cast.ts`; на телефоне — по одному крупно) и двигаются от `public/audio/<slug>/features.json`. Контракт для перерисовки и анимации от звука — `docs/instruments/animation-contract.md`, `src/instruments/animation.ts`.
- **Тексты**: правило «от оригинала» (`docs/methodology/04-text.md`, валидатор сверяет строки с `canon.md`). Эталоны всех трёх песен готовы и сверены по буквам с изданиями (2026-10-17): `content/songs/<slug>/canon.md` — оригиналы с источниками, «Последовательность в записи» (каждый повтор — позиция), «Расхождения и вопросы» (что закрывает только слух). `lyrics.json` пересобраны по эталонам (T2 сделана); время слов черновое до T1. Субтитры видео (VTT) с YouTube в этот проход скачать не удалось — времена реплик Karitas взяты из прежней находки; кадры титров (`lyric_frames.py`) по видеофайлу владельца закрыли бы часть вопросов. Карта голоса и транскрипты — `docs/analysis/<slug>.md`.
- **Тайминги всех трёх песен — черновые**: строки — по официальным субтитрам, пословная заливка выключена до 80 % доказанных строк (T1).

## Решения

- Синхронизацию делают скрипты (выравнивание известного текста по голосу), ИИ — только текст, порядок строк и повторы, перевод, пояснения, проверка отчётов.
- Telegram-бот-приёмная сделан и убран по решению владельца.
- Редактор тайм-кодов и ручной режим удалены.
- Палитры — из кадров официальных видео.
- Дизайн: свой, не копия Apple Music (T5).
- Пояснения: в интерфейсе «Пояснение», в данных поле `comment` (было `sharh`, T9).
- Кнопка «Не совпадает» (T8) есть: владелец отмечает места на слух (кнопка или M), в «О песне» — список и «Скопировать» для агента.
- Репозиторий остаётся публичным — решение владельца (2026-10-17), риск с правами на современные тексты (`docs/research/product.md`) ему известен. Записи по-прежнему только зашифрованы.
- Ненужное (ветки, скрипты, временные файлы) чистить сразу, даже если не мешает — пожелание владельца.
- Кто делает каждый шаг новой песни и откуда она приходит (владелец даёт ссылку на официальное видео в чате Claude Code) — `docs/methodology/new-song-route.md`. Готовность к новым песням ~58 % (Dashboard): не хватает стандарта перевода (T17), встраивания новых способов в маршрут и репетиции (T20).
- Добавление песни — один маршрут `docs/methodology/README.md`; после каждого шага `npm run song-status -- <slug>` печатает следующую команду (T11).
- Сервисов не прибавлять: уже есть Claude Code (главный), GitHub (код и Actions), Vercel (сайт и всё серверное), Grok Build и Antigravity (исполнители по подпискам). Новое — только если ничего из этого не умеет; новый провайдер-исполнитель (например Codex) допустим — решение владельца (2026-10-18).
- Исполнители называются по ветке: `grok/t<N>-<кодовое слово>` → «Grok · <Слово>» (Grok · Sync, Grok · Sources, Grok · Parts); Gemini, смотрящий видео, — «Gemini · Watch»; Claude Code — «Claude · Lead». Так их видно в Dashboard.
- Расход агентов ведётся в `ops/usage/` (сборщик `collect.py`, журнал `ledger/`, сводка `latest.json`): Grok — токены по сессиям (лимит xAI не сообщает), Gemini — остаток окон Antigravity из `/usage`.
- Видео концертов смотрит Gemini через Antigravity по заданию `scripts/instrument_id/prompts/watch-video.md` (порядок — `scripts/instrument_id/prompts/README.md`).
- Пословная заливка включается только для всей песни, когда доказано 80 % строк в каждой группе; построчно на доказанных строках её не включать — решение владельца (2026-10-18).

## Открытые вопросы владельцу

- Видео концертов трёх песен (360p достаточно): нужны «глазам» — Gemini Flash через Antigravity смотрит файл целиком. Как получить файлы: владелец присылает ботом, как записи, или Claude скачивает их на машине владельца открытой программой yt-dlp — ждёт «да» владельца. Сторонние сервисы и ключи не использовать (решение владельца 2026-10-18).

- Веса выравнивателя MMS — лицензия CC-BY-NC 4.0 (некоммерческая). Пока сайт некоммерческий — используем; при платном доступе — пересмотреть (`docs/research/technology.md`, раздел 1). То же для головы распознавателя инструментов, если она обучена на IRMAS (CC BY-NC-SA 4.0, T7b).
