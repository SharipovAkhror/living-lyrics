## Как работать

- **Записи** приносит владелец файлом в чат (скачивает своим Telegram-ботом; облако с YouTube не качает). Записи в репозитории только зашифрованы: `content/audio-enc/<slug>/high.m4a.enc` (AES-256-GCM, ключ `AUDIO_KEY`). Ключ есть в Vercel (скрытый) и в секретах GitHub Actions; владельцу ключ отправлен файлом. Для локального `npm run dev` со звуком положите его в `.env.local` строкой `AUDIO_KEY=…`.
- **Тяжёлые шаги** (отделение голоса, выравнивание, признаки звука) — в GitHub Actions: проверено, что раннер расшифровывает записи (`.github/workflows/audio-check.yml`, `docs/analysis/actions-check.md`). Конвейер — `.github/workflows/pipeline.yml` в `main`; те же шаги локально — `scripts/pipeline/*.py`. Статус запусков: `https://api.github.com/repos/SharipovAkhror/living-lyrics/actions/runs`.
- **Сеть облачной среды Claude Code** закрыта для большинства сайтов (WebSearch работает; GitHub и PyPI доступны). Страницы читать через Vercel Sandbox (`scripts/pipeline/sandbox/fetch_text.py`). На десктопе этих ограничений нет.
- `.claude/settings.json` разрешает рутинные команды без подтверждений.
- **Исполнители.** Задачи с кодом выполняет Grok; задачи «посмотреть видео» — Gemini 3.8 Flash через Antigravity владельца (`agy -p …`, по подписке, без ключей; его `view_file` читает локальный видеофайл целиком, ссылку YouTube не открывает). Оркестрирует обоих Claude Code: Грок и Gemini друг другом не управляют. Задачи из `docs/BACKLOG.md` выполняет Grok через плагин Grok Build (модель grok-4.7, усилие high): каждая — в своём worktree `../living-lyrics-wt/<имя>`, ветка `grok/<имя>`, без правок STATUS и BACKLOG. Claude Code проверяет (дифф, validate, typecheck, сборка, выборочная сверка с источниками), вливает в `main` и пушит; владелец разрешил пушить после проверки без отдельного вопроса. Каждая задача Grok сохраняется сессией в `~/.grok/sessions` (по папке задачи): `grok sessions list` и `grok -r` в папке worktree открывают её чат. Мост плагина иногда считает задачу «идущей» после её конца (процесс grok не выходит) — верить журналу Grok.

## Что есть

- **Сцена — поток строк** (`src/scene/flow.ts`, `Scene.tsx`, `LineBlock.tsx`, `InstBlock.tsx`): текущая строка на матовой подложке в верхней трети, следующие видны заранее, повторы — отдельные строки с пометкой, смена голоса подписана. Тап по строке — играть с неё.
- **Пословная заливка выключена, пока тайминг не доказан** (`timing.status = draft` или флаг `timing-draft`): строка загорается целиком, отсчётов «через…» нет. Слова рисуются одним слоем; бледность — прозрачностью слова (нет двоения на соединениях букв).
- **Плеер**: дорожка с отмеченными проигрышами, ⏮ ▶︎ ⏭ (тап — строка, удержание — перемотка), подписанные «Перевод», «Пояснение», «Весь текст», «Настройки»; «О песне» — кто поёт и играет; одна шторка настроек.
- **Инструменты**: 25 гравюр (`scripts/art/`), 3D даф и уд (вид «реалистичный»), галерея `/instruments`. В проигрыше инструменты вступают по очереди (`src/scene/cast.ts`; на телефоне — по одному крупно) и двигаются от `public/audio/<slug>/features.json`. Контракт для перерисовки и анимации от звука — `docs/instruments/animation-contract.md`, `src/instruments/animation.ts`.
- **Тексты**: правило «от оригинала» (`docs/methodology/04-text.md`, валидатор сверяет строки с `canon.md`). Эталоны всех трёх песен готовы и сверены по буквам с изданиями (2026-10-17): `content/songs/<slug>/canon.md` — оригиналы с источниками, «Последовательность в записи» (каждый повтор — позиция), «Расхождения и вопросы» (что закрывает только слух). `lyrics.json` пересобраны по эталонам (T2 сделана); время слов черновое до T1. Субтитры видео (VTT) с YouTube в этот проход скачать не удалось — времена реплик Karitas взяты из прежней находки; кадры титров (`lyric_frames.py`) по видеофайлу владельца закрыли бы часть вопросов. Карта голоса и транскрипты — `docs/analysis/<slug>.md`.
- **Тайминги всех трёх песен — черновые**: строки — по официальным субтитрам, пословная заливка выключена до 90 % доказанных строк в каждой группе (T1; цель — 100 %).

## Решения

- Устройство чатов (решения владельца, подтверждены им кнопками 2026-10-20). Главный чат делится на два: **LL · Main** (оркестратор) — единственный чат, с которым говорит владелец (решения, задачи, приёмка по отчётам, доска, `docs/STATUS.md`), и **LL · Site** — исполнитель по сайту и песням (ставит задачи Grok и Gemini, проверяет, вливает). LL · Tech и LL · Business отчитываются LL · Main. Внутренние сообщения и задания между чатами и исполнителями — коротко и по-английски; владельцу и в документах для него (STATUS, доска) — по-русски. Технические и процессные дела (ротация, хосты, настройки, устройства) оркестратор целиком отдаёт LL · Tech. История чатов хранится вечно: на Станции `cleanupPeriodDays` 36500 для всех проектов; на любом новом устройстве эти настройки должны ставиться сами после входа (делает LL · Tech). LL · Business не ротируется, а переподключается тем же разговором под демон Claude; старые главный чат и Tech уходят в архив, не удаляются.
- Права и пароль (LL · Business, `docs/business/`). **Решения владельца, подтверждены им кнопками 2026-10-20:** пароль на сайте остаётся; зикр из хадры (запись не владельца, кто записал — не выяснено) — только для близкого круга, без монетизации, запись в репозиторий не класть, пока не известно, кто её сделал. **Не решено:** направление развития (старые стихи в переводах владельца он отклонил, свои песни не подходят — он не пишет и не поёт); правило «новые современные тексты не добавлять» остаётся рекомендацией бизнес-чата, владелец его не выбрал. Разрешений правообладателей на три песни Sami Yusuf нет; они остаются под паролем без изменений.
- Монетизация (LL · Business, `docs/business/monetization.md`). **Выбор владельца кнопками 2026-10-21:** цель дохода — окупить подписки и немного сверху; перевод и пояснения делают агенты, владелец проверяет. Продавать можно только своё и свободное (перевод и пояснения, услуга для артистов по договору, живые занятия, принты гравюр); чужие тексты, записи, шрифт мусхафа, обложки, MMS и зикр — нельзя (вывод бизнес-чата). **Открыто:** платные материалы вне публичного репозитория («не знаю»), первые покупатели, бюджет на юриста, платёжный сервис (новый сервис — решает владелец). **2026-10-21, кнопкой:** гравюры к продаже не готовы; сейчас продавать нечего — монетизация ждёт готового продукта (синхронизация ≥ 90 %, стабильный iPhone). **Правило владельца (2026-10-21):** никакого нейро-слопа — продаётся только то, что владелец проверил и принял по каждому куску; ИИ — инструмент, а не готовый продукт.
- Машины и переезд (решения владельца 2026-10-19 и 2026-10-20, обсуждены в LL · Tech): машины называются Станция (домашний ПК), Ноутбук, Облако, Телефон (`ops/README.md`, «Машины»). Пока всё работает через Станцию; цель — со временем не зависеть от ПК. Облако Anthropic (claude.ai/code) постоянным домом не годится: контейнер временный, Grok и Gemini там не хранят вход по подписке; свои серверы для облачных сессий — только планы Team и Enterprise. Выбранный путь — постоянный сервер Oracle Cloud Always Free («Облачная станция»: Grok через `grok login --device-auth`, Gemini через вход по ссылке и коду, Claude через Remote Control). Регистрация в Oracle не прошла: нужна кредитная, а не дебетовая карта; владелец ждёт кредитную карту, затем одна попытка регистрации. До этого ничего не переносим: ни платного сервера, ни Codespaces. Автозапуск remote-control на Станции отклонён; новые части, привязанные к ПК, не добавлять. Оркестрация как есть: Claude Code ведёт, Grok и Gemini — исполнители в своих оболочках; модель внутри Claude Code не подменять (без ANTHROPIC_BASE_URL). Главную сессию не перезапускать, пока через её фоновый хост идёт связь с Ноутбука.

## Независимость

Репозиторий самодостаточен: правила (`AGENTS.md`), состояние (этот файл), задачи (`docs/BACKLOG.md`, полные задания — `docs/tasks/`), ход работы (`ops/board.json`) и методика (`docs/methodology/`) лежат в нём. Работу продолжит любой агент любого провайдера или человек — без пересказа и без чьих-то заметок вне репозитория. Требование владельца (2026-10-18): проект не зависит ни от одного агента и ни от одной корпорации.

Чем заменить каждый внешний сервис:
- **ИИ-исполнители** (Claude Code, Grok Build, Antigravity): любой агент, который умеет git и правку файлов, по `AGENTS.md` и `docs/tasks/`. Тексты, перевод и время слов проверяются скриптами и источниками, а не доверием к модели.
- **GitHub Actions** (тяжёлые шаги): те же скрипты локально — `scripts/pipeline/*.py` (Python, ffmpeg); модели Demucs, Whisper, MMS — открытые.
- **GitHub** (хранилище): любой git-хостинг, `git push` в другой адрес; история целиком в каждой копии.
- **Vercel** (сайт): сборка `npm run build` — статические файлы `dist/`, их отдаст любой хостинг. От Vercel зависит только пароль на сайт (`middleware.ts`): на другом хостинге его заменит базовая авторизация сервера.
- **Записи**: шифр AES-256-GCM, ключ `AUDIO_KEY` хранится у владельца; расшифровка — `scripts/tools/audio-crypt.mjs` или `scripts/pipeline/decrypt_audio.py`.
