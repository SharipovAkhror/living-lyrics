# Задача: библиотека инструментов в 3D с управлением

Задание для исполнителя (агент любого провайдера или человек). Оркестратор (Claude Code) выдаёт эту задачу частями и принимает результат по чек-листу в конце. Токены и время не экономить: важнее качество и точность.

## Зачем

В инструментальных частях песен сайт показывает, какие инструменты играют. Сейчас это плоские гравюры (`src/instruments/svg/*.svg`, генератор `scripts/art/`), которые почти не двигаются. Нужно: **все инструменты полностью перерисовать качественно в 3D, добавить новые, и сделать их управляемыми** — чтобы сцена могла заставить струну дрожать, мембрану вздрагивать, смычок ходить, клавиши нажиматься, кольца звенеть — в такт музыке. Библиотека должна подходить к большей части живой музыки (оркестр, камерная, народная, духовная), не только к песням Сами Юсуфа.

Прочитайте сначала: `AGENTS.md`, `docs/STATUS.md`, `docs/instruments/animation-contract.md`, `src/instruments/animation.ts`, `src/instruments/list.ts`, `src/scene/InstrumentStage.tsx`, `src/instruments/layout.ts`, `docs/design/design-system.md`, страницу `/instruments` (`src/pages/InstrumentsPage.tsx`).

## Принятые решения (пилот T6)

Исследование T3 (`docs/research/technology.md`, разделы 3 и 6) эти выборы закрыло. Семейства после пилота идут по ним и конвейер заново не строят.

- Модели собирает Node: `scripts/art3d/<key>.mjs` и общий `scripts/art3d/lib.mjs`. Команда: `npm run art3d -- <key>` (без ключа — все, кто уже подключён в `build.mjs`). Blender не используем: его нет на машине сборки, а `bpy` — GPL.
- Результат: `public/instruments/3d/<key>.glb` и `<key>.json`, плюс `index.json` со списком ключей. Сжатие — meshopt. Декодер в приложении ленивый.
- Контур гравюры — оболочка в своём шейдере (проход глубины и inverted hull), не OutlinePass: тот читает `performance.now()` и ломает перемотку. Штриховка считается в шейдере от освещения и красится цветом песни.
- Имена узлов и морфов — таблица в разделе 2 (`vibrate`, `hit`, `part-jingles`, клип `idle`). Контракт `docs/instruments/animation-contract.md` с ней совпадает.
- Время кадра — аргумент `update(drive, time)` в секундах воспроизведения. На сцене один холст; в карточке галереи — свой, потому что карточка отдельный элемент.

## Что сделать

### 1. Модели — из кода, воспроизводимо

- Каждый инструмент — **скрипт процедурного моделирования** в Node (`scripts/art3d/<key>.mjs`, см. «Принятые решения»), результат — `public/instruments/3d/<key>.glb`. Модель можно поправить правкой скрипта и пересобрать; ничего не лепится вручную без исходника. Blender Python не используем.
- Допустимо взять готовую модель, только если её лицензия CC0 или CC-BY (с указанием автора в `docs/instruments/credits.md`) и она доводится до тех же требований. Модели с неясной лицензией — нет.
- **Органологическая точность прежде всего**: пропорции, число струн и хоров, колков, ладов, отверстий, форма корпуса, материалы — по справочникам (музейные каталоги, энциклопедии инструментов). Ссылки на использованные справки — в шапке скрипта.
- Бюджет для телефона: до ~30–60 тыс. треугольников на инструмент, текстуры не больше 1024 px (или без текстур — процедурные материалы), GLB ≤ 1,5 МБ после сжатия (Draco или meshopt).

### 2. Управляемые части (именование — контракт)

Узлы и морф-таргеты называются так, чтобы сцена находила их без знания конкретного инструмента:

| Часть | Имя узла / морфа | Чем управляется (`InstrumentDrive`) |
|---|---|---|
| струны | `part-string-<n>` (n = 1…, от низкой) с морфом `vibrate` | `sustain`, `pulse` |
| мембрана | `part-skin` с морфом `hit` | `pulse` |
| кольца, тарелочки | `part-jingles` (вращение/смещение) | `pulse` |
| смычок | `part-bow` (путь движения — анимационный клип `bow`) | `sustain` |
| клавиши, молоточки | `part-key-<n>`, `part-hammer-<n>` | `pulse` |
| отверстия, воздух | `part-breath` (точка эмиттера частиц) | `breath` |
| весь инструмент | корень `instrument` | `energy`, `beat` (покачивание) |

Плюс в каждом GLB: анимационный клип `idle` (спокойное «дыхание», можно пустой), ориентация — инструмент смотрит в камеру, центр в начале координат, высота нормирована к 1 (масштаб задаёт сцена).

Рядом — манифест `public/instruments/3d/<key>.json`: какие части есть, рекомендуемые ракурсы камеры (`hero`, `close`), подсказки цвета материалов, автор/лицензия.

### 3. Рендер в приложении

- Адаптер `src/instruments/render/three.ts`, реализующий `InstrumentRenderer` из `src/instruments/animation.ts` (`mount`, `update(drive)`, `dispose`). three.js подключается лениво (только когда на экране инструмент), одна общая WebGL-сцена на `InstrumentStage`, а не по канвасу на инструмент.
- **Стиль**: по умолчанию — «гравюра» (линии контура и штриховка шейдером: outline + hatching по освещению) в цвете песни, чтобы продолжать визуальный язык сайта; второй стиль — «материалы» (дерево, кожа, металл, мягкий свет). Переключатель — в настройках сайта.
- Время — функция воспроизведения: одинаковый кадр при перемотке (никаких накапливаемых симуляций; вибрация струн — синус от времени и громкости, а не физика с состоянием).
- Фолбэк: если WebGL недоступен, «Уменьшение движения» или слабое устройство — показывать текущие SVG.
- iPhone Safari: 60 кадров/с на iPhone 12 и новее при 3 инструментах на экране; не греть телефон (рендер только когда инструмент видим).

### 4. Список инструментов

Сначала перерисовать все 25 из `src/instruments/list.ts`, затем добавить (каждый — с записью в `list.ts`: русское и родное название, семейство, происхождение, одно спокойное фактическое предложение):

- **Оркестр**: альт, флейта, гобой, кларнет, фагот, валторна, труба, тромбон, туба, литавры, малый барабан, тарелки, челеста/колокольчики, орган.
- **Ближний Восток, Центральная Азия, Кавказ**: сетар, кеманче турецкая (кеменче), кавал, саз, дутар, рубаб, дойра, нагара, тар азербайджанский (11 струн) отдельно от персидского.
- **Другие традиции, часто встречающиеся в мировой музыке**: ситар, табла, пипа, гучжэн, кото, сякухати, кора, мандолина, классическая гитара, укулеле.
- **Голоса**: людей нет. Гравюра — соловей на ветке розы и стая «Беседы птиц»; объём, если будет, фигур не возвращает.

Порядок по семействам: щипковые → смычковые → духовые → ударные → клавишные → голоса. Каждое семейство — отдельная подзадача.

### 5. Страница-галерея

`/instruments`: у каждого инструмента — 3D-вид с вращением пальцем/мышью, ползунки входов (`pulse`, `sustain`, `breath`, `energy`, `beat`) и кнопка «сыграть пример» (синтетический сигнал), чтобы проверить анимацию без песни.

## Как сдавать (чек-лист приёмки для оркестратора)

Каждая подзадача (семейство) сдаётся коммитом в отдельной ветке `art3d/<семейство>` с:

1. Скрипты моделей и собранные GLB + манифесты; `npm run validate && npm run typecheck && npm run build` проходят.
2. Скриншоты каждого инструмента в двух стилях, светлая и тёмная тема, iPhone и десктоп (`npm run shots`), — в описании коммита или `work/` с отчётом.
3. Таблица в отчёте: инструмент → треугольники, вес GLB, части и морфы, источники для пропорций, лицензия.
4. Проверка анимации: короткое видео или серия кадров со значениями входов 0 / 0,5 / 1.
5. Оркестратор отклоняет, если: пропорции неверны (число струн/отверстий/колков не по справочнику), части не по контракту, вес/полигоны выше бюджета, неясная лицензия, рывки при перемотке, отсутствует фолбэк.

После приёмки всех семейств: обновить `docs/instruments/animation-contract.md`, `docs/methodology/09-instruments.md`, `docs/STATUS.md`, `docs/BACKLOG.md`.
