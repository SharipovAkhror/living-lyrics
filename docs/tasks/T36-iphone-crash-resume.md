### 2. Путь сохранения и чтения позиции

Сохранение (`src/pages/song/SongPage.tsx:169-190`, `src/player/resume.ts`):
- ключ `living-lyrics.resume.v1` в `localStorage`, на песню `{ t, playing, savedAt }`. Все вызовы в `try/catch` (`resume.ts:23-41`): если хранилище бросает (приватный режим, квота), запись молча теряется;
- запись раз в 2 с (`SongPage.tsx:181`), на `pagehide` (`:182`), на `visibilitychange → hidden` (`:183`) и при размонтировании (`:188`). Обработчики начинают работать только после `clockArmed`, то есть после восстановления (`:156`, `:170`);
- запись пропускается при ошибке звука и `t < 1` (`:174`). Ближе 1,5 с к концу пишется 0 (`:175`).

Чтение (`SongPage.tsx:135-157`):
- только внутри `engine.init(...).then(...)` (`:135`). `init` сначала ждёт `loadAudio(slug)` из IndexedDB (`src/player/engine.ts:123`). `indexedDB.open` в `src/player/fileStore.ts:5-11` не ограничен по времени и не ловит `onblocked`;
- `?t=` в адресе побеждает сохранённое (`:139-141`). Сам сайт таких ссылок не создаёт (`git grep` по `src`), только внешние;
- точка старше 3 ч (`RESUME_AUTO_MS`, `resume.ts:10`) не применяется (`:144`), `t < 1` — тоже (`:145`);
- проверки версии сборки нет: ключ `v1` переживает новые деплои. Это не помеха;
- если точка была «играет», вызывается `play()`. При отказе (iOS без жеста) — пауза и кнопка «Продолжить с m:ss» (`:149-152`, кнопка `:514-523`).

Найденные разрывы:
1. **Восстановление зависит от IndexedDB.** `SongPage.tsx:135` → `engine.ts:123` → `fileStore.ts:5-11`. Если `indexedDB.open` не отвечает (это известный сбой WebKit: зависание первого `open` было в Safari 14.1.x; связь с текущей iOS **не подтверждена**), `.then` не наступает. Тогда не будет ни перемотки, ни кнопки, ни дальнейших записей, а страница стоит на 0:00. Если `init` отклоняется, `.then` без `.catch` тоже молча пропускает восстановление. Тест `idb-stall` это показывает: точка 90,1 с лежит в хранилище, а страница открылась на 0:00 без кнопки.
2. **Перемотка не сохраняется сразу.** Записи по событию перемотки нет, только таймер 2 с (`SongPage.tsx:181`). Если процесс убит в первые 2 с после перемотки, вернётся старое место. Тест `seek-then-kill`: перемотка на 1:27, после «падения» — 0:01. Для случая владельца («ничего не трогал») это маловероятно.
3. Окно потери при обычном прослушивании — до 2 с (таймер), это укладывается в ±2 с. Простое «падение» без перемотки в WebKit восстанавливается верно: тест `wait-then-kill` проходит.

Причина у владельца **не воспроизведена** однозначно. Простое убийство страницы на текущем коде даёт верное место, паузу и кнопку. Кандидаты по порядку: (а) сборка без возобновления — только если он слушал до 2026-10-21 15:51 +05 или деплой отстал (проверить в Vercel); (б) зависание IndexedDB при подъёме страницы после падения (разрыв 1); (в) падение вскоре после перемотки (разрыв 2). Память (T27) этим раундом не измерялась.
