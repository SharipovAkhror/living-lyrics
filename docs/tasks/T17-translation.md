# Задача T17: стандарт научного перевода и сверка трёх песен

Слова владельца (2026-10-18): «Нужен стандарт для перевода, чтобы ни капли ИИ там не было, а чтобы как будто учёный правильно по канонам всё чётко сверял и переводил».

Что есть: `docs/methodology/06-translation.md` (пять шагов на строку, скорость ≤ 17 зн/с, словари Lane/Steingass, принятые научные переводы — Николсон, Арберри; для Корана — Кулиев, Крачковский, Османов), `07-comment.md` (пояснения), `08-transliteration.md`, валидатор `scripts/tools/validate.ts` (`BANNED_RU`, скорость), канон `content/songs/<slug>/canon.md`, источники `sources.md`, переводы — `tr.ru` у строк в `lyrics.json`.

Зона: `docs/methodology/06-translation.md` (и ссылки из README/07), новый `docs/methodology/translation-standard.md` (если удобнее отдельным файлом), `scripts/tools/validate.ts` (только проверки перевода), `content/songs/*/lyrics.json` — **только** `tr.ru` и, если перевод меняет смысл пояснения, `comment`; `content/songs/*/sources.md` (новые источники), `docs/analysis/translation/<slug>.md` (досье). Слова оригинала, время, секции — не трогать.

Сделать:

1. **Исследование, как это делают филологи.** Найди и прочитай (веб-поиск, открытые издания): принципы академического перевода персидской, арабской, турецкой суфийской поэзии и средневековых латинских и немецких текстов на русский (школы Крачковского, Е. Э. Бертельса, Б. Я. Шидфар; переводы Руми на английский (Николсон, Арберри, Льюисон) и на русский, русские переводы «Дивана Шамса»), требования к подстрочнику и к поэтическому переводу, как переводят суфийские термины (‘ишк, шаук, фана, бака, хал, макам, саки, джам…) — устойчивые русские соответствия с источником. Итог — **стандарт** простыми пунктами: что считается точным переводом песенной строки, как работать с терминами, что запрещено.
2. **Что значит «ни капли ИИ».** Запиши в стандарт список приёмов, которые выдают машинный или «гладкий» перевод, и запрети их: пафосное усиление («поистине», «воистину», «бесконечный»), добавленные метафоры, которых нет в оригинале, общие слова вместо конкретных («вселенная», «душа» там, где в оригинале другое), канцелярит, кальки синтаксиса, лишние пояснения внутри строки, ритмическая «красивость» в ущерб смыслу, смена лица и времени. Добавь в валидатор то, что проверяется машинно (стоп-слова и обороты), остальное — в чек-лист.
3. **Досье на каждую строку** (`docs/analysis/translation/<slug>.md`): оригинал, подстрочник по словам с грамматикой, источники смысла (словарь с указанием статьи/страницы, научный перевод с указанием издания и страницы, комментарий), принятый перевод, что не поместилось (→ пояснение). Источник обязателен; где его нет — «требует проверки», не догадка.
4. **Сверка трёх песен по стандарту.** Пройди все строки I Have Come Alive, Karitas, ONE. Исправь переводы, которые не проходят стандарт, сохрани скорость ≤ 17 зн/с. В отчёте — таблица изменений: строка, было, стало, почему (со ссылкой на источник).
5. **Независимая проверка Gemini.** Подготовь для оркестратора список строк (id, оригинал, принятый перевод) — оркестратор отдаст их Gemini на обратный перевод и проверку смысла. Сам Gemini не вызывай.
6. Проверка: `npm run validate && npm run typecheck`, `npm run song-status -- <slug>` для трёх песен.

Готово, когда: стандарт записан и опирается на найденные источники; запреты «ИИ-перевода» в стандарте и, где можно, в валидаторе; досье на все строки трёх песен с источниками; переводы сверены и исправлены с таблицей причин; список для Gemini готов; проверки проходят.
