# Задача T19: скорость и плавность — переходы между песнями и все места ожидания — сделано (2026-10-18)

Слова владельца (2026-10-18): «При переключении на новую песню лагает, как будто он грузит песню. Такого рода моменты надо предугадать, найти и под них UI/UX доработать».

Запускается после того, как T14 (сцена и страница песни) и T15 (плеер и фоновый звук) влиты в main. Если к этому времени владелец выбрал концепцию T18 — используй её раздел «состояния ожидания и переходы»; если нет — сделай сдержанно в нынешнем «Космосе».

Зона: `src/pages/**` (библиотека, страница песни, переходы), `src/player/**`, `src/app/**`, `src/scene/**` (только загрузка и первый кадр), `src/styles/**`, `vite.config.*`, `public/**` (заголовки кэша, манифест), `vercel.json` (если есть), `docs/**`.

Сделать:

1. **Замер, а не догадки.** Профиль открытия песни из библиотеки и переключения следующей: что грузится (`lyrics.json`, запись, `features.json`, `peaks`, шрифты письма, гравюры, 3D), сколько весит, в каком порядке, что блокирует первый кадр и начало звука. Холодный и тёплый кэш, iPhone-подобная сеть (Playwright: 4G/3G, CPU ×4). Таблица «до».
2. **Найти все места ожидания** во всём интерфейсе (не только смена песни): первый вход, медленная сеть, буферизация звука, перемотка в незагруженное место, шрифт другого письма, листы «Весь текст» / «О песне», галерея инструментов, ошибки сети. Список с тем, что видит пользователь сейчас.
3. **Исправить.** Звук начинает играть, как только можно (потоково, без ожидания всего файла; `preload` по ситуации); тяжёлое (`features.json`, гравюры, 3D) — после первого кадра; предзагрузка по намерению (наведение и видимость в библиотеке, следующая песня — заранее, в фоне, с учётом экономии трафика); кэш (заголовки Vercel для неизменяемых файлов с хешами; при необходимости — сервис-воркер только для статических файлов, не ломая фоновый звук из T15); переход между песнями без белой вспышки и прыжков фона; кнопка воспроизведения честно показывает буферизацию; понятные ошибки с действием.
4. **Повторный замер**, таблица «после», и бюджеты, которые проверяются в сборке (например, первый кадр песни, начало звука на тёплом кэше).
5. Проверка: `npm run validate && npm run typecheck`, `npx vite build`; кадры и запись последовательности переключения (серия кадров через 100–200 мс) в `work/shots/t19/`.

Готово, когда: есть таблицы «до/после» по замеру; все места ожидания найдены и закрыты; переключение песни плавное, звук стартует быстро; бюджеты записаны; фоновый звук (T15) не сломан; проверки проходят.
