# Задача T1: синхронизация слов — до 90 % (цель 100 %) доказанных строк в каждой группе

Цель владельца: слова загораются ровно тогда, когда их поют. Пословная заливка включается для всей песни, только когда доказано **90 % строк в каждой группе** (соло, хор) — решение владельца 2026-10-20 (было 80 %, 2026-10-18); цель — 100 %, недоказанные строки тоже доводить. Доказательство не ослаблять: случайный проход строки ≤ 5 %, правила — `docs/methodology/05-alignment.md`.

## Где остановились (прогон `39128266965`, ветка `grok/t1-sync` влита в main)

Цепочка: строки по официальным субтитрам (±0,3 с) → постановщики (MMS-окна, htdemucs_ft, stable-ts, второй выравниватель) → доказательство слова (сильная атака голоса + свидетель Whisper в 0,10 с; где одиночный свидетель проходит случайно чаще 15 % — оба) → строка доказана при ≥ 25 % доказанных слов и ни одном опровергнутом (случайный проход 0,035). Свидетель Whisper выбирается по паре песня/язык по числу доказанных строк.

| Группа | доказано / всего | % |
|---|---|---|
| I Have Come Alive, соло | 66 / 120 | 55 |
| Karitas, соло | 21 / 60 | 35 |
| ONE, соло | 21 / 37 | 57 |
| ONE, хор | 1 / 26 | 4 |

Узкие места по языкам: латынь Karitas — 1 из 24 строк (Whisper large-v3-turbo: 16 из 59 слов в 0,10 с, медиана 0,273 с); немецкий ONE — 1 из 23 (large-v3: 9 из 112, медиана 0,376 с); азербайджанский Karitas — 13 из 26; хор ONE (Экхарт, хоровое пение) — 1 из 26. Whisper эти языки и хор слышит плохо, поэтому свидетель не подтверждает даже верную постановку.

## Сделать

1. **Независимый свидетель, который слышит звуки, а не слова.** Фонемный выравниватель, не зависящий от MMS и Whisper: например, открытая wav2vec2/XLS-R модель, обученная на фонемах IPA (вроде `facebook/wav2vec2-xlsr-53-espeak-cv-ft` или новее), и фонемизация известного текста через espeak-ng (латынь, немецкий, азербайджанский, персидский и др.); или MMS-адаптеры языка, если они дают независимый от постановщика сигнал. Лицензии моделей записать (некоммерческие помечать, как MMS); веса в репозиторий не класть. Выбор — по замеру, не по догадке.
2. **Калибровка на тех же правилах.** Для нового свидетеля — случайный проход слова и строки на смещённых метках (как для Whisper); свидетель допускается к паре песня/язык, только если удерживает строку ≤ 5 %. Пороги не сдвигать ради процентов.
3. **Хор.** Проверить, чем хор отличается: атаки размыты, слова тянутся. Поискать честный признак для хора (атака по огибающей стема голосов, гласные-ядра, согласие нескольких свидетелей) с той же проверкой случайного прохода. Если честного способа нет — так и написать, с числами.
4. **Прогон в GitHub Actions** (`.github/workflows/pipeline.yml`, задание `jobs/<slug>.json`) для трёх песен; таблица «было/стало» по группам и языкам; отчёт `docs/analysis/<slug>-qa.md` обновить.
5. Если группа песни дошла до 90 % во всех группах — `timing.status` и флаги ставит конвейер по правилам, сайт включит заливку сам; руками время не двигать.

Проверки: `npm run validate && npm run typecheck`, `python scripts/pipeline/test_sync.py`. Push — только своей ветки, чтобы запустить Actions (без force).

Готово, когда: новый свидетель откалиброван и встроен; прогон трёх песен сделан; по каждой группе — доказано / всего и почему не больше; методика (`05-alignment.md`) описывает свидетеля и его калибровку; проверки проходят.
