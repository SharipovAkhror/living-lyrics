# Задача T20: маршрут новой песни — встроить новые способы и отрепетировать

Слова владельца (2026-10-18): «Надо дорогу сделать для новых песен — как мы их будем внедрять, откуда, с какого интерфейса». Дорога записана в `docs/methodology/new-song-route.md` (кто делает каждый шаг и что нужно от владельца). Это последний шаг до «добавляем новые песни».

Запускается после T17 (стандарт перевода): маршрут должен ссылаться на готовый стандарт.

Что есть: маршрут по стадиям `docs/methodology/README.md` и `01-intake.md` … `12-publish.md`; `npm run song-status -- <slug>` (`scripts/tools/song-status.ts`) — таблица стадий и одна следующая команда; `npm run new-song`; конвейер `scripts/pipeline/*.py` и `.github/workflows/pipeline.yml`. После T11 (методика «справится даже слабый агент») появились способы, которых в стадиях и в `song-status` ещё нет:

- приём по ссылке на официальное видео: `yt-dlp` берёт звук и видео одного ролика (`docs/methodology/new-song-route.md`, `scripts/instrument_id/prompts/README.md`);
- строки и их время по официальным субтитрам: `docs/analysis/<slug>/cues.json` (только время и id, без текста субтитров);
- просмотр видео Gemini и вступления инструментов: `scripts/instrument_id/` (`vision.json`, `fusion.json`, `entries`), правило «титры + кадр» или «три плана»;
- стандарт научного перевода и досье на строку (T17): `docs/methodology/06-translation.md`, `docs/analysis/translation/<slug>.md`;
- состав песни — книги, авторы, издания (T13);
- учёт расхода исполнителей: `ops/usage/`.

Зона: `docs/methodology/**`, `scripts/tools/song-status.ts`, `scripts/tools/new-song.ts`, `scripts/tools/validate.ts` (только проверки стадий), `.claude/skills/add-song/**` (навык только указывает на маршрут), `content/songs/<новая песня>/**`, `docs/analysis/<новая песня>/**`, `content/audio-enc/<новая песня>/**`, `jobs/<новая песня>.json`.

Сделать:

1. **Стадии.** В `01-intake.md` … `12-publish.md` и в `README.md` — новые способы как обычные шаги: что сделать, чем проверить, что считается готовым. Маршрут `new-song-route.md` и стадии не противоречат друг другу; по каждой стадии видно, можно ли её делать параллельно.
2. **`song-status`.** Знает новые стадии (приём по ссылке, реплики субтитров, видео и вступления, досье перевода, состав) и для каждой выдаёт одну следующую команду. Не просит невозможного (например, пустое задание, когда конвейера нет на ветке).
3. **Репетиция на четвёртой песне.** Владелец выбирает песню и даёт ссылку на официальное видео (или файл записи). Пройдите весь маршрут по `song-status`, без нового кода под песню, так, как прошёл бы слабый агент: команды — только те, что выдаёт `song-status` и стадии. Каждое место, где пришлось догадываться или читать код, — правка методики или `song-status`, а не обход.
4. **Отчёт репетиции** — `docs/analysis/<slug>/rehearsal.md`: шаги, время на каждый, где споткнулись и что поправлено.
5. Проверка: `npm run validate && npm run typecheck`, `npm run song-status -- <slug>` для всех четырёх песен, `npx vite build`.

Готово, когда: стадии и `song-status` описывают весь маршрут, включая новые способы; четвёртая песня прошла маршрут до прослушивания владельцем без нового кода; отчёт репетиции записан, найденные шероховатости исправлены; проверки проходят.
