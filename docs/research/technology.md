# Технологии: что брать в конвейер

Дата сверки источников: 2026-10-17. Утверждения ниже опираются на страницы, которые открывались в этот день (репозитории, карточки моделей, документация, локальные файлы). Чего не удалось измерить или дочитать — помечено «не измерено» или «не подтверждено». Чужие цифры с других датасетов на наши песни не переносятся.

Общий раннер для тяжёлых шагов — GitHub Actions, публичный репозиторий. В документации GitHub для публичных репозиториев стандартный Linux-раннер (`ubuntu-latest`) — 4 ядра, 16 ГБ ОЗУ, 14 ГБ SSD ([исходник таблицы в github/docs](https://github.com/github/docs/blob/main/data/reusables/actions/supported-github-runners.md)). Проверка этого репозитория 2026-10-16 увидела 4 ядра и 15 ГБ (`docs/BACKLOG.md`, задача T1; отчёт `docs/analysis/actions-check.md`). Песни длинные: ориентир «10 минут» ниже — оценка порядка, не замер. На диске 14 ГБ нельзя держать полный снимок большой модели вместе с PyTorch и кэшем.

Канон сцены, который рекомендации не ломают: известный текст выравнивается по голосу (T1); телефон ничего не считает; кадр инструмента — функция времени воспроизведения (`src/instruments/animation.ts`, `docs/instruments/animation-contract.md`).

## 1. Выравнивание известного текста по пению

Задача T1: начало слова на сольной строке не дальше 0,1 с от голоса. Текст уже известен (`lyrics.json`, слова `w` / `s` / `e` в `src/data/schema.ts`). Распознавание «с чистого листа» здесь вредно: оно переписывает строку.

Языки каталога: персидский, арабский, турецкий, азербайджанский, английский, латынь, средневековый немецкий (`gmh`), испанский. В схеме есть и другие коды (`src/data/schema.ts`).

### Как честно мерить без ручной разметки каждого слова

Публичная цифра с Jamendo сюда не подставляется: репертуар другой, и среднее отклонение на поп-песнях en/fr/de/es обычно шире цели 0,1 с, а медиана — уже. Точные MAE статей в этот текст не копируются, пока T1 не снимет свои прокси.

Честная проверка для этого проекта, без претензии на «точность слова»:

1. Границы строк против официальных субтитров, где они есть с временем (Karitas — `docs/analysis/research/`, T2). Это проверка строки, не слова.
2. Согласие двух выравнивателей с разными весами. Второй MMS (`mms-1b-all` после `MMS_FA`) таким согласием не является.
3. Согласие начала слова с атакой голоса (`qa_sync.py` в той же ветке). Совпадение с атакой не доказывает, что слово то самое.
4. Отметки владельца (T8), если он скажет «да». Хор и распев автоматикой не закрываются — это уже написано в T8.

Пока все четыре не сошлись, строка остаётся `timing-draft`, как сцена уже умеет.

### Рекомендация

Основной путь — CTC по известному тексту: довести `ctc.py` из `wip/sync-tools` и кормить его эмиссиями MMS (один языковой адаптер за раз, не весь снимок `mms-1b-all`). Обёртка `ctc-forced-aligner` годится, если свой Витерби на пении разъедется; веса по умолчанию у неё те же по лицензии, CC-BY-NC 4.0.

Второй голос — WhisperX `align` только там, где в `alignment.py` уже есть модель: en, de, es, ar, fa, tr. Перед прогоном открыть лицензию конкретного wav2vec2. Для азербайджанского, латыни и `gmh` модели по умолчанию нет. `gmh` → `deu` в `MMS_LANG` — сознательное приближение к современному немецкому, его надо помечать в отчёте QA, а не считать точным.

MFA оставить в стороне для этого каталога: нет персидского, азербайджанского и латыни, модели речевые. stable-ts не подключать: архив и Whisper.

Лицензия весов MMS — некоммерческая. Для закрытого конвейера исследования это приемлемый технический выбор. Выкладывать веса нельзя. Можно ли продавать сайт, чьи метки времени посчитаны такой моделью, — вопрос юристу (см. `product.md`).

## 2. Отделение голоса

T1 сверяет атаки голоса. T6 кормит рисунки четырьмя стемами: ударные, бас, прочее, вокал (`animation.ts`, дорожки `drums` / `bass` / `other` / `vocals`).

Сейчас и в main, и в `315ce92` вызывается Demucs с `--two-stems vocals`. README Demucs прямо говорит: этот флаг после полного разделения смешивает остальное, быстрее и легче по памяти не становится. Ветка сохраняет `vocals.wav` и `no_vocals.wav` и выбрасывает ударные, бас и «прочее». Для анимации этого мало.

### Рекомендация

Разделять `htdemucs` и сохранять четыре стема. Флаг `--two-stems` для дорожки признаков не нужен: он не ускоряет расчёт и уничтожает стебли, без которых `FAMILY_DRIVE` не на чем стоять. `htdemucs_ft` запускать только если на наших песнях вокал в `htdemucs` заметно течёт в «прочее», и только после замера времени: это четыре прохода.

RoFormer и UVR не ставить моделью по умолчанию, пока для конкретного файла весов не прочитана лицензия и не измерен CPU. Пакет `audio-separator` можно оставить как загрузчик на потом: код MIT, веса — нет.

Ожидание по времени на раннере закладывать по README Demucs (порядка длительности трека, с запасом), а число из комментария `separate.py` проверить одним прогоном T1 и записать в отчёт. До этого прогона ни 6, ни 15 минут не считать фактом.

## 3. Признаки звука для анимации и узнавание инструментов

Контракт (`animation.ts`, строки 10–62, и `docs/instruments/animation-contract.md`) ждёт дорожки `loud`, `onset`, `bright`, `drums`, `bass`, `other`, `vocals` с частотой 20–50 Гц и необязательный список `beats`. Из них `driveAt` собирает `energy`, `pulse`, `sustain`, `breath`, `beat` (все 0…1, только от времени).

Файл `scripts/pipeline/features.py` на коммите `315ce92` этого не делает. Его шапка: кривые вокала для `align.py` и `qa_sync.py` (`rms_db`, `activity`, спектральный поток) с шагом 10 мс. Утверждение контракта и задачи T6, что этот файл пишет `public/audio/<slug>/features.json`, к содержимому ветки не относится. Писателя `features.json` ещё нет.

Классификаторы (PANNs, AST, BEATs, CLAP, модели Essentia) выдают метки классов, не огибающие. Огибающие считаются из стемов.

### Огибающие: чем считать

| Вход контракта | Чем считать | Источник |
|---|---|---|
| `loud` и `energy` | RMS смеси, нормированный в 0…1 по песне | librosa `feature.rms`. Код librosa — ISC, в [LICENSE.md](https://github.com/librosa/librosa/blob/main/LICENSE.md) copyright 2013–2026. Дату тега 1.0.0 в этот проход не перечитывали |
| `onset` и `pulse` | сила атаки, спектральный поток | librosa `onset.onset_strength`: положительная разница логарифма мел-спектра |
| `bright` | спектральный центроид, нормированный | librosa `feature.spectral_centroid` |
| `drums`, `bass`, `other`, `vocals` | RMS соответствующего стема Demucs | тот же RMS, четыре файла из раздела 2 |
| `sustain` | медленная огибающая стема минус короткие атаки | это правило проекта, не функция библиотеки. Порог и окно подобрать на одной песне и описать в коде |
| `breath` | доля высокой полосы или шума на стеме духовых / «прочее» / вокал | то же: эвристика под контракт, не готовая модель. Для семьи без `breath` контракт и так возвращает 0 |
| `beat` | времена долей | `beat_this` (ниже). Если трекер не нашёл пульс, список пустой: `beatPhase` уже возвращает 0. Для свободного ритма (таксим, аваз) так и оставлять |

Время этих признаков на 10 минут — секунды, не десятки минут: это не нейросеть. Точные секунды не измерялись.

## 6. Трёхмерные инструменты для T6

Задание `docs/tasks/instruments-3d.md` рекомендует Blender Python. На машине владельца Blender нет (условие задачи T3). Репозиторий — Node, гравюры уже порождаются кодом (`scripts/art/`). Скрипт `bpy` тащит GPL Blender в сборку, даже если сами сетки мы напишем.

Бюджет задания: 30–60 тыс. треугольников на инструмент, GLB не больше 1,5 МБ, три инструмента на iPhone 12 при 60 кадрах/с. Это требование, не измерение. На устройстве в этом исследовании ничего не гонялось.

| Путь | Лицензия | Что даёт | Цена |
|---|---|---|---|
| Процедурная сетка в Node: three.js `BufferGeometry` и [@gltf-transform](https://github.com/donmccurdy/glTF-Transform) | README glTF-Transform: MIT, copyright 2024. Релиз v4.5.1 — 2026-09-28. three.js — отдельный пакет, его LICENSE здесь не вставлялся | те же имена частей `part-*`, что ждёт контракт; сборка без Blender; правится как обычный скрипт | сложную деку и розетку дольше лепить кодом, чем в моделлере |
| Blender headless (`blender -b -P`) | Blender и bpy — GPL | удобнее лепить органику | нет на машине владельца; в Actions это отдельный образ и другая лицензия на скрипты |
| Чужая сетка CC0 / CC-BY | только после карточки конкретной модели | готовая форма | имена частей чужие; органология проекта (число струн, лады) в чужой сетке не совпадёт. Smithsonian Open Access часто называют CC0; страницу лицензии в этот проход не открывали — перед файлом прочитать карточку и записать автора в `docs/instruments/credits.md` |
| Draco, `KHR_draco_mesh_compression` | кодек Google, обёртка в glTF-Transform (`gltf-transform draco`) | сильно жмёт треугольники | дольше распаковывается на CPU телефона. Сравнение на iPhone не снималось |
| meshopt, `EXT_meshopt_compression` | команда `gltf-transform meshopt` в том же README | жмёт геометрию, морфы и ключи | декодер меньше. Для телефона это первый выбор сжатия, пока замер не покажет иное |

Контур «гравюра»:

Пример three.js `OutlinePass` ([файл](https://github.com/mrdoob/three.js/blob/dev/examples/jsm/postprocessing/OutlinePass.js)) делает несколько дополнительных проходов и, если `pulsePeriod > 0`, красит кромку через `performance.now()`. Это стена часов, не время песни: перемотка даст другой кадр, что запрещает `InstrumentDrive`. Постобработка ещё и греет телефон. Контур делать оболочкой (задние грани, толщина в шейдере) цветом `currentColor`. Штриховку — полосами в шейдере того же цвета, без текстур. Один общий контекст WebGL, как уже написано в задании T6; WebGPU для iPhone 12 не закладывать, поддержку не проверяли.

### Рекомендация

Модели писать на Node и собирать glTF-Transform. Blender не требовать. Сжатие — meshopt. Материал — контур оболочкой и штрих в шейдере, без `OutlinePass` и без карт. Чужие CC0-сетки — только как сверка пропорций, с записью лицензии в credits. Если какое-то семейство кодом не соберётся, тогда отдельное решение про Blender в Actions, не на машине владельца.

Цифра «60 кадров на iPhone 12» остаётся приёмочным критерием T6, не результатом этого исследования.

### Следующий шаг

T6. Сначала писатель `features.json` (раздел 3), затем один инструмент (даф или най) процедурной сеткой, meshopt, контур оболочкой, проверка перемотки: тот же кадр на той же секунде. Бюджет треугольников и размер GLB записать в отчёт приёмки.
