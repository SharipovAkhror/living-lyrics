# Формат данных песни

Источник истины — `src/data/schema.ts` (zod). JSON-схемы для автодополнения в редакторе: `docs/schema/song.schema.json`, `docs/schema/lyrics.schema.json` (обновляются командой `npm run validate -- --emit-schema`).

## song.json

| Поле | Тип | Описание |
|---|---|---|
| `slug` | строка | совпадает с именем папки: `[a-z0-9-]+` |
| `title` | строка | название как в релизе |
| `titleOriginal` | строка? | название на языке оригинала (`مرده بدم زنده شدم`) |
| `artist`, `featuring[]` | строки | исполнитель и приглашённые |
| `release` | `{ album?, year?, label? }` | |
| `performance` | `{ event?, venue?, city?, date? }` | для живых записей |
| `languages[]` | коды ISO 639 | только реально спетые, по порядку появления. Две строчные буквы — ISO 639-1 (`fa`, `ar`, `he`, `hi`, `la`), три — ISO 639-3 (`ota` османский, `gmh` средневерхненемецкий, `grc` древнегреческий). Полный список — `src/data/iso639.ts`. Неверный код валидатор называет в тексте ошибки. Новая песня на новом языке код приложения не меняет |
| `poets[]` | `{ name, lang?, era? }` | авторы текстов |
| `duration` | секунды | длительность файла `high.m4a` |
| `palette` | `{ accent, accentDark, field[3–4] }` | цвет песни (светлая/тёмная тема) и цвета живого фона |
| `coverGlyph` | строка? | не используется: обложка — только цвет песни, без букв. Поле оставлено, старые файлы проходят проверку |
| `audio` | см. ниже | |
| `timing` | `{ status: draft∣aligned∣verified, method, notes? }` | |
| `credits[]` | `{ role, name }` | **только подтверждённые** |
| `review[]` | строки | открытые вопросы |
| `parts[]` | см. ниже | состав: чьи слова, из какой книги, где в записи звучат. Порядок — первое появление. Поля нет, пока состав не собран |

`parts[]` — одна часть на один спетый текст. Повтор позже поётся той же частью. Переложение на другой язык — отдельная часть. Инструментальные секции и секции без слов в состав не входят.

| Поле | Описание |
|---|---|
| `id` | `[a-z0-9-]+`, уникален внутри песни |
| `title` | короткое имя по-русски, обычный регистр («Газель Руми», «Мавваль») |
| `lang` | код ISO 639, тот же, что у строк этой части |
| `author?` | `{ name, years?, original? }`. `years` — только срок, который назвал источник («1098–1179», «ум. 1556», «XIII в.»). `original` — имя своим письмом. Нет автора в источнике — поле опускают, карточка пишет «не установлено» |
| `work?` | `{ original?, ru?, lang? }`. Название книги или стихотворения: своим письмом и по-русски. Нужно хотя бы одно. `lang` — язык названия, когда он не совпадает с языком пения |
| `ref?` | номер газели, бейты, глава, страница, издание — как в источнике |
| `url?` | адрес `http` или `https`, уже дословно записанный в `sources.md` |
| `note` | одно предложение: как часть звучит в этой записи |
| `sections?`, `lines?` | id секций или строк. Нужно хотя бы одно. Секция забирает все свои вокальные строки |

Валидатор сверяет id с `lyrics.json`. Строка в двух частях — ошибка. Строка ни в одной части, пустая часть, чужой `lang`, адрес вне `sources.md`, часть не по порядку первого звучания — предупреждение. Песня с вокалом и без `parts` тоже даёт предупреждение. Как заполнять — [стадия 4](methodology/04-text.md), раздел «Состав песни».

`audio`:

```json
{
  "status": "ready",
  "high": "/audio/<slug>/high.m4a",
  "saver": "/audio/<slug>/saver.m4a",
  "peaks": "/audio/<slug>/peaks.json",
  "gainDb": -3.2,
  "provenance": { "kind": "url", "ref": "https://…", "retrieved": "2026-10-16", "codec": "opus 160k", "sha256": "…" }
}
```

## lyrics.json

```json
{ "sections": [ Section, … ] }
```

**Секция** — общие поля: `id`, `start`, `end` (секунды), `label` (обычный регистр), `comment?`, `flags?`, `entries?`.

- `kind: "vocal"` — `voice?` (кто поёт), `lines[]`. `entries` здесь — сопровождение, не певец: певец остаётся в `voice`.
- `kind: "instrumental"` — `instruments[]` (ключи каталога, ведущий первым; пустой список — пустая сцена, аплодисменты, без подстановки ансамбля), `performers?[]` («Имя (инструмент)»), `mode?` (лад), `note?` (1–2 фразы), `layout?` — раскладка гравюр: `single`, `pair-sides`, `pair-diagonal`, `stack`, `fan`, `hero-insets`, `grid`. Без `layout` сцена выбирает сама по числу инструментов и размеру экрана; задавать вручную — только когда выбор спорит со смыслом ([стадия 9](methodology/09-instruments.md)).

`entries` — кто вступает и когда, массив `{ key, at, until? }`. `key` — ключ из `src/instruments/list.ts`. `at` и `until` — секунды от начала записи и лежат внутри секции: `at` не раньше начала и раньше конца, `until` позже `at` и не позже конца (допуск валидатора 0,05 с). Порядок массива — порядок появления: на маленьком экране гравюры выходят в этом порядке. `until` опускают, когда инструмент играет до конца секции. Валидатор отклоняет неизвестный ключ и время вне секции; ключ без гравюры — предупреждение. Список не обязан совпадать с `instruments` по составу, но в данных песни они про одно и то же: `instruments` — кто слышен, ведущий первым, `entries` — в какую секунду каждый вступает.

**Строка** (`line`):

| Поле | Описание |
|---|---|
| `id` | уникальный, `[a-z0-9-]+` |
| `lang`, `script` | язык — код ISO 639, как в `languages`. Письмо — код ISO 15924 из `SCRIPT_CODES` в `src/data/schema.ts`: `Latn`, `Cyrl`, `Grek`, `Arab` (арабское письмо, в том числе персидский и урду), `Hebr`, `Armn`, `Geor`, `Deva` и другие индийские, `Hani`, `Jpan`, `Kore`, `Thai`, `Ethi` и остальные из того списка. Направления справа налево перечислены в `RTL_SCRIPTS` (`Arab`, `Hebr`, `Syrc`, `Thaa`, `Nkoo` и другие). Незнакомое письмо сцена не роняет: строка идёт гарнитурой `f-serif`, недостающие знаки добирает системный шрифт. Сейчас направление справа налево сцена ставит для `Arab`; остальные коды из `RTL_SCRIPTS` подключаются одной правкой `src/data/timeline.ts`, не под каждую песню |
| `words[]` | `{ w, s, e, br?, em? }` — слово как поётся, начало и конец (с), перенос после слова, ключевое слово. Арабское письмо хранится с полными огласовками; тумблер «Огласовки» снимает знаки только при показе (`src/data/harakat.ts`, правило полноты — в `docs/methodology/04-text.md`) |
| `alt?` | `{ script, text }` — та же строка другим письмом (Физули арабицей) |
| `translit?` | кириллическая транскрипция. Обязательна, если `script` — `Arab` или `Aran`. Валидатор предупреждает, когда поле пустое |
| `tr` | `{ ru: "…" }`, можно добавить другие языки: `{ ru, uz, en }`. Лёгкая разметка: `**слово**` — пара к ключевому слову оригинала (`em`), горит тем же цветом; `*слово*` — курсив для оттенка смысла |
| `comment?` | пояснение, разметка `**…**`, `*…*`, пустая строка — новый абзац |
| `voice?` | кто поёт эту строку |
| `placedBy?` | кто поставил строку: `mms`, `mms-window`, `mms-ft`, `stable-ts`, `second`. Нет поля — строка осталась на реплике. Окна MMS и стем htdemucs_ft в доказательстве считаются одним постановщиком |
| `fx?` | не используется (наследие прежней сцены); новые строки его не заполняют |
| `flags?` | `text-unverified`, `timing-draft`, `translation-draft`, `comment-draft`, `attribution-unverified` |

## peaks.json

```json
{ "rate": 20, "duration": 490.1, "rms": [0.02, 0.05, …] }
```

`rate` значений в секунду, нормированный RMS 0…1. Сцена использует его для живого фона и «дыхания» гравюр.

## features.json

`public/audio/<slug>/features.json`, контракт `AudioFeatures` в `src/instruments/animation.ts`. Пишет `scripts/pipeline/features.py` (стадия `features`). Компактный JSON, без переносов: семь дорожек с отступами весили бы мегабайты.

```json
{ "rate": 20, "duration": 580.06, "tracks": { "loud": [0.12, 0.4], "onset": [], "bright": [], "drums": [], "bass": [], "other": [], "vocals": [] }, "beats": [0.5, 1.02] }
```

| Поле | Смысл |
|---|---|
| `rate` | 20 значений в секунду (договор контракта — 20–50). Одинаковая длина у всех дорожек |
| `duration` | секунды смеси |
| `tracks.loud`, `onset`, `bright` | громкость смеси, сила атаки, спектральная яркость, каждая 0…1 |
| `tracks.drums`, `bass`, `other`, `vocals` | громкость стемов htdemucs, 0…1, в шкале смеси, не собственного пика стема |
| `beats?` | секунды долей. Поля нет, когда устойчивого пульса не нашлось, в том числе в свободном ритме |

Числа дорожек — с двумя знаками после запятой; с одним, если иначе файл тяжелее ~900 КБ. `sustain` и `breath` в файл не входят: их на каждом кадре считает `driveAt` из этих дорожек и семейства инструмента. На телефоне файл только читается.

## Файлы песни

| Файл | Что внутри |
|---|---|
| `song.json` | метаданные, палитра, аудио, статус тайм-кодов, состав (`parts`), открытые вопросы |
| `lyrics.json` | секции и строки — ровно то, что поётся, с измеренным временем слов |
| `canon.md` | дословные оригиналы всех спетых текстов с источниками; `npm run validate` проверяет, что каждая строка в нём есть |
| `sources.md` | откуда каждый факт: записи, тексты, титры, палитра |

## Как сцена читает данные

- Каждая строка — отдельный шаг потока; повтор текста — отдельная строка (сцена помечает её «повтор»).
- Письмо `Arab` сцена рисует справа налево шрифтом мусхафа (для персидского можно включить насталик). Остальные письма — антиква `f-serif`; знаков, которых в ней нет, системный шрифт не прячет и страницу не ломает. Список письма справа налево — `RTL_SCRIPTS` в `src/data/schema.ts`.
- Строка арабским письмом хранится с огласовками. Тумблер «Огласовки» (по умолчанию включён) решает, рисовать ли знаки на сцене, в «Весь текст» и в арабских вставках пояснений. Выключенный режим не меняет файл и не разрывает соединения букв.
- Строка становится текущей за 0,6 с до первого слова; переход длится до 0,6 с и успевает закончиться до следующей строки.
- После паузы длиннее 4 с над следующей строкой появляется «через 0:08».
- `voice` (строки или секции) подписывается над строкой, когда голос меняется.
- Пояснение: у строки → у ближайшей предыдущей строки той же секции → у секции.
- Инструментальная секция заранее видна строкой «Инструменты: …», на сцене — все её инструменты сразу, каждый на своей подложке (раскладку считает `src/instruments/layout.ts`, лишние при нехватке места собираются в «+N»), с отсчётом до первого слова следующей вокальной.
