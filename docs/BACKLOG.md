# Задачи

Каждая задача самодостаточна: её можно отдать любому агенту (любого провайдера) или человеку. У каждой — цель, что читать, что считается готовым. Общие правила — `AGENTS.md`; текущее состояние — `docs/STATUS.md`. Закончив задачу, обновите оба файла и закоммитьте.

Порядок — по важности для владельца: сначала точная синхронизация и правильные тексты, потом дизайн и инструменты.

**Как сейчас идёт работа (с 2026-10-17).** Задачи выполняет Grok (Grok Build, модель grok-4.7) — каждая в своём git worktree `../living-lyrics-wt/<имя>` на ветке `grok/<имя>`; Claude Code ставит задачи, проверяет и вливает в `main`. Сделано: T9; T2, часть 1 — эталоны `canon.md` трёх песен; T3 — `docs/research/technology.md` и `product.md`. Сделано также T8 и T2 целиком. Идут: T11 (`grok/t11-method`), T1 (`grok/t1-sync`), пилот T6 (`grok/t6-pilot`), образцы T4 (`grok/t4-fonts`). Следом: признаки звука (T6, отдельная часть, после T1).

**Выводы T3, которые обязательны для задач** (подробно — `docs/research/technology.md`, «Сводка для бэклога»): выравнивание — свой CTC на MMS + второй проход WhisperX (en/de/es/ar/fa/tr), не второй MMS; веса MMS — CC-BY-NC 4.0, в репозиторий не класть; голос — `htdemucs` в четыре стема, без `--two-stems`; признаки для анимации — librosa + `beat_this`, Essentia (AGPL) не брать; шрифты — Amiri, Source Serif 4, мусхаф KFGQPC как есть (сабсетить нельзя); 3D — сетки из Node, сжатие meshopt, контур оболочкой в шейдере (`OutlinePass` ломает перемотку).

## T1. Синхронизация «как швейцарские часы»

**Цель.** Время каждого слова измерено по голосу; сайт включает пословную заливку только там, где она доказанно совпадает с голосом.

**Есть.** Незаконченная работа агента — ветка `wip/sync-tools`: `align.py` (построчное выравнивание MMS), `engines.py`/`ctc.py` (второй выравниватель), `qa_sync.py` (отставание/спешка по каждой строке), `timing.py`, `features.py`, `stem_cache.py`, `apply_timing.py`, `.github/workflows/pipeline.yml` (задание `jobs/<slug>.json` → стадии → коммит результата). Секрет `AUDIO_KEY` в GitHub есть, проверка `audio-check.yml` прошла (раннер 4 ядра, 15 ГБ). В приложении заливка уже выключается для `timing.status = draft` и строк с флагом `timing-draft` (`src/scene/Scene.tsx`, `LineBlock.tsx`).

**Сделать.** Влить ветку, довести и проверить на I Have Come Alive в Actions; два независимых выравнивателя + сверка с атаками голоса; уверенность по строке → флаги; отчёт `docs/analysis/<slug>-qa.md`; затем три песни. Документация — `docs/methodology/05-alignment.md`, `11-qa.md` (убрать оттуда упоминание удалённого редактора).

**Готово, когда.** Для сольных строк расхождение начала слова с голосом ≤ 0,1 с по `qa_sync.py`; строки, не прошедшие проверку, помечены и показываются целиком; `timing.status = aligned`.

**Сделано (2026-10-17):** `canon.md` трёх песен сверены по буквам; `lyrics.json` пересобраны по эталонам (Karitas — под 977 с), каждый повтор — строка; голос без разобранных слов — секция `voice`; пояснения — для читателя, у своих строк. Открытые вопросы на слух — `song.json → review` и конец каждого `canon.md`. Время слов черновое до T1. Субтитры видео (VTT) не получены: YouTube отвечает 429 / проверкой на бота — перепроверить реплики, когда будут.

**Исходная постановка.** Пересобрать `lyrics.json` (Karitas — под реальные 977 с; сейчас его разметка рассчитана на 490 с, поэтому голос начинается раньше, чем показывает сайт), переводы и пояснения сохранить где строки совпадают, в переводе отметить пару к выделенному слову `**…**`. Титры (кто поёт, кто играет) — в `song.json → credits`, исполнители — в инструментальных секциях.

**Готово, когда.** `npm run validate -- --strict` без предупреждений о `canon.md`; порядок строк совпадает с субтитрами/картой голоса.

## T4. Шрифты и типографика

**Цель.** Приятные для глаза шрифты; курсив и жирный там, где помогают читать.

**Сделать.** Персидский по умолчанию — классический, но читаемый для новичка набор, как в уважаемых изданиях (кандидаты: Amiri, Noto Naskh Arabic, Scheherazade New; насталик оставить вариантом для знатоков). Арабский — шрифт Мединского Мусхафа остаётся. Латиница/кириллица оригинала — серьёзная антиква с настоящим курсивом; перевод — читаемый шрифт с курсивом. Показать владельцу образцы картинками (`npm run shots`), выбрать, обновить `src/styles/tokens.css`, `scripts/tools/font-coverage.json`, `docs/design/design-system.md`.

**Сделать.** 2–3 направления картинками на iPhone и десктопе (экран песни, плеер, библиотека), владелец выбирает; затем внедрить. Обязательно: расположение кнопок плеера аккуратнее; фон плавнее и разнообразнее (сейчас однородный); кнопка воспроизведения; на телефоне проверить касания (владелец пока слушал только на компьютере). ## T6. Инструменты: полная перерисовка в 3D с управлением и анимация от звука

**Цель.** Все инструменты заново, качественно, в 3D, с управляемыми частями (струны дрожат, мембраны вздрагивают, смычок ходит, клавиши нажимаются), подходящие к большей части живой музыки; плюс новые инструменты. Делает отдельный агент (можно другого провайдера); Claude Code выдаёт подзадачи по семействам и принимает по чек-листу.

**Полное задание** — `docs/tasks/instruments-3d.md` (модели из кода, именование частей, рендер, список инструментов, галерея, приёмка). Контракт — `docs/instruments/animation-contract.md`, `src/instruments/animation.ts`.

**Отдельно (не зависит от 3D):** `features.json` по каждой песне → загрузка в `SongPage` → `driveAt` → входы рисунков. Без этого никакие рисунки не двигаются в такт. Внимание (T3): `features.py` из ветки `wip/sync-tools` пишет кривые для проверки вокала, а не `features.json` — писатель признаков нужно сделать заново (librosa + `beat_this`, четыре стема `htdemucs`).

**Готово, когда.** В проигрышах видно: даф вздрагивает на ударах, струны дрожат с громкостью, у ная видно дыхание; при перемотке кадр тот же; на iPhone плавно.

## T8. Кнопка-флажок «не совпадает» — сделано (2026-10-17)

Кнопка «Не совпадает» в плеере и клавиша M; список «Отмеченные места» в «О песне» (переход, удаление, «Скопировать» — текст для агента); как агент обрабатывает список — `docs/methodology/11-qa.md`, «Отметки владельца». Ниже — исходная постановка.

Зачем: ИИ не слышит, а скрипты проверки ошибаются на хоре и распевах; последнее слово за ушами владельца. Как: во время прослушивания одна кнопка (или клавиша) «не совпадает» запоминает момент и строку — ничего не останавливая и не редактируя; в «О песне» — список отмеченных мест и кнопка «скопировать»; список присылается агенту, тот правит текст или выравнивание. Делать только после «да» владельца.

## T11. Методология «справится даже слабый агент»

**Цель (владелец).** Новая песня добавляется без нового кода: всё настроено, понятно и просто; любой ИИ, даже слабый, по задаче сам находит в интернете тексты и названия, проверяет их, переводит со смыслом и удобно для чтения в темпе песни, а то, что не вошло в перевод, пишет в пояснения.

**Часть 1 (идёт, `grok/t11-method`).** Единый маршрут в `docs/methodology/README.md` (вход → команды → выход → машинная проверка на каждой стадии), `npm run song-status -- <slug>` («где я и что дальше»), шаблоны `docs/methodology/templates/`, пошаговый поиск текстов и перевод с примерами, обобщение языков и письменностей в схеме, согласованные навык `add-song` и `AGENTS.md`.

**Часть 2 (после T1, T2, T8, T6-пилота).** Внести в стадии 02, 03, 05, 09, 11 то, как конвейер работает на самом деле. Затем **репетиция**: слабая модель (например, `grok-4.7-build-fast` с низким усилием) в отдельной ветке добавляет одну из наших песен с нуля только по методологии; результат сравнивается с эталоном (`canon.md`, `lyrics.json`); каждое место, где она ошиблась или застряла, — правка документа или инструмента; повторять, пока не пройдёт. Потом — первая новая песня владельца как настоящая проверка.

**Готово, когда.** Репетиция слабой моделью даёт песню, которая проходит `npm run validate -- --strict` и совпадает с эталоном по тексту и порядку строк, без вмешательства оркестратора.
