# Telegram-бот: приёмная записей

Бот принимает записи без компьютера: перешлите ему файл из бота-загрузчика (или пришлите ссылку на Dropbox / Google Диск), он проверит качество, зашифрует запись и положит её в репозиторий, в `content/inbox/`. Дальше агент делает песню по методологии.

Код — `api/telegram.ts` (функция Vercel в этом же проекте), разбор файла — `api/_audio.ts`.

## Что умеет

| Прислали | Что делает бот |
|---|---|
| аудио, видео или документ до 20 МБ | скачивает у Telegram, определяет формат, кодек, битрейт, частоту, длительность, отвечает вердиктом, сохраняет |
| ссылку на Dropbox, Google Диск, прямую ссылку на файл | скачивает сам (до 45 МБ) и делает то же |
| ссылку на YouTube, Spotify, Apple Music, SoundCloud и т. п. | сохраняет ссылку как заявку и просит файл |
| `/help` | короткая подсказка |

Файл больше 20 МБ Telegram ботам не отдаёт — бот предложит положить его в Dropbox или на Google Диск и прислать ссылку.

## Почему бот не качает с YouTube сам

YouTube не отдаёт видео облачным серверам: запрос с адреса дата-центра (Vercel, GitHub Actions, облачные песочницы) получает «Sign in to confirm you're not a bot». Это проверено на этом проекте. Боты-загрузчики, которые работают, держат для этого свою инфраструктуру. Обходные пути есть — cookies отдельного аккаунта YouTube или платный «домашний» прокси, — но они хрупкие, нарушают правила YouTube и могут кончиться блокировкой аккаунта, поэтому здесь их нет.

Про качество: «оригинала» на YouTube нет. Лучшее, что он хранит, — AAC 128 кбит/с (формат 140) или Opus около 130–160 кбит/с (формат 251); у подписчиков Premium для части музыки — AAC 256. Бот-загрузчик, которым пользуется владелец, отдаёт формат 140 — это максимум для обычного аккаунта. Лучше YouTube бывает только покупка без потерь (FLAC/ALAC: Qobuz, Bandcamp, 7digital, магазин исполнителя).

## Подключение (один раз)

1. **Бот.** В Telegram откройте @BotFather → `/newbot` → придумайте имя → получите токен вида `123456:ABC…`.
2. **Доступ к репозиторию.** GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token. Repository access: «Only select repositories» → `living-lyrics`. Permissions → Repository → **Contents: Read and write**. Срок — какой удобно (по истечении бот перестанет сохранять и скажет об этом).
3. **Vercel.** Проект → Settings → Environment Variables → добавьте для Production:
   - `TELEGRAM_BOT_TOKEN` — токен из шага 1;
   - `GITHUB_TOKEN` — токен из шага 2.
   (`AUDIO_KEY` уже задан.) Затем Deployments → последний → Redeploy.
4. **Включить.** Откройте на сайте (войдя по паролю) `https://living-lyrics.vercel.app/api/telegram?setup=1`. Страница подключит бота к сайту и покажет ссылку «Стать владельцем» — нажмите её, в Telegram нажмите «Start». Всё.

Чужие люди боту писать могут, но он им не отвечает ничем, кроме «это закрытый бот». Владельцы хранятся в `content/inbox/owners.json` (добавить вручную можно и переменной `TELEGRAM_ALLOWED_USERS` — id через запятую).

## Как это устроено

- Telegram присылает сообщения на `POST /api/telegram` (вебхук). Пароль сайта этот путь пропускает (`middleware.ts`), а функция проверяет секретный заголовок, который знает только Telegram (он выводится из токена бота).
- Бот отвечает Telegram сразу, а работу доделывает в фоне (`waitUntil`), чтобы Telegram не слал сообщение повторно.
- Запись шифруется тем же ключом и форматом, что и `scripts/tools/audio-crypt.mjs` (AES-256-GCM: IV 12 байт, тег 16 байт, данные), и коммитится одним коммитом через GitHub API вместе с `info.json`.
- Коммиты, которые меняют только `content/inbox/`, не пересобирают сайт (`ignoreCommand` в `vercel.json`).
- Агент забирает запись: [стадия 2](methodology/02-audio.md#приёмная-telegram).
