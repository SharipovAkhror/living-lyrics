# Бюджет исполнителей

Правила расхода для Grok Build, Antigravity/Gemini (`agy`) и Claude. Их держат LL · Site и LL · Tech, когда ставят задачи и запускают исполнителей; следит LL · Ops. Каждое правило опирается на число из разбора `docs/research/spend-2026-w43.md`. Правило меняется только после нового разбора с цифрами.

Неделя 43 для сравнения: Grok — 1 958 млн токенов за 5,5 дня, 100 % недели за 36 часов до сброса, 35 % ушло в работу, которой нет в `main`.

## Правила по сбережению

Оценка сбережения — для недели 43, если бы правило действовало.

### 1. Ворота приёмки для кругов (≈ 580 млн, 30 %)

- Задача, которая идёт кругами (дизайн, иконки, «до уровня X»), получает в брифе **список проверок с порогами** (что измеряем, где, сколько). Без него задачу не запускают.
- **Не больше 3 кругов на один бриф.** Каждый круг кончается коммитом и строкой «прошло / не прошло» по списку.
- Четвёртый круг — только после приёмки LL · Main по отчёту. Ответ владельца «берём» означает: сначала влить, потом новый бриф с новым списком.
- Почему: «студия» — 20 кругов, 508 млн, иконки — 10 кругов, 137 млн; ничего не влито. После «берём» прошло 15 кругов на 438 млн.

### 2. Потолок сессии: 30 млн токенов или 2 часа (≈ 100–150 млн, оценка)

- Сессия, дошедшая до 30 млн токенов или 2 часов на часах, останавливается на ближайшей точке сдачи: коммит, запись «где остановились», затем новая сессия с коротким брифом.
- Медиана сессии — 13,6 млн. 15 сессий дороже 30 млн несли 360 млн сверх потолка; сессии дольше 2 часов — 773 млн (39 %). В длинной сессии каждый вызов несёт около 130 тыс. токенов контекста.
- Оценка сбережения: свежая сессия повторит часть чтений, поэтому считаю 30–40 % от 360 млн.

### 3. Остановка на плато (≈ 45–90 млн)

- Два прохода подряд без прибавки в измеряемом числе (строки, баллы, тесты) — задача останавливается. Исполнитель пишет отчёт, LL · Site передаёт его LL · Main. Следующий проход — только с новой идеей, одобренной LL · Main.
- Почему: T1 до 90 % — последний проход 43,7 млн, прибавка 0 строк. До этого +40 строк стоили около 5 млн каждая.

### 4. Темп недели

- Grok к концу дня *d* недели (неделя с пятницы 21:08) — не больше *d* / 7 · 100 % + 10 %.
- **≥ 70 % раньше чем за сутки до сброса:** только задачи, которые вливаются в тот же день. Ночных цепочек без приёмки нет. LL · Ops сразу пишет LL · Main.
- Почему: 21 октября в 13:24 было 76 % при 2,3 дня до сброса. Дальше ночная цепочка «студии» за 19 часов сожгла оставшиеся 24 % (около 470 млн). 21 октября за один день ушёл 41 % недели.

### 5. Узкий бриф — узкий контекст

- Бриф называет файлы, которые нужно прочитать. `docs/BACKLOG.md` (42 КБ) и `docs/STATUS.md` (28 КБ) целиком не читаются, только нужный раздел.
- Файлы больше 30 КБ читаются по поиску и диапазону строк. Прочитанный файл не перечитывается, пока его не изменили.
- Почему: 62 % вызовов `read_file` — повторные (7 557 из 12 193). `app.css` (57 КБ) прочитан 934 раза, `attack_chance.py` (191 КБ) — 336. Доля этого в токенах из журналов не видна, поэтому сбережение не оцениваю.

### 6. Исполнитель по работе

- **Grok** — код. **agy (Gemini)** — зрение, видео, оценки по кадрам, обратный перевод, вторые свидетели. **Claude** — оркестрация и приёмка, не исполнение.
- Каждый запуск agy записывается: `python ops/usage/collect.py --run <json> --task "<задача>"`. Запуск без записи учёт не видит.
- Почему: Grok — 100 % недели, у Gemini осталось 84 %. После 18 октября в журнале нет ни одного запуска agy.

### 7. Когда не запускать вовсе

- Задача ждёт выбора владельца: следующий круг не запускать, пока выбора нет («студия» и иконки 21 октября шли, пока стояли на доске со статусом «ждут выбора владельца»).
- У задачи нет измеряемой приёмки (правило 1).
- Недельный темп превышен (правило 4), а задача не вливается сегодня.

## Сигналы для LL · Ops

LL · Ops сразу пишет LL · Main, если:

- исполнитель занял ≥ 70 % недели, а до сброса больше суток;
- запуск идёт больше 2 часов или потратил больше 50 млн токенов без коммита;
- одну задачу переделывают третий раз.

## Для LL · Tech

- Глобальные хуки Claude запускаются на каждый вызов инструмента Grok и падают: за неделю 67 351 неудачный запуск, около 3 часов на часах (оценка). Отключить их для сессий Grok или починить.
- Потолки правил 2 и 4 нужно проверять автоматически (мост Grok или `collect.py`). Спецификацию пришлёт LL · Ops.
