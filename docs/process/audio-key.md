# Замена ключа записей

Ключ `AUDIO_KEY` шифрует `content/audio-enc/` (AES-256-GCM: 12 байт IV, 16 байт тега, затем данные — `scripts/tools/audio-crypt.mjs`). Он есть в секрете GitHub и в переменной Vercel. Прочитать его оттуда нельзя. Владелец 2026-10-24 разрешил заменить ключ.

Команду запускает **сам владелец** на Станции, один раз:

```bash
npm run rotate-key
```

Агенты её не запускают. Скрипт — `scripts/tools/rotate-audio-key.mjs`. Ключ не печатается: ни на экран, ни в аргументы, ни в окружение дочерних команд. Он попадает только в `.env.local` и на stdin `gh secret set` и `vercel env add`.

## Что делает команда

Каждый шаг можно повторить. Повтор после сбоя продолжает с места остановки и не создаёт второй ключ: берёт `AUDIO_KEY` из уже записанного `.env.local`.

1. Создаёт 32 байта (64 шестнадцатеричных знака) и пишет `AUDIO_KEY=…` в `.env.local` основной копии `living-lyrics`. Перед записью проверяет `git check-ignore`: файл должен быть в `.gitignore`. Если строка уже есть от незаконченного запуска — использует её. Затем копирует файл в те рабочие копии из `git worktree list`, где `.env.local` ещё нет. Чужой файл не перезаписывает.
2. `gh secret set AUDIO_KEY_NEW` — значение через stdin.
3. Дальше скрипт умеет шаг одноразового workflow. Сам файл `.github/workflows/rekey-audio.yml` после замены 2026-10-24 удалён, и запускать его нечем. Этот шаг в документе больше не команда. Код шага в `scripts/tools/rotate-audio-key.mjs` оставлен: его проверяет `rotate-audio-key.test.mjs`. Следующей замене ключа файл workflow придётся вернуть, если этот шаг снова понадобится.
4. Vercel, проект `prj_qSpZgGNjg0KoGNHaT0Rw3RcBZ7kX`, команда `team_vKwfBgyY5JNLfiqxgWSD6R8A`. Версия CLI зафиксирована: `npx vercel@63.1.2` (выпуск npm от 2026-10-09, на 2026-10-24 ей больше двух недель). Каталог `.vercel` в репозитории не создаётся: команды идут из временной папки, проект задаётся `VERCEL_ORG_ID` и `VERCEL_PROJECT_ID`. Переменная `CI` не ставится: в этой версии CLI она не открывает браузер при входе. Если `whoami` не проходит, открывается `vercel login` — владелец входит в браузере. Затем прежняя `AUDIO_KEY` удаляется из production и, если была, из preview (`--yes --non-interactive`), и записывается заново с `--sensitive --yes --non-interactive` через stdin. Для preview имя ветки не передаётся: в 63.1.2 так переменная ставится на все ветки preview. Если CLI всё же ответит `git_branch_required`, скрипт остановится и попросит добавить переменную в панели Vercel, не удаляя её при следующем запуске.
5. `gh secret set AUDIO_KEY` — то же новое значение через stdin. Секрет `AUDIO_KEY_OLD` не создаётся: старое значение прочитать нельзя.
6. Последняя строка: `Готово — напишите в LL · Main «ключ готов»`.

Состояние шагов лежит в `.env.rotate-state` рядом с `.env.local`. Этот файл тоже попадает под `.env*` и ключа не содержит. Пока замена не закончена, его не удаляют.

## Что уже сделано

Замена прошла 2026-10-24: новый шифр трёх записей влит в `main` (PR #13, ветка `rekey/audio`). Одноразовый workflow после этого удалён. Секреты GitHub этим файлом не меняются.

Файлы `.enc` в истории git до 2026-10-25 зашифрованы прежним ключом. Ключ утрачен: на Станции его не было, из секретов его не прочитать. Расшифровать те коммиты нельзя. Откат на старый шифр невозможен.

## Сухой запуск

Проверка без настоящих секретов и без настоящего `.env.local`:

```bash
node scripts/tools/rotate-audio-key.test.mjs
```

Тест подставляет `git`, `gh` и `npx` и гоняет полный сухой проход и повтор после обрыва на шаге 3. Ключ в выводе, в аргументах и в журналах не появляется.
