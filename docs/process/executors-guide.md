## 3. «Лень» agy: замер и лечение

Источник — `~/.gemini/antigravity-cli/conversations/*.db`, 146 разговоров с 16 по 22 октября. В таблице `steps`: `status = 7` — шаг упал, `error_details` — текст отказа.

| Что | Число |
|---|---|
| Разговоров | 146 (21 окт — 90) |
| С отказом в разрешении | 38 (26 %) |
| Оборвались на упавшем шаге | 35 (24 %); **все 35 — после отказа в разрешении** |
| Что отказано | `dir` / `Get-ChildItem` по `content\songs`, `python -c …` (проверки кадров и звука), `ffprobe`, чтение PNG в `living-lyrics-wt/*/work/…` (вне рабочей папки) |
| Модель | `gemini-3.8-flash-high` во всех, где модель видна |

Почему так. Задания писали «Never run commands», но Flash всё равно тянется к командам: проверить файл, померить звук. В режиме `-p` отказ кончает ход. Ответ пустой, статус «SUCCESS», и снаружи это выглядит как лень.

Проба A/B, 2026-10-22: одно задание — прочитать файл в worktree и посчитать строки командой. Правильно: 36 и 127.

| Вариант | Итог | Время | Токены |
|---|---|---|---|
| A: Flash high, без флагов | «SUCCESS», **пустой ответ** | 11 с | 10 тыс. |
| B: Flash high, `--add-dir <wt> --dangerously-skip-permissions` | верно, ровно в JSON | 27 с | 38 тыс. |
| C: Sonnet 4.6, те же флаги | верно, но JSON обёрнут текстом | 13 с | 25 тыс. |

Настройка, обязательная для каждого запуска agy:

1. `cwd` = worktree задачи, `--add-dir <тот же worktree>`. Других папок не давать.
2. `--dangerously-skip-permissions`.
3. `--output-format json --json-schema <схема>`. Пустой `response` при SUCCESS — ошибка: разобрать причину, а не повторять вслепую.
4. Модель — по таблице раздела 4.
5. В задании: «Готово, когда: …», список проверок, «не задавай вопросов, делай».
6. Каждый запуск записывается: `python ops/usage/collect.py --run <json> --task "<задача>"` (обёртка LL · Tech делает это сама).

### Проверяющий `ll-judge`

- Карточка `.claude/agents/ll-judge.md`. Владелец — LL · Ops. Вызывает тот, кто принимает работу (LL · Site и другие менеджеры), как субагента.
- Вход — три вещи: список «Готово, когда» из брифа, diff ветки, выводы проверочных команд. Работу исполнителя судья не переделывает и файлов не меняет.
- Выход — JSON: `{"verdict": "pass|fail|unclear", "items": [{"check": "...", "result": "pass|fail|unclear", "evidence": "файл:строка или вывод команды"}], "minutes": n}`.
- Не больше 10 минут. Не успел — `unclear` по оставшимся пунктам, а не продление.
- Работе не мешает. Судья идёт параллельно с подготовкой к вливанию. `fail` — один возврат исполнителю с пунктами судьи; второй `fail` — решение менеджера.
- LL · Ops раз в неделю сверяет вердикты с итогом: сколько раз менеджер или владелец не согласились с судьёй. Если больше 20 %, список или модель меняются.
