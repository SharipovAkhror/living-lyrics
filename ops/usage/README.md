# Учёт расхода агентов

Отдельно от продукта: сколько тратят исполнители и сколько осталось по подпискам владельца. Сводка — `latest.json`. Её читает Dashboard. Каждое число там несёт `source` и `at` (откуда взято и когда). Нет измерения — поля нет. Догадок нет.

| Агент | Подписка | Что видно | Откуда |
|---|---|---|---|
| Claude Code | название из `subscriptionType` (`pro` → «Claude Pro») | только план. Окна 5 ч и недели мод берёт сам из рантайма (`session.usage()`), в этот файл они не пишутся | `claude auth status --json`. Почта и идентификаторы отбрасываются |
| Grok (Grok Build) | имя с модалки, например SuperGrok Heavy | недельный процент использованного и строка сброса как на экране; токены сегодня и за 7 дней | процент — экран `/usage` в отдельном сеансе `grok` (псевдоконсоль). Токены — `grok usage <id>` по сессиям из `living-lyrics-wt` |
| Gemini (Antigravity) | имя из шапки, например Google AI Pro | две группы: Gemini и Claude/GPT. У каждой остаток 5 ч и недели. «Quota available» — остаток 100 % и нет времени сброса | экран `/usage` в `agy`. Задание после конца — `agy -p --output-format json` |

Группа Claude/GPT на экране `agy` — квота Antigravity, не подписка Claude Pro. В сводке она лежит дважды одним и тем же объектом: `gemini.quota["claude-gpt"]` и `gemini.claudeGpt`.

У недели Grok поле `timezoneLabeled: false` значит, что клиент не подписал пояс. Строка `resetsAt` хранится как на экране и в UTC не переводится.

Окна Claude, кредиты сверх плана и безымянные корзины кэша в сводку не попадают: на экране подписки их нет, либо мод уже показывает окна сам.

Файлы:

- `ledger/<ГГГГ-ММ>.jsonl` — журнал. Строка сессии Grok дописывается, только когда изменились токены, вызовы или ходы. Строка квоты — только когда изменились план или проценты. Обратный отсчёт «через сколько сброс» сам по себе строку не добавляет. Событие `kind: run` пишется всегда. Старый файл не переписывается: он и есть история пиков, по которой считается неделя.
- `latest.json` — последняя сводка.
- `review.py` — недельный разбор Grok (LL · Ops): токены, кэш, цена по прейскуранту, время, чтения файлов по каждой сессии из журнала. Только чтение. Итог — `docs/research/spend-<год>-w<NN>.md`, правила — `docs/process/executor-budget.md`.
- `collect.py` — сборщик. Разбор экранов проверяют `ops/usage/tests/` (`python -m pytest ops/usage/tests`).

Запуск на машине владельца (там вошли Grok, Claude и Antigravity):

```bash
python ops/usage/collect.py
```

Dashboard запускает его сам раз в 10 минут. Задание Gemini после окончания записывается так:

```bash
python ops/usage/collect.py --run <вывод agy в JSON> --task "watch-video karitas"
```

Адрес почты, который печатает `agy`, и любые ключи в учёт не попадают. Для экранов `/usage` нужен пакет `pywinpty`. Неделя Grok снимается отдельным сеансом со своим `--leader-socket`, рабочий сеанс не трогается.

## Пороги и «ценность на токен»

- `alerts` в `latest.json` — пороги расхода из `docs/process/executor-budget.md` (правила R2, R4), только флаги, никто ничего не останавливает. `{kind, task, session, value, at}`: `tokens` — сессия Grok больше 30 М токенов; `wall` — идёт дольше 2 ч (секунды); `no-commit` — больше 50 М токенов или 2 ч и ни одного коммита в её worktree с начала; `weekly` — недельный лимит Grok от 70 %, а до сброса больше суток. Считаются только живые сессии (обновлялись в последние 30 мин). Начало сессии — первый её снимок в журнале, поэтому время может быть меньше настоящего на один такт сбора (10 мин). Панель и карточка показывают их в разделе «Расход».
- `value` заполняет LL · Ops (`ops/usage/review.py`), раз в неделю или по запросу; `collect.py` переносит его без изменений. `{weekTokens, tokensInMain, tokensNotInMain, mergedTasks, mTokPerMergedTask, source, at}`, токены в миллионах. Панель показывает миллионы токенов на влитую задачу и долю токенов, дошедших до `main`.
